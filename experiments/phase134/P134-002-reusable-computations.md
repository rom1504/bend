# P134-002 — Find a reuse boundary that pays

Started2026-10-24 alongside bounded emission. Production source/selection remains
unchanged until independently qualified integration.

The first owner-lowering memo makes a real decision before `p111_entry` and
passes29 controls and a real edited Lexer fresh-output comparison. It is rejected
for integration: all14 Lexer hits cover cheap native primitives;31 ordinary
owners miss, and complete hosted requests do not improve. Admission and hit
counts alone are not a profitability result.

Stage decomposition executes checked Bend exports and requires complete bytes to
match the frozen native reference. Generic owner lowering is only4.5–10.7% of
the warmed hosted backend on the three existing requests. Lexer has substantial
actual inline/range transformation work; splitting transforms from commit
verification puts its two repeated commit verifications at about16% of backend.
Map has a larger private-candidate preparation share. These hosted diagnostics
are not inferred native shares.

Two narrower hypotheses now deserve falsification:

1. Within a genuine `P114SBoundary`, identical ordered function headers preserve
   the verifier's ready-signature context. Exact unchanged bodies can reuse
   successful verification, while changed bodies and all uncertain context run
   the original verifier. Preserve the independent final verifier. A forged
   `valid=True` value is not a certificate and is outside this internal contract.
2. `p113i_function_done` already invokes the per-function range transformation;
   the later range pass repeats work. Retain its exact input/result pair, and
   skip only when the later input equals the earlier **input**. Equality with
   the earlier output alone is insufficient without an idempotence theorem.

Both proposals must beat their equality, retention and context costs on complete
requests, not only their skipped operation. Use balanced repeated observations,
edited-source fresh oracles, unrelated workloads and explicit mutation controls.
Independent source audit and final verification remain required.

An exact-input per-function range unit is also a possible cross-revision memo:
the transformation consumes the function and fixed implementation/policy, not an
arbitrary source book. Demonstrating within-request reuse does not establish
incremental source compilation. Preserve this distinction in every result.
