# Phase151 dispatch audit

Start with separate matched acquisitions of **p88_roles**, then **p112fp_binary**, plus complete dynamic query-and-consume loops. Both are promising fixed-result U32 tables; neither has established whole-compiler hotness. A source rewrite can reduce the cost of compiling these definitions while making their eventual execution slower, so keep both measurements.

**Source contract.** [p88_roles](../../selfhost/src/host/prepared-base.bend#L122) has 12 numeric arms, U32 tag → List<U32>, and an empty-list fallback. The current prepared word-pair carrier still reaches [p88_record_width](../../selfhost/src/host/prepared-base.bend#L290): each valid record obtains the roles once for the width check and again for field decoding. The tag≤11 admission, exact width, field shapes, spans, malformed-data refusal and authenticated carrier boundary remain separate obligations. No result type depends on tag.

[p112fp_binary](../../selfhost/src/back/qbe/fused-regions.bend#L3) has ten U32 cases, 26–35, returning exact QBE opcode strings; every other value returns `INVALID_P112_FLOAT_OPERATION`. Its real callers include [p112fp_binary_text](../../selfhost/src/back/qbe/fused-regions.bend#L24), [p114so_text](../../selfhost/src/back/qbe/owned-products.bend#L153), and [p114fl_binary](../../selfhost/src/back/qbe/owned-products.bend#L295). They cover arithmetic and comparison emission, with distinct result widths/casts. Preserve every string, especially comparison names and fallback. Existing [p112fp_control_report](../../selfhost/src/back/qbe/fused-regions.bend#L106) covers admission/refusal shapes, but does not independently assert every opcode spelling.

**Smallest useful sequence.**

1. Compile one reference and one scalar-spelled module per helper, with identical consumers, parent, Base, assets, runtime and flags. Replace the selected declaration; including both implementations in every acquisition hides the source-cost removal. Record complete acquisition and emission scope, source/SSA/object sizes, then reverse the acquisition order if the first difference is material. A changed implementation need not have identical self SSA.
2. Before timing, compare exact results for every supported tag/opcode and explicit defaults. For roles include 0–15, 31/32 and 4294967295; for opcodes include 0, 25–36 and 4294967295. The unused-default binders and closed branch values make these tables narrower candidates than general pattern matching.
3. Execute a runtime-seeded loop over mixed supported/default queries. Consume **every list element or String character**, incorporating order and length in a deterministic observation, and charge construction, traversal and destruction. Avoid per-query IO or clocks, a fixed known argument that specializes away dispatch, and a benchmark returning only a list length. Report the full consumed region; a checksum is an observation, not a collision-free equality proof.
4. If the local witness is useful, use the decoder driver below for complete prepared-Base transfer. For float emission, the smallest source-grounded consumer is `p112fp_binary_text` over all ten operations with whole emitted strings observed; only then use the existing [f32-arithmetic](../../selfhost/tests/consolidation/native-focused/f32-arithmetic.bend) request and exact generated output/native result. A bare `pure-f32` fixture is too small to exercise the dispatch contract broadly. Do not acquire a whole changed compiler merely to discover a losing table rewrite.

**Decoder transfer driver.** [archived decode-probe.bend](../../implementation/phase151/evidence/README.md) is an isolated 96-line / 4,432-byte module, SHA256 `8177ea9afd362a6d144780e3e83fef085e7b8727f7d046a7c3e60edf2bc3dd03`. It has not been source-checked or executed by this audit. For replay, recover that unexecuted driver from the Phase151 capsule. Root should use maintained `source.py.blocks` to retain the preamble and all declarations of [the frozen Phase150 reference](../../selfhost/build/phase150/parser-source01/reference.bend), **exclude its def main**, then append this module. That reference is 345,187 bytes, SHA256 `9174372bee83a1b566fc86339182f004cde6a7aa258097636135693c051af826`; for the candidate, replace only `p88_roles` in the same assembled prefix.

The eight reused observer definitions are `p144pn_word`, `p144pn_text`, `p144pn_texts`, `p144pn_terms`, `p144pn_term`, `p144pn_defs`, `p144pn_def`, and `p144pn_def_terms`. Decoder/read dependencies are `p88_decode_admitted`, `p88_u32`, `p86_read_file`, `kc`, and their existing dependency closure, all present in that prefix. Required product types are `P88Products`, `P88Decoded`, `P88Number`, `P88Cursor`, `KBasePrefixState`, `KBasePreparedWorld`, `FFreshPrefixState`, `FReadyPrefixState`, `KDef`, and `KTerm`. No new host algorithm or ABI is needed.

Runtime argv after the native `--` is:

```text
phase151-decode CARRIER STAMP BEGIN END
phase151-decode controls
```

The first token is the existing ignored sentinel convention. BEGIN/END are strict decimal U32 strings. For the pinned Base file, `BEGIN=1` and `END=p86_width(base_text,0)+2=75066`; bounds are metadata, not authorization. Use the same authenticated carrier/stamp as the maintained request. The driver does not itself authenticate an arbitrary path/stamp.

The observer consumes the entire product: book, fresh next/ready, frontend names/constructor indexes/count/ready, world state bound/delta/stamp/patches/ready, all five world lists, todos and checkedBound. The retained def/term observers include indexes, constructor definitions, quantities, spans and flags. It prints separate decode, observation and total local region milliseconds plus a tagged U32 hash. File reading is before the local clock; external process timing also charges startup and final cleanup. The observer exit is not a guarantee that every runtime destructor has completed.

Four explicit refusal oracles test `cache header bounds`, `cache stamp`, `cache tag`, and `cache width`, using short independently specified decimal carriers. They do not substitute for complete decoder conformance or authenticate a positive payload. The control path uses a Boolean parameter helper, avoiding the pinned language's prohibition on computed match scrutinees.

**Compiled path and no-new-IR possibility.** Current [f_context_pattern](../../selfhost/src/front/contextual.bend#L104) eagerly sends numeric literals through [core_literal_step/core_literal_word](../../selfhost/src/core/term.bend#L603), producing a U32 constructor with 32 bit cells. [ff_match](../../selfhost/src/front/flatten.bend#L145), [hit/miss construction](../../selfhost/src/front/flatten.bend#L191), and [f_hit_row/f_pattern_sub](../../selfhost/src/front/elaborate.bend#L164) then split and rewrite generic terms. Downstream materialization/checking/erasure repeatedly visit those trees. Phase150 establishes this as a causal acquisition issue for its lexer; it does not assign a cost to these two tables.

A restricted compact path is representable using **existing KLiteral, application, lambda and Bool-match terms**: scalar equality guards select unchanged closed arm values. Ordinary literal [checking](../../selfhost/src/check/kernel.bend#L860) and [annotation](../../selfhost/src/check/annotate.bend#L281) already retain suitable compact literals. A new public term constructor is therefore not inherently necessary.

However, `ff_match` currently receives heads/rows/variables/freshness/origin, **not an authenticated scrutinee/result type environment**, and literals have already expanded before it. An optimization there alone cannot remove all initial expansion. A real frontend path must defer eligible literal expansion earlier, preserve the old path for every ineligible case, and carry enough eligibility information. The narrow initial domain is one explicitly established U32 parameter, flat literal arms plus an unused wildcard, closed arm bodies, and an independent fixed result type—exactly these tables. Resolve/type-check scalar primitives normally; do not trust spelling or bypass checking.

Generalization must preserve dependent constructor refinements and substitutions, branch order, coverage/refusals, affine use of the scrutinee/captures, fresh IDs and diagnostic spans. A fixed outer result type alone does not rule out refinement-dependent uses inside a branch. Nat, mixed constructor matrices, dependent motives, duplicate/overlapping patterns and effectful scrutinees belong on the old path until proved otherwise. A linear equality chain may execute worse than the existing bit decision tree; generated runtime is an explicit falsifier.

Start with clean acquisitions; tiny requests have no economical 500-sample stage distribution. If a substantial unexplained acquisition gap remains, reuse maintained freeze/run/stages tools and strict gates. The decoder's multiple variable clock lines do not satisfy the maintained exact/prefix-plus-one-integer profiler contract; do not filter them or modify admission.

The retained [full Phase147 profile](../../selfhost/build/phase147/profile-final-full01/stages.json) puts **all Base preparation at 0.233s CPU**, only five samples. Faster `p88_roles` execution can save only a subset of that region for that request. No `p112fp_binary` owner share is established. **Compiling the rewritten helper definitions** is a different potential saving in a compiler-source request, and needs measurement. A few scalar rewrites could remove avoidable frontend work, but row counts and the lexer proxy do not justify seconds-per-pattern, 100s, or a material whole-build prediction. Preserve a local negative result if acquisition gains are small or resulting execution regresses.

No compiler/benchmark targets, subagents, profiler rebuilds or production edits were used by this audit.
