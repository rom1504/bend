# Full-pool recurrence allocation certificate

Hypothesis: V1's fold gain came from jointly ordering and coloring recurrence endpoints. V3 retained membership and priority and lost that gain. Preserve the V1 ordering/coloring only where every eligible read name can be placed without spilling.

The new `x190_j_counted` first scans the original read list using exactly the original register-candidate eligibility (positive score and `X181Stack` home). If more than 32 eligible names exist, it calls an exact copy of the original counted path. Otherwise it uses V1 scores, unchanged full liveness/fixed-point analysis, and V1 partner reservation. Acceptance requires every candidate to have one of the nine register homes and the existing independent graph/ABI/call-clobber validator to pass. Any failure returns to the exact original counted path, which also restores original priority. No workload names, body lengths, source constants or benchmark input checks occur in the policy.

The certificate is stronger than comparing candidate and original spill counts: no eligible read name is excluded or spilled at all. It does not promise optimal instruction selection or speed. Existing saved homes and zero-read dead destinations remain outside this pool exactly as before. IR, memory operations, widths, loop conditions, ownership, effects and ABI stay unchanged.

Costs: every eligible joint allocation adds one bounded name-list scan (the outer joint allocator already enforces its original statement/parameter limits). Accepted small pools perform one full liveness/color allocation. Rejected oversized pools perform only the original full allocation. Failed small-pool speculative allocations perform the new attempt followed by the original attempt; this exceptional path can nearly double allocation work for that function. No native compiler throughput result is claimed. Global coverage/fallback frequency and compile overhead must be measured before promotion.

Prediction frozen before checking/runtime: fold restores V1's 13-instruction body and retains zero frame operands; edit's oversized pool takes original placement. Retained heldout fold and changed numeric sentinel must be measured independently. Actual ELF activation is required; failure to restore fold placement stops timing. Recipe: recipe-v4.json.
