# Phase40 workflow efficiency findings

The campaign implemented compact owner tasks, two medium-effort implementers,
a bounded evidence owner, serial root execution and explicit screen/confirmation
budgets. It reused checked development, existing comparison/execution protocols,
semantic owners and final gate collectors. Versioned additions provide selected
plan execution, starting-Phase39 packaging, append-only elapsed accounting and
small report/preservation derivatives. No controlled model/effort comparison was
performed, so elapsed duration cannot establish a model speed multiplier.

Saved-output prototypes isolated mechanisms before compiler work. Lists retained
materialized stages and BigInt countdown; tree split leaf/flow/complete components;
lexer split guard/class/step/complete and retained native strings/materialized
mode/tuple values. The corrected lexer confirmation is227.097seconds/90samples
at three fixed inputs, with manual complete gains2.14×/1.97×/2.10×. It is a useful
future mechanism result; source integration is deferred and no installed lexer
improvement follows. Negative controls and range/outlier uncertainty remain.

Compiler-produced behavior is a distinct stage. Canonical Base List admission
required correcting builtin constructor flags and quantity1 fields. Checked04
actual list/Nat controls then caught undefined `$u2` despite earlier bootstrap
and saved-output success. The reviewed emission-only child-position correction
keeps the planner's descendant/whole-graph proof; its passing actual successor
controls and final gates remain necessary. This evidence justifies preserving
failures and testing declaration/continuation boundaries before broad promotion.

The reusable full catalog is45points/23sources; each selected comparison contains
baseline, candidate and TS executed together in the same rotation. Supplemental compare.py prototype
reports cannot substitute for actual checked final execution summaries. A single
full final sweep and relevant confirmations avoid duplicate campaigns; normal
checked request costs include the new list512 source separately from execution.
Static source/runtime counts quantify complexity, not throughput.

The full checked05 sweep passed all output observations but found a 2.43×
raytrace regression. Broader Nat admission selected a structural worker ahead of
an existing faster scalar island. Checked06 restricts that admission to data
results and restores the whole raytrace modules byte-for-byte to Phase39.
This is an optimization-selection conflict, not evidence that explicit frames
are universally faster. Keep negative controls and compare the complete emitted
call graph when a local improvement causes a broad regression.

The corrective comparison uses a prospective, reviewed identity-reuse rule:
42 final checked06 modules exactly equal the measured checked05 bytes; only the
three changed ray points need fresh rotations. The data selector checks both
audited summaries, fresh checked06 preparation, sources, points, role identities
and measurement protocol. It retains rejected ray rows separately and never
pools timings or changes a failed result. This saves a second approximately
18-minute full sweep. Semantic and compiler-cost gates still use checked06.

Inherited diagnostics also need precise ownership. An old counter matched every
explicit frame stack and therefore counted a newly optimized producer as a fold.
Its successor separately counts the original fold and producer, retaining the
one-fold assertion and adding producer proof/alias checks. A component fixture's
old refusal expectation for proper-descendant tail recursion similarly needs an
explicit positive witness. These changes preserve failed reports and version the
diagnostic tools; they do not waive semantic failures or alter compiler output.

Elapsed accounting separates raw wall, recorded tool elapsed, merged tool wall
coverage, declared session bounds and outside-window/unclassified time. The
interruption from Oct2 to Oct3 dominates raw elapsed; agent continuation after
last initial root receipt has an uncertain endpoint. Declared windows are not
continuous active work. Unrecorded work/waiting cannot be relabeled model latency.
The initial90–110minute estimate is prospective context, not achieved speedup.

Final outcome: checked06 is installed and all release gates close. Lists improve
9.97–13.11× and trees 1.83–2.18× over Phase39 on the selected points. Compilation
cost rises 24.45% for tree and 19.09% for list; source grows 141 lines. These
costs remain explicit. The lexer result remains a deferred manual prototype.
The canonical [report](README.md), [compiler costs](compiler-cost.md) and
[release](release-06.md) bind these distinct outcomes.

The portable five-point smoke completes all 45 samples in 20.360 seconds with
`--budget 20`; the runner explicitly records a 0.360-second budget overrun.
This is a successful complete preset run, not proof of a hard 20-second enclosing
deadline. Use the recorded outcomes and adequate budgets for automation.

The initial 90–110-minute forecast was not achieved by the observed resumed
session. Repeated inherited diagnostic/provenance repairs and final integration
remain substantial workflow costs. Compact agents produced useful independent
reviews, but this campaign has no controlled attribution of latency to model or
effort. The [accounting](accounting/report.md) records declared windows and
instrumented time without treating the interruption or unclassified work as
model latency. Next workflow work should reduce brittle helper-name/counter
assumptions and repeated acquisition while retaining the semantic contracts.
