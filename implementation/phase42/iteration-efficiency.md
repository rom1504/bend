# Phase42 iteration efficiency — interim qualitative account

Phase42 used seven owner roles—calls, frames, fusion, layout, request facts, independent review and validation—plus root coordination. The owners produced isolated patches, falsifiers, oracles, frozen controllers and reports concurrently. Root applied canonical changes, bound checked images and supervised heavy builds, acquisition, profiles and timing. This made ownership and review explicit; the ledger does not establish a causal speedup from the number of agents.

This account reads the existing [campaign ledger](../../selfhost/build/phase42/campaign.jsonl) through the start of checked16 integration03/recipe04 semantic qualification. The ledger is still open and can advance while this draft is written. Final elapsed totals, job sums, overlap and category counts belong to root's accounting report. Recorded enclosing job intervals are not added to their child intervals. Unclassified time must not be called model idle time, human delay or unused compute.

The heavy critical path remained serial: candidate patch integration, checked compiler build, actual emission, exact-value/activation controls, then timing or broad qualification. Root constrained memory, affinity, job count and deadlines using the existing bounded supervision tools. Parallel owner analysis did not authorize concurrent unbounded compiler jobs. Failed supervised jobs stayed in the ledger with their own artifacts; controllers and probes were versioned after consumption instead of being rewritten under an old receipt.

## Work that resolved decisions early

Saved-output ablations and tiny exact-emission probes tested a specific mechanism before a general compiler change. The compiler CPU profile separated request planning from bootstrap/verification work; it supported investigating repeated plans without treating overlapping sampled shares as additive savings. Request facts retained original complete plans and negative results, avoiding the tempting but invalid substitution of a root graph superset for a helper's exact graph.

The Map native comparison screen passed complete-value and hook/dependency controls but showed little headroom. A later Map dispatch proposal regressed and was excluded. These negative results stopped source expansion in that family. They did not justify aggregate parity claims or hide the remaining Map gap. BST predicates exposed separate blockers in sequence: native product/ListFrame proof, nested structural continuation, root activation and the exact Nat.add residual admission. Recording actual plan flags prevented treating a dormant emitted worker as a runtime gain.

Native container proof and alias-DAG controls caught a static aggregate-fuel problem before promotion: separate full depth allowances for both Sigma siblings could expand an alias DAG exponentially. Serial residual-fuel equality replaced that proposal. Exact native ABI observation also corrected the predicted Sigma kind to the actual specialized representation. A tiny Node parse caught diagnostic-generation syntax; the failed producer and consumed successor remained separately retained.

The preimport BigInt observer witness established a real unsupported-domain divergence, including reentrant values and dynamic G.code events that equal outer results would miss. Its initial blanket-stop interpretation was corrected after reading the already published standard-intrinsics-at-initialization contract. The witness was retained, not relabeled as passing. Nat.add promotion then used the narrower supported contract plus independent maximum/overflow, postimport mutation and Error-hook suspension controls. This was a contract clarification based on prior documentation, not a new waiver written to admit the candidate.

## Failed-job lessons and late qualification cost

The ledger includes early derivation/control failures such as calls-derive01, fusion-controls01 and whole-tree-controls01/02; checked04 and checked06 bootstrap failures; invalid or unadmitted fixture acquisitions; and failed diagnostic injections. These are different kinds of failure. Checked04 exposed an unannotated constructor let that Bend could not infer; checked06 caught a literal replacement compile error. Source-order/linearity mistakes in independent fixtures required valid successors before their runtime evidence was usable. A failed adapter or assertion is not a timed losing candidate, and a passing saved-output prototype is not evidence of general source emission.

Later derivation assertions also predicted implementation shapes too narrowly. Root's actual emitted modules and complete controls corrected those assumptions rather than weakening semantic oracles. Changes in private clones, ordinary entry selection and generated worker shape required versioned instrumentation tied to the actual checked API. Predicted counters, AST patterns and zero-entry assumptions were hypotheses until the emitted path was observed. Keeping structural assertions separate from complete values made it possible to distinguish a stale assay from a behavior regression.

The important late mistake was the shared equality-domain change. Native qty1 Sigma proof had been routed through j_region_same_type, whose existing callers also admit local qty2 Sigma/vector layouts. The strict native proof's43 assertions passed, while the legacy count.keep worker silently lost admission. The unchanged Phase39 vector preflight caught this in integration02, after source15 was already frozen. This was a real compatibility regression, not an instrumentation explanation.

Source16 restores the original local-region equality policy and calls strict closed equality directly from JPure Ann/Var/terminal checks. The native controller successor keeps all43 expected assertions and uses the dedicated predicate for its six strict equality cases. The unchanged legacy vector oracle/preflight remains a separate gate. The ledger records the failed final02 preflight, a new checked16 build and passing focused vector/native successors before integration03. Moving that domain-consumer preflight earlier would have avoided late rebuild and recipe rebinding; no wall-time saving is claimed without a measured counterfactual.

## A faster guard sequence for a successor

1. State the existing runtime contract and enumerate every consumer of a changed shared predicate before designing its widening or tightening. Separate algorithm selectors, source closed-type proof and runtime ownership. Run both admitted old-domain positives and new-domain negatives in the first focused predicate probe.
2. Freeze a pinned-TypeScript-valid minimal source fixture and verify the generated diagnostic's syntax before acquiring three compiler roles. Keep malformed synthetic IR controls separate from source-valid fixtures. Bind each role's actual runtime/API/Base and ordinary output independently.
3. After the first checked build, run cheap actual-emission activation and complete-value controls for the affected family **and** legacy vector/fold/unary/container consumers. A static worker declaration or planner pass is insufficient; require actual ordinary entry and live mutation fallback.
4. Inspect actual generated worker/clone shapes before freezing instrumentation assertions. Keep complete values, alias identities, observer order, errors and deep-stack controls independent of those shape assertions. Any successor must retain consumed producers and failed evidence.
5. Run a small balanced compiler-cost screen before broad qualification. Report request, import, verification/process and RSS boundaries separately. The checked13 two-case screen improved tree compilation but regressed list compilation; this net-image tradeoff did not isolate cache or fusion causality.
6. Freeze the selected source/API/runtime, then regenerate recipes and run the broad frontend, ordinary/relocated CLI, full semantic, runtime and four-case compiler-cost gates once against those exact identities. If a real compatibility repair changes the image, rerun the focused affected controls first and bind a new final gate; never transfer a prior checked receipt by label.

This sequence preserves cheap falsifiers ahead of broad work and adds the missing old-consumer admission check. Final numerical efficiency and release status remain pending root's closed accounting and qualification reports.
