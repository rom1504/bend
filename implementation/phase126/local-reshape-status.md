# Local reshape experiment status

This is an unqualified prototype, not a measured improvement or selected compiler change. The source/machine evidence and allocation ceiling are in [local-reshape-design.md](local-reshape-design.md).

The whole-worker interface preserves the original two operands until a guarded runtime helper decides whether both roots are distinct, raw, dynamic cells of the exact authenticated two-field constructor. Success snapshots all four fields, transfers each once, reuses the two input shells and allocates the outer shell through the existing constructor ABI. Refusal changes nothing and executes the entire original worker body. This removes neither reference-count semantics nor any fallback branch. RFC1, shared and static roots deliberately refuse; parallel execution is not qualified.

Independent backend review found no concrete blocker in the source equation recognizer or raw-only helper. Required integration conditions are the exact checked constructor identity, guarding before the first destructive take, unchanged fallback, and exact additive import verification. Independent integration review also found no blocker: the guard precedes all original instructions; parameter/local collision checks cover the complete original schema; the exact ABI and constructor reference are verified; previous checks remain unchanged aliases. This is a source-certificate argument, not safety on forged IR.

The initial recognizer's size gate called `nq_layout_size(...,513)`. Independent investigation of the analogous identity experiment showed that helper always subtracts remaining fuel from 4097. The gate consequently refused every small positive case. Frozen v1 is preserved; `recognizer-v02.bend` computes 513 minus remaining 513-fuel directly, retaining the intended 512-node limit. This is an admission bug, not evidence that runtime reuse works. `inspect-v02.mjs` asks the checked compiler for actual `warp_zip` and renamed `hedge.cross` admission, separate equation/type results and the original checked definitions. No expected positive is asserted by host code.

`manifest03.json` pins the corrected recognizer, whole-worker wrapper, exact import verifier and 18 finite structural/import/hygiene controls. The previous three hook implementations are copied as exact aliases; the wrapper retains original body, parameters, result convention and dependency list. Hygiene uses the original local schema and rejects collisions with both new temporaries. `prepare-integration.py` is a narrow source-only extension authority: it verifies those frozen module bytes, proves alias identity and requires every other existing declaration to remain unchanged. Generic Phase126 composition policy and N111/request/runtime admission gates are not weakened.

Ordinary owning tree/String controls retain external root aliases, reuse the same argument twice, preserve a heap payload alias, cover static values and both wrong-tag directions, and compare complete outputs with an independent host oracle. Their files are frozen in `cases.json`. Fabricated finite terms are only arguments to analysis/verifier functions; they are never emitted as native programs.

Still required before selection: checked actual-source admission; all finite controls; ordinary native outputs; structural evidence that the correct original worker is guarded; actual success/refusal and allocation counts; paired tree timing; and broader/native qualification if retained. The source-level 34–39% node-allocation ceiling assumes every relevant call succeeds and does not predict a runtime speedup. A low raw-success rate or wrapper overhead can invalidate this approach cheaply without a broader optimizer rewrite.
