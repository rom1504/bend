## Decision ladder and time discipline

- Prepare small exact-declaration closures and real compiler inputs. Charge
  parsing/loading, setup, final observations and teardown, and state any narrower
  region explicitly. Share one baseline/candidate image where possible.
- Independently check the source and focused semantic controls first. Then compare
  complete outputs on actual compiler and unrelated ordinary workloads. Matching
  error results do not count as successful compilation.
- Use bounded paired native measurements; account for source size, actual routing,
  candidate admission and the original final verifier. A non-hit is an overhead
  control, not a benchmark win. Preserve every refusal and negative result.
- A meaningful real-region gain earns a complete request comparison. Only a
  compelling request gain earns full cold acquisition/native qualification.
  Small wins with tiny source changes can be retained without claiming a new
  qualified executable. Do not pay for a full build to discover a weak ceiling.
- Compare emitted QBE first. Exact source/runtime/toolchain/output identity can
  reuse previous generated-program evidence; changed products need targeted
  execution, and broader changes need appropriate independent gates.

The initial source audit is roughly20 minutes per independent candidate. Reject
weak interfaces promptly. Do not repeatedly expand a failing harness or rebuild
the whole compiler for each candidate. Neither bounded kernel speed nor source
checking proves compiler correctness or recursive research acceleration.
