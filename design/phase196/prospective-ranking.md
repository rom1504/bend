# Prospective comparison of three ways to select machine optimizations

Screen 15 proposed local instruction selections in five profiled Bend programs. Tree and BST use the qualified Phase195 generation. Edit distance, ray and lexer use the Phase194 generation for which we have matching physical profiles. Each alternative is an isolated edit to a single block in rendered assembly. This is a diagnostic of ranking quality. It does not change the compiler.

Freeze all blocks, edits, identities, profile weights, scores, tie handling and promotion criteria before executing any timed candidate. Evaluate every alternative, so the low-ranked cases provide a check for missed wins. Rebuild the baseline and all variants through identical assembler/linker settings. Use the ordinary catalog oracle at the frozen input and independently run mature C at additional inputs per program. The projected block excludes calls, branches and surrounding memory traffic. A profile weight is the period-weighted fraction of all sampled PCs in the exact block.

Rank by (1) fractional instruction count reduction, (2) fractional reduction in LLVM-MCA total cycles across 100 repeated projections, and (3) the second score multiplied by the block's baseline profile weight. Use Ivy Bridge and the established no-alias model. Also record block reciprocal throughput as a diagnostic. Break ties lexically by candidate identifier. The primary research budget buys four choices. Count how many replicated wins each policy finds, plus the sum of measured fractional savings of its four individual trials. Candidates on the same program may overlap; never interpret that sum as an achievable combined speedup. Report per-policy pairwise ranking agreement or rank correlation across all 15 and wall time separately from research effort.

Run two independent eight-round comparisons on one CPU, rotating all four roles within each case and reversing case and role ordering in the second session. Each role uses the same repetitions per case calibrated on the corresponding baseline, aiming for 250 ms or longer. Exclude calibration runs. Require exact outputs, counts and empty stderr on every run. A replicated win requires at least 2% less median paired runtime and improvement in at least six of eight pairs in **each** session. Record marginal and reversed outcomes. This operational threshold is a selection rule, not a statistical confidence interval. If rankings miss substantial observed wins, record the failure before proposing an alternative model.
