# Independent observer controls

Use `selection-v4.json` for the fifteen core controls and
`selection-boundary-v4.json` for the two foreign/pool controls. The parent's
baseline source check accepted all fifteen core sources; exact evidence is in
`v4-source-qualification.json`. This is source acceptance, not native execution
or optimization-admission qualification. V4's mutual comparison helper is
explicitly `@unsafe`; these controls do not claim a termination/kernel proof.
V1–V3 and their failed source checks remain preserved through the versioned
derivation receipts. Do not edit a consumed version.

`selection-demand-v3.json` selects zero-argument, partially applied factory,
and native-successor demand witnesses. The successor's v2 source adds its
required Nat annotation; the failed v1 remains preserved. The independent
twenty-case query batch uses exact loaded names `strand:probe`,
`strand:compare`, and `inspect`, with false and true permission queried
separately. A forced-true structural plan is not a production capability.
`malformed-plan-obligations-v1.json` specifies eighteen internal
plan mutations for the future validator gate; it is not an executed suite.
`source-review-v1.md` records independent source review and remaining gates.

These tiny programs specify semantic and admission boundaries independently of
the measured Map/String source. They were authored by source inspection;
initial creation does not claim parser, type-check or runtime success. Root
owns all actual compiler/target validation. Preserve versioned successors if a
fixture needs correction after it is consumed.

The original `selection-v1.json` selects 15 native programs. `strand.bend` is a shared library,
not an executable test. Goldens were calculated from the source definitions;
the polynomial hash is `acc * 17 + word` modulo 2^32. Error goldens use the
existing checked Nat-overflow contract. `admission-oracles-v1.json` identifies
the candidate function and separately states its expected structural outcome.
Resolve imported names through the loaded book; a name suffix is not proof of
identity. Matching output alone does not establish intended admission/refusal.

The one-root observer returns its original renamed `Strand` value plus an
indexed U32. The two-root observer returns both original roots plus unsigned
lexicographic ordering. The scalar work differs from upstream Map's helper
structure; no Base function or benchmark name should be an admission condition.

Positive controls cover static constructors, parameter-built dynamic nodes,
shared parents, identical roots supplied with two owned references, shared
dynamic tails, early exit, unequal lengths and unsigned high words. The
discarded-result case checks cleanup of an adapter's returned root while an
independent shared owner remains live. The helper-twice case forces repeated
expansion of a helper with internal field binders.

Negative controls change a field, reorder equally typed fields, change the root
map across branches, duplicate one returned root, or retain demanded scalar
work after recursion. These must decline the first bounded observer scope.
An unused scalar overflow before returning the unchanged root may either keep
its ordered error in an admitted residual or decline; silently dropping it is
always wrong. Functions and closures remain affine; no fixture attempts to
duplicate an ordinary function as if it had kind Data.

The same semantic fixtures should run at one and four threads. That does not
test cancellation by itself. A separate generated-C or raw-core controller is
needed to establish pre-existing shared error, an error from a scalar helper,
long traversal polling, and untouched raw/device fallback. Such controls must
keep their changes separate from timed programs and report exact scope. The
current host `err_post` exits immediately and `err_seen` is device-only, so a
host shared-error diagnostic must explicitly emulate that visibility; it is
not a production host cancellation test. No physical GPU behavior is inferred.

Foreign and raw capability controls are a separate boundary: an ordinary raw
book must not activate a borrowed plan merely by presenting a generated-looking
tag, cache record, annotation or function name. Unknown foreign access must
disable the checked permission even when the returned root appears unchanged.
Do not feed such untrusted values directly to a private observer as a purported
public ABI test; the test must enter through the ordinary compiler route.

`emission-audit-v2.py C OWNER --expect active|absent --permission 0|1 --out JSON`
reads actual generated C and verifies the explicit capability, selected private
pair, scheduler hook, borrowed-body ownership exclusions, stable adapter roots,
and error-check ordering. V1's exact-whitespace hook pattern rejected a present
indented hook; v2's derivation records that method-only correction. This source
audit does not claim that the selected function executed.

`prepare-active-path-v1.py C OWNER FRESH_PHASE70_OUT` derives C with an atomic
adapter-entry counter and one flushed stderr marker. Root compiles and runs it
under the usual guard. Require the marker, remove exactly that line, then check
the original golden including failures. This checks that admitted hidden errors
take the new route, even when host fail-stop exits before an exit callback.

`prepare-error-diagnostic-v2.py C OWNER FRESH_PHASE70_OUT --mode MODE` derives
three separate diagnostic copies: `pre-entry`, `post-observer`, and `loop-poll`.
It makes shared error visible on the host, forces the selected adapter's
nonsequential check path, and records actual return coverage. The fourth loop
visit must perform the unchanged modulo4096 poll after three real transitions;
only the initial counter is offset to keep this diagnostic short. Use the
three-node `two-root-alias` program and owner `strand:compare`. Root must run
single-threaded. Successful diagnostics terminate at the failed adapter before
wrapper allocation, so they do not claim normal teardown or absence of leaks.
All diagnostic C is separate from performance inputs. The Python preparers run
on CPU0 and never execute Node, Clang, or native programs.
