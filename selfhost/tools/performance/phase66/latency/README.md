# Phase66 controlled measurements

This lane keeps five requested metrics separate: generated-program runtime, B1 compilation, genuine B2 compilation, conformance (the controls lane), and compiler source complexity (the size lane). Only the root agent runs targets, serially on CPU3 with a 1 GiB Node heap, 2 GiB process-tree RSS limit and 4 GiB available-memory floor. Factories and analyses are data-only CPU0 work.

## Compilation

`make-method.py` derives the frozen Phase65 method into a fresh Phase66 boundary and retains old image lineage. `make-bindings.py` binds actual Phase65 State10 B1/B2; it does not synthesize bootstrap sidecars. The first baseline recipe is `selfhost/build/phase66/baseline-latency/recipe.json`: `prepare`, then `generations` (four sources, three roles, three rotations).

`make-head-method.py` adds a distinct `typescript_head` role. Old and new TypeScript revisions and Base files stay separately pinned. HEAD output acquisition reuses the existing Phase52 checked emitter on copied original fixtures. `runtime/smoke.py` checks every original point with the unchanged execution worker. `join-head-oracles.py` joins all 23 raw modules and 45 fresh point observations before any HEAD timing oracle is admitted. `head-four-latency/recipe.json` uses four roles and four cyclic rotations; preparation remains outside the clocks.

`make-candidate-method.py` distinguishes optional annotation API support from the reviewed host's explicit Base eligibility. The old eligible Base requires exactly one bound product; the updated, ineligible Base requires absence. Both producer and consumer hash guards must exist in the pinned snapshot. `make-upstream-audit-method.py` keeps the old immutable verifier for old images and invokes the actual frozen checked snapshot verifier for the exact new upstream pin. All declared snapshot bytes are verified before that import. It does not waive revision or bootstrap checks.

`make-qualified-products-method.py` is the explicit successor for the independently qualified updated Base. It requires the exact integrated host and the pinned owned/custom control receipts before admitting its new Base hash. Earlier mandatory-cache-only images retain their original policy and recipes. Eligible images must actually generate the fully bound optional artifact during preparation.

`join-bend-oracles-v2.py` supports a checked new image with all sources or an explicit source subset. Every original runtime point belonging to each requested source is mandatory. Such subset qualification only admits that subset; it cannot silently authorize a broad campaign.

`join-b2-oracles.py` reuses the final qualification lane's fresh ordinary-driver B2 emission of all 23 sources. It requires complete byte equality with the separately executed B1 modules and all 45 observer modules, then binds the actual self-emitted API and raw outputs. The resulting B2 oracles admit latency without fabricating checked metadata or repeating identical point execution. `bind-qualified.py --image b2` also verifies the actual image emission, generator, source and explicit export admission.

Every clean sample uses a fresh process and a prepared private cache. The compiler import, API load, first ordinary compilation and their sum are separate fields. Raw generated library bytes must equal the specific image's qualified oracle. CPU/allocation diagnostics, later warm requests, preparation, and generated-program execution are separate scopes. `analysis/clean.py` independently verifies every raw output and recomputes within-source medians and all ordered role ratios.

## Generated-program runtime

`runtime/freeze-program-bundles.py` preserves the actual selected old Bend modules, old TypeScript modules and fresh HEAD TypeScript modules under Phase66. It joins the old checked B1 to the genuine B2 byte-equality qualification. `runtime/run-v2.py` preserves the existing 20/60/300/600-second timing protocols, warmup, exact value checks, role rotation, ray policy, startup observations and drift. Its only admission extension accepts explicit per-role compiler targets over the same original source/argument/expected-result corpus. All module bytes and lineage receipts are checked before and after execution.

Use `selfhost/build/phase66/program-reference-snapshot/timing-recipe-v2.json`, not the preserved first recipe. Roles in this bridge campaign are `baseline` = current Bend-generated programs, `typescript` = old TypeScript-generated programs, and `candidate` = HEAD TypeScript-generated programs. Role names never replace actual compiler identity. The `budget-*` commands select the retained presets; `all45-part1/2/3` cover all 45 points in three batches. Compilation is entirely outside these execution budgets. Timing observations are pending until those commands finish.

For the selected new Bend compiler, `runtime/freeze-selected.py --oracles <full-23/45-qualified-oracles> --out <fresh-phase66-directory>` prepares a separate candidate bundle and commands. It requires every original point to have passed, rehashes the admitted inputs and copied modules, and pairs new Bend with the preserved old Bend and HEAD TypeScript modules. `runtime/run-v3.py` admits this explicitly qualified candidate kind while preserving the existing timing loop. B1 module qualification does not imply genuine B2 module equality; the separate bootstrap gate supplies that evidence.

Reports preserve individual samples and differences; small changes are not promoted merely because a median moved. The original held-out BST, expression and record-aggregation families remain identifiable. No finite benchmark implies full language or backend conformance. All old Phase65 tools/raw evidence stay unchanged.

`final-performance-analysis07-plan.json` under the Phase66 raw directory lists CPU0-only analyses for the final corrected attempt07: both 207-worker compiler campaigns and the three full-runtime batches. Its compilation recipes are `b1-07-full-latency/recipe.json` and `b2-07-full-latency/recipe.json`; the execution recipe is `program-selected07-snapshot/recipe.json`. Earlier attempt04 plans and measurements remain historical. `analysis/final.py` joins only completed 23-source/45-point results with identical image identities and the unchanged 600-second preset. It reports execution with equal point weights and with equal source weights, alongside separate B1/B2 compilation clocks; these finite benchmark averages are not claims about typical production programs.

`analysis/runtime-details.py --joined <selected-performance07.json> --out <fresh-path>` expands that completed join into individual point and source comparisons. It rechecks the joined input identities, reconciles both geometric weightings, retains zero-work canaries and held-out partitions, and records sample ranges and drift. Import and first-call medians remain separate from timed execution. Observed range separation is not a statistical confidence interval. The full execution campaign uses three batches with the 600-second preset; that preset is not a 600-second cap for the combined 45-point campaign.
