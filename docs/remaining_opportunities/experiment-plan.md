# A short, falsifiable next optimization campaign

Status: proposed, not executed. Baseline: Phase45 worker23 at `55e5b79`,
research cutoff 2026-10-04. Opportunity IDs refer to the [ranked list](README.md).
Use the existing experiment-file workflow; this document is not a new active
goal or permission to reopen the closed Phase45 raw campaign.

## Outcomes and accounting

The campaign should establish a useful general transformation, its actual
activation, its effect on generated-program time, and its compiler/size costs.
A new analysis, source patch or attractive isolated median is not completion.

Record four separate outcomes:

| Outcome | Evidence |
| --- | --- |
| Program correctness | Exact scoped values, errors, demand/event traces, aliases and stack behavior |
| Program speed | Quiet paired runs on unchanged inputs, with raw samples and all failed points retained |
| Compiler cost | Checked request/stage time, allocation/RSS and generated bytes |
| Iteration cost | Queue/dependency wait, builds, acquisition, execution, review/integration and unclassified elapsed time |

The previous campaign's 138.15 measured job-minutes did not explain all 323.10
elapsed minutes. Use interval accounting and an explicit dependency DAG rather
than adding parallel job durations and calling the sum elapsed time.
Implement scheduling changes only through the
[bounded pilot](../self_hosted/parallel-validation.md).

## Stage 0: explain missed work without changing generated behavior

Freeze the baseline API, runtime, Base, source and harness identities. Source
analysis and optional diagnostic derivatives must not replace that baseline.
Reuse maintained corpus artifacts for initial inspection; do not reacquire all
45 points merely to count static instructions in unchanged output.

For selected roots, emit or derive a compact record with:

- selected plan and refusal reason for stronger plans;
- private graph function/call/constructor/projection counts and exact layouts;
- aggregate consumers: private projection, private call, native boundary, return,
  storage or unknown use;
- direct-call targets and potential small helper bodies;
- repeated semantic-query keys and per-stage time;
- generated functions/bytes and duplicate specialized components.

Include the current ABI-2 full checking path in compiler-stage attribution:
its `validated` argument is not consumed by `check_program_diagnostic`. Count
actual prefix/context/instance work before designing any reuse. This is a
compiler-latency investigation, not a generated-program optimization or proof
that the checks are safe to omit.

Do not count a syntactic opportunity as a hot one. For the smallest relevant
programs, a separate instrumented derivative should count worker entry,
fallback, constructor allocation sites and actual continuation suspension.
Diagnostics run separately from clean timing and retain their own identities.

Keep the initial effect vocabulary small and explicit. Distinguish at least
`mayThrow`, public/global observation, private read/write, allocation identity,
unknown call/reentry and safe scalar computation. Derive separate permissions:
`canDiscard`, `canDuplicate`, `canMoveAcross`, and `canEliminateShell`.
Do not replace them with a single overly broad purity bit.

**Stop condition:** if there is no repeated executed work or the observations
cannot be tied to the selected output, choose another consumer before extending
the analysis. This stage should produce a decision table, not an optimizer rewrite.

## Stage 1: one fresh aggregate and its uses

Start with an exact private constructor whose input expressions have already
been evaluated into stable values. Track its aliases and uses within a structured
straight-line region. Forward matching projections and known tag tests. Remove
the allocation only when every use is modeled and object identity cannot escape.

Example, conceptual IR only:

```text
left  = checked_expression_a()
right = checked_expression_b()
pair  = Construct Pair(left, right)
first = Project Pair(pair, 0)
return first

=> keep both expressions in the same order; return left
```

The second computation stays even if its value is unused, unless a separate
discardability proof permits removal. Unknown globals and native calls are not
silently folded. Public input objects are not fresh private constructor values.

Use a saved-JavaScript structural derivative as an early falsifier only. Compare
the original, shell-only removal and any later discard-safe cleanup separately.
If the JIT already removes the shell and clean time/allocation does not improve,
record the null result. It may still be a useful enabling rewrite, but it does
not earn standalone runtime credit or justify an unbounded campaign.

For a checked implementation, update JW visitors through a small shared API;
introduce a local validator for definitions, targets, arity, projection index,
layout, terminators and scope. Existing validity flags are not a full verifier.
Start with structured-path facts; full SSA and MemorySSA are unnecessary here.

## Stage 2: bounded inlining exposes the same rule across calls

Choose only a small private acyclic helper with one exit. Evaluate actual
arguments once and in their original order, alpha-rename its slots, substitute
parameters, simplify, then apply Stage 1. Compare code size after simplification,
not merely before expansion. Retain hard per-call and per-root growth budgets.

Do not duplicate a long continuation into multiple case arms. Either refuse a
multi-exit helper initially or introduce a separately specified join/block form.
Lean's simplifier provides direct evidence that the naive composition can grow
exponentially; a general inliner is not an excuse to ignore this cost.

Inlining changes calls, sizes, uses and potentially SCCs. Recompute affected
facts before choosing Number Nat, recursion policy and entry profitability.
Keep the conservative graph bound and original dependency identities. Removal
of an emitted call does not authorize removing its source/host guard.

**Pass consumers:** aggregate elimination first; later private argument reduction,
value propagation and dead-slot cleanup can consume the same use/effect facts.
Do not add them simultaneously to hide which mechanism produced a gain.

**Stop conditions:** missing activation, semantic mismatch, code-size explosion,
material compiler regression without runtime benefit, or a clean canary loss.
Retain the rejected patch/output/receipt and its exact cause.

## Stage 3: wider function and Array coverage

Prepare both investigations in parallel, then integrate separately.

### Known local functions (O3)

Use the existing [known-local-function design](../../design/phase45/known-local-functions.md)
instead of starting another callback recognizer. Track a bounded set of lambda
sites and explicit evaluated captures through aliases, factories and helper
parameters. Lift a supported target into a first-order private function and
specialize only when the target/capture facts are complete.

Test `factory(a)(b)` with observable factory-prefix work. It must occur before
evaluation of `b` at the established source demand boundary. Add capture sharing,
branch-dependent target, partial/oversaturated application and public escape
controls. An unknown target retains the original behavior; a finite target set
is not a license to inspect mutable public code early.

### Typed internal Arrays (O4)

Begin with arrays allocated inside the root and a scalar result. Model operations
as typed nodes with explicit ordering and alias facts. Preserve native owner,
index/length behavior, errors, F32 rounding and returned array handles. Separate
operation admission from immediate tuple-shell elimination.

Reuse the semantic lessons of the earlier independent array-fold/delayed-write
controls. Add independent mixed programs that compose reads, updates, callbacks
and loops. Then stop at the public boundary: a result containing an array or
user ADT requires O5 identity/sharing-preserving adaptation as a separate change.

**Selection criterion:** actual newly optimized work across independent programs,
not whether a named morning/evening/row fixture improves. Those fixtures provide
regression evidence; they must not become compiler selectors.

## Compiler-cost and code-size track (O7)

An agent can independently census repeated definition/SCC facts and duplicated
private graphs while the first runtime pass is developed. Existing root caches
remain part of the baseline; cache-hit counts alone are not a benefit.

The first cache experiment should preserve generated bytes and selections.
Record key construction, lookup, retained memory, misses, refused facts and work
avoided. Initially invalidate an entire function/component revision after a
relevant change; incremental repair is optional complexity, not a prerequisite.

Shared emitted components require a different test. Keys must include original
definition/specialization/layout/dependency identities. Root captures and guard
permissions retain their existing scope, as does the root-lexical recursion
budget shared across nested same-root entry. Continuation frames remain
invocation-owned. Sharing a body must not reset that budget or merge distinct
roots' proof state into shared mutable module storage.

The earlier broad-cache and helper-hoist null results are mandatory comparison
points. Prove why current overlapping typed graphs offer a different opportunity.

## Agent ownership and critical path

Eight helpers are available, but eight competing IR edits would slow integration.
Use the following maximum decomposition; do not keep an agent busy with invented
work after its deliverable is complete.

| Owner | Independent deliverable | Integration boundary |
| --- | --- | --- |
| Root | Priorities, interface freeze, integration, resource queue, selected result | Only one combined artifact is promoted |
| Helper 1 | JW use/effect contract and first local consumer | Own shared model/analysis APIs |
| Helper 2 | Independent aggregate/inlining semantic controls | No implementation assumptions in expected outputs |
| Helper 3 | Known-function flow prototype/design delta | Patch against frozen interface; no conflicting schema edits |
| Helper 4 | Array effect/alias prototype and result-boundary inventory | Separate from function-flow integration |
| Helper 5 | Compiler-stage/query and duplicate-component census | Diagnostic only until a cache scope is selected |
| Helper 6 | Performance interpretation, held-out fixtures and output analysis | Uses immutable artifacts; requests execution through queue |
| Helper 7 | Independent public ABI/demand/stack review | Challenges legality before timing escalation |
| Helper 8 | Parallel validation pilot and accounting | Tool ownership separate from compiler semantics |

Code inspection, fixture preparation and review can overlap. Builds of dependent
successors cannot. Parallel local execution is allowed only under the reviewed
resource policy; clean timings require an exclusive host or separate machine.
Use patches/worktrees when ownership overlaps, not shared uncontrolled mutation.

Default to a 20-minute investigation checkpoint with a concrete finding; larger
1–2h probes get explicit milestones and a falsifier. Record when an agent is
waiting on a schema, build, decision or benchmark. Those timestamps measure
coordination latency, not continuous reasoning or token cost.

## Qualification without repeating the whole suite after every edit

1. **Static/local:** validate transformed IR, exact source identities, selection
   and expected mechanism. Tiny before/after tests exercise reusable rules.
2. **Semantic fast path:** run independent values/errors/event/alias controls,
   including expected refusal and ordinary fallback.
3. **20–60-second screen:** maintained canaries and explicit affected cases,
   with baseline/reference/candidate and unchanged input sizes.
4. **300/600-second confirmation:** predeclared deeper measurements only for
   surviving hypotheses. Preserve drift and all attempts; do not resample until
   a favorable median appears.
5. **Transfer:** use fresh programs whose source structure was not visible to
   the pass author, plus renamed/mixed variants. Renaming alone is not a holdout.
6. **Integration:** freeze the combined compiler, rerun interaction controls,
   then one complete semantic/runtime/CLI qualification for that exact image.

Duration presets do not guarantee complete coverage. The current complete runtime
comparison uses three serial full slices; record missing samples explicitly.
Profiles, counter derivatives and saved-output ablations are explanatory evidence,
not clean timing or a genuinely checked compiler release.

At each integration, report source/IR complexity as well as speed: added/removed
lines and helpers, duplicated walkers retired, new semantic concepts and remaining
opaque paths. Do not delete a stronger specialized plan before the common pass
demonstrates equivalent coverage and acceptable performance.

The decision after this campaign should be a measured next frontier. It may be
aggregate elimination, higher-order coverage, arrays or compiler analysis cost;
the evidence should choose among them rather than extend a failing favorite.
