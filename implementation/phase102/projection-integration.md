# Projection composition follow-up

The root-owned generated-C projection experiment passed all 51 frozen control
observations (36 fresh, 15 inherited) and 72 screening executions. Its six-round
paired comparison against the depth-bounded compiler gives approximately
0.941× generated-index, 0.956× real-index, 0.992× sequential-render,
0.931× four-worker-render, 0.684× DAG and 0.704× chain time. Exact records are
`projection-controls01`, `projection-screen01` and `projection-pair01`. These
are generated-C interventions, not yet a Bend compiler or native-chain result.

Readiness alone is not the missing step: `nfo_admit` already reruns worker
admission after owning-observer forwarding. Product signatures are filtered
earlier, and the existing fixed-shell ABI does not recursively flatten these
nested result shells. Broadening that ABI would be a larger change than the
observed opportunity requires.

The isolated `projection-bend-source05` candidate instead adds a 119-line
structural composition certificate. It retains the existing accepted
`NOObserverEntry` metadata during `nfo_finish`, selects an already admitted
owning caller with exact identity arguments, and reduces only a finite pure
projection of the observer's known result-wrapper syntax. The selected result
must be the exact proved scalar observation. Existing `no_adapter` then emits
the borrowed computation followed by ordinary owned-root cleanup, with no
temporary result shells. Public ABI, the original observer proof and permission
boundary, and the unrelated workers remain unchanged.

The source recipe reverses exactly to Phase98 and changes no installed source
or image. Candidate SHA256:
`b73ba46c3751752921e58d4cc75b57f152a8777008fdd82a5782f3eef0ade672`.
Initial preparation ran no compiler or program. The later root-owned
`projection-api04` acquisition passes the checked API, and all 23 exact helper
controls in `projection-bend/check-admission-v5.mjs` pass. Full-output controls,
paired application timing and native-chain qualification remain separate gates.

Independent review rejected two earlier offline versions before execution.
The first allowed beta substitution to discard a projector-created effect or
partial computation. The second retained only original schema-wrapper subtree
arguments, fixing that strictness problem, but its generic occurrence scan did
not detect unused binders that could capture an injected root ID. Version 3
keeps the immutable subtree guard and explicitly scans both Var and Lam IDs.
Both counterexamples are retained as helper-control obligations. This is why
the generated-C experiment's success did not itself justify a broader source
rewriter.

The first actual checked-API acquisition, `projection-api01`, then found that
the language requires a named match scrutinee. Version 4 moves the computed
adapter into a helper parameter before matching; its selection and safety
checks are unchanged. The later `projection-api03` acquisition found a linearity
error: `nfp_identity` queried the same argument twice without a reusable pattern.
Version 5 adds only `+arg`; the rest of the helper's repeated bindings were
audited. Both failed acquisitions remain evidence, not successful semantic tests.

The separately composed `projection-eligible-source04` includes the concrete
ordered inline-eligibility filter after the generic captured-predicate version
failed checked API admission. Its candidate SHA256 is
`12581b645a732350380e37b1f826bb191049e7d7b1b802bbaa10073244bb697d`.
Static review alone did not establish the language's template/capture acceptance;
the successful checked API is the admission evidence.

The offline `projection-activation01/report.json` audit compares all 17 actual
`projection-emission01` products with `depth-emission01`. Eight sources activate
the rule: all three applications and five control sources. The other nine C
products are byte-identical. In every activated source the only changed worker
body is `String.order`: it directly calls the unchanged borrowed comparison,
checks for error, drops both saved owned roots and returns the observed scalar.
It bypasses two temporary Tuple allocation sites and the final projection.
The original observer, owning adapter and projector bodies remain identical.
The structural selector also identifies these same eight callers in the saved-C
prototype; no application or String name is part of its admission rule.

The shortened worker enables the existing hint policy to force-inline
`String.order` and `String.eq`, plus `String.is_le` in the renderer. Replacing only
the admitted body and normalizing these hint tokens reconstructs every complete
candidate C product exactly. Actual Bend lowering is smaller than the prototype:
it reuses the owning adapter emitter with a scalar result rather than introducing
the prototype's private three-Term product. This establishes activation and code
shape, not a runtime gain. The audit binds `projection-eligible-source04`; it
does not cover the separately composed `projection-cold-source01` candidate.

See the [method boundary](../../selfhost/tools/performance/phase102/projection-bend/README.md)
for budgets, capture prevention, unsupported syntax and remaining proof limits.

## Keep allocation elimination separate from forced inlining

The later root-owned native-chain03 qualification exposed a local-fold runtime
regression. Its saved-C `restore-hints01` ablation changes only four hint tokens,
restoring the prior `INLINE` declarations/definitions of `String.order` and
`String.is_le`. The optimized borrowed computation remains. Root's paired probe
reports that these hint changes restore fold parity, identifying a profitability
interaction between passes rather than a reason to restore discarded tuples.

The isolated successor `projection-cost-source01` changes one expression in
`nfp_replaced`: its conservative dependency metadata becomes old dependencies
followed by new dependencies. Every actual new call stays represented, while
the old adapter/projector chain remains a lower bound on dependency cost for
forced inlining. This operates after ordinary admission. The only consumers
of the dependency field are readiness and inline membership; body emission,
ownership cleanup, public ABI and the projection certificate are unchanged.
Each round of the three-pass inline closure can only shrink relative to the
parent. Clang can still inline ordinary functions using its own cost model.

An offline actual-C graph model predicts restoration of exactly the old hint
sets on all 62 retained products (45 native runtime products and 17 focused
products), with no extra or missed demotions. Exact pins and per-product results
are in `projection-cost-model01/report.json`. Candidate source SHA256 is
`63ef222c4c6de73bb54c8e51d3b0a0552979b5791ea98e64d1098051a9cda237`;
its recipe reverses exactly to Phase98. This is experimental candidate04:
candidate03's native qualification does not transfer to it. The later checked
`projection-cost-api01` acquisition passes. An offline audit of its three actual
application emissions (`projection-cost-activation02/report.json`) confirms
complete C differs from qualified03 only in hint tokens and restores precisely
the depth02 hint maps. The same closed seven-product audit confirms four runtime
products exactly equal the prior hint-ablation C. It authenticates their raw
build/run receipts, binaries and full outputs: 32 matching-product observations
are inherited, within 128 total observations across four compared roles. None
are fresh candidate04 executions. The early activation01 snapshot had pinned
the still-open batch manifest and is preserved with a supersession note. Timing
and any later native image gates remain separate; candidate04 is experimental.
See [the small cost policy](../../selfhost/tools/performance/phase102/projection-cost/README.md)
for the consumer audit, monotonicity argument and byte-budget limitation.

The subsequent `projection-cost-screen01` executes the three actual Bend-produced
applications in four alternating rounds, checking all 72 complete outputs.
