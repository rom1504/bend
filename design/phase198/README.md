# Direct x86 runtime parity

The starting qualified frontier is 1.86457× mature self-hosted Bend C on the native45 corpus (44 timed programs). The Phase197 candidate is source-checked and runs faster on six targeted inputs. The wide suite will decide its actual gain. Qualification, all optimization experiments and model comparisons run on one guarded CPU. Independent source development and offline machine inspection can run concurrently. Keep the five GiB reserve and the previous compiler.

1. Acquire a native compiler from the exact Phase197 source. Freeze current and candidate products, compare ordinary outputs and fresh full-corpus runtime. Continue through N2, conformance and object reproduction. Re-run the broad metric after substantial further changes can justify it.
2. Test removing *iterations* and *intermediate representations*. Two promising examples are a countdown after a terminal state and a complete fixed-point numeric loop whose coordinates stop changing after escape. Compare ideal code, the specific transformation on ordinary output and the measured compiler implementation. Separate whole-loop gains from instruction-level gains.
3. Test adaptations of existing semantic and machine information. Candidates include eliminating ownership transfers in constructor permutations, shortening scheduler transfers while preserving bounded stack, coloring compatible recurrence values together, and improving stack placement in call-rich functions. Freeze legality, inputs, rough ceilings and refusals before investing in implementation.
4. Attribute runtime-library costs with identical direct objects. The mature C reference is built with Clang at O3, while the x86 support library uses GCC at O2 and an immutable descriptor accessed indirectly. Recompile the existing support code and test precomputed constructor, heap and capability facts, independently of generated Bend instructions. Compare full outputs, compiler/runtime identities and whole-program timing. Keep the C reference as measured.
5. Compare alternatives rapidly on one or two hot inputs and unrelated controls; use physical work counts and LLVM-MCA selectively. Preserve nulls and failures. Use independent C oracles, compiler structure/refusal controls, two orders/sessions, held-out cases, direct objects, full-suite measurements and self-reproduction in that order when warranted. A hand-derived ceiling, a checked Bend implementation, and a native-qualified compiler have distinct evidentiary value.

The objective is the ordinary optimized direct-x86 target. Benchmark inputs, inner repetition counts and observable results must retain their meaning. Optimizing away repeated benchmark invocations or substituting a program compiled by C does not test the objective. Aggregate ratios use the historical geometric metric and include every eligible case. Report runtime and compiler costs separately.
