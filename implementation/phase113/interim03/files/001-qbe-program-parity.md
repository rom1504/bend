## Objective and fixed comparison

Make programs generated by the compiler written in Bend reach pinned upstream
native runtime parity while preserving correctness and keeping compilation fast.
Keep the five metrics separate: generated-program runtime; experimental native
N1 and N2 compiler-request time; conformance; and source/concept complexity.
Production B1/B2 labels and installed selection are not silently reassigned.

Phase112 facts is the frozen baseline: 15.94324× upstream geometric runtime on
44 measurable points across23 historical families, plus one zero-work control.
Local-pair/edit-distance take135–145× upstream time; scalar-region11.78× and
Mandelbrot15.86×. Compiler requests take about2.08× upstream time on three sources;
ready-executable construction is near1× under the asymmetric cached-runtime
policy. These are different clocks. Previous word-profile source/counter audits
are historical witnesses; recheck changed facts bodies before claiming a current
mechanism. Original inputs, expected complete outputs, timing repetitions,
upstream pin/tools and fixed runtime remain immutable references.

Ratios mean candidate/reference elapsed time, lower is faster. No speculative
gain range is a guarantee. Broad parity needs general transformations: even
magically making the four slowest points equal upstream leaves the aggregate
at10.17×. Do not optimize by benchmark name, omit regressions or redefine a case.

## Central hypothesis

The generic backend lowers ordinary functions into boxed values, runtime frames,
scratch-bank moves and dispatcher transitions, then attempts to recover direct
workers from that committed representation. The mature C backend already has
ordinary destinations, self-tail loops, fixed product layouts, multiple results
and checked array policies. Some of these decisions are entangled with C-string
construction. Extract or reuse the semantic decisions in Bend and render them as
structured machine IR before generic runtime lowering loses them.

QBE already constructs SSA. A second general SSA implementation or a new machine
backend is not a prerequisite. Preserve unsupported effects, unknown calls,
escaping closures and unqualified recursion on the existing generic path.

## 1× ambition: complete ordinary scalar regions

Extend checked result/ownership facts through recognized primitive results,
closed callees and conservative branch joins. Keep physical Term widths separate
from whether a value requires ownership operations. Build complete ordinary
function regions with explicit destinations/local joins, scalar results and
self-tail loops; use the existing structural verifier and QBE renderer.

First decisive case: the current scalar-region loop plus two unrelated semantic
controls. Require the intended steady-state runtime frames/dispatch/ownership
calls to disappear, not merely more private definitions. Then inspect the ray
call chain and an independent list/string traversal. Use source rules and exact
checked identities, never fixture names. Reuse mature `nf_*`/`nq_*` analysis and
liveness where practical instead of writing parallel recognizers.

Expected information: whether complete loop shape closes a large part of the
runtime gap, and which existing admission boundary actually blocks it. A partial
fact change that leaves the hot graph unchanged does not justify a broad run.

## 10× ambition: shared direct-function and product planning

Introduce a small reusable representation of complete functions: typed inputs,
explicit result vectors, joins/tail edges, ownership facts and closed-call
summaries. Share layout/admission semantics with the mature C path, leaving
backend formatting separate. Admit complete regions before boxing and runtime
continuation construction. Preserve one generic fallback and one runtime ABI
where possible; adapters at boundaries must be explicit.

Add flat product arguments/results and checked direct array-result lowering.
Start with `(array handle, scalar)` across two ordinary functions, then a loop
carrying several handles. Return fields through typed output slots when required
by the machine ABI; do not rely on an implicit C aggregate convention. Avoid
allocating temporary tuples/state records when their fields remain available.
Ownership belongs to each field; unknown/escaping layouts remain boxed. Test
shared and unique arrays, owned String fields, permutations and both release
orders. The local-pair/edit-distance family is an evaluation consumer of these
general rules, not a recognizer input.

If that succeeds, admit mutually tail-recursive groups atomically into a local
loop/control-flow graph. Preserve stack-bounded execution. Non-tail reconstruction
requires an explicit destination/continuation design and stays generic initially.

Expected information: whether representation and control decisions optimized
together eliminate whole categories of work. This is the main path toward
broad runtime parity, and it must remain simpler than accumulating unrelated
late pattern repairs.

## 100× ambition: architecture-level equivalence and joint optimization

Make the checked direct-function plan the shared semantic foundation for optimized
C and QBE emission, including field layouts, ownership transfers, call effects,
closure/environment specialization and bounded recursive groups. Build a layered
optimizer where facts survive until consumed, so transformations compose without
reconstructing semantics from runtime calls. Retain explicit scheduled/effectful
regions and stack-safe generic adapters rather than erasing Bend's execution
semantics merely to obtain sequential benchmark speed.

Use a small equivalent-kernel experiment through QBE and a Clang control after
matching representation/control flow. Compare instructions, memory traffic and
spills. This isolates residual machine-backend limits from semantic lowering.
Only then consider targeted machine optimization or alternative backend work.
A bounded law-constrained search may choose among admitted inlining/layout plans,
with an immutable evaluator and separate search/evaluation inputs. No learned or
recursive improvement is claimed without measuring validated gain per time.

The100× label describes ambition and scope, not a forecasted speed multiplier.
It is selected only when smaller experiments give credible evidence and the
implementation remains reviewable within the time budget. Avoid a whole-compiler
rewrite with no executable checkpoint.

Use bounded disjoint agents for direct-function planning, product/array ABI,
independent semantic controls and offline harness/evidence preparation. Root
integrates and owns the serial CPU3 target lane. Agents do not independently run
compiler acquisitions, broad tests or timing targets. Prefer reuse of existing
infrastructure over new framework code. Model labor/quotas are not available from
process receipts; report measured target occupancy without inventing token costs.

Authenticate duplicates before hardlinking; historical shared inodes stay immutable
and every new output uses a fresh path. If compression is needed, retain verified
lossless archives and explicit restoration indices before removing an original;
never delete unrelated work. Secure headroom before full acquisitions.

Full target guards: CPU3, at most4GiB process-tree RSS, at least16GiB available
memory,128MiB per generated file; small jobs2GiB. Deadlines are bounded. No
unqualified parallel/GPU claim. Current sequential execution scope stays explicit.

## Correctness and evidence

All compiler algorithms remain Bend. Host Python/JavaScript may transport source,
execute checked APIs, supervise processes, gather counters and compare evidence;
they may not implement semantic lowering. Never edit human-written `bend2/bend.ts`
or the pinned upstream reference. Keep ordinary runtime checks unless premises
for their removal are established in the checked pipeline.

Use independent scalar edge cases, shared/static ownership and alias survival,
constructor layouts, arity/signature mismatches, escaping values, strict evaluation
order, failures and deep recursion. Retain structural verification, exact original
expected outputs, source/runtime admission and mutation/refusal controls. Tests
are not whole-compiler proofs. A changed runtime requires separate qualification.

Freeze current facts source/API/N1/N2/runtime and all timing inputs. Native
self-reproduction and broad tests are integration gates rather than every-edit
loops. Keep compilation, construction and program execution times separate. Record
individual samples and aggregate scope, cache policy, code growth and memory.
Existing rejected immediate-helper lowering remains excluded until independently
explained and qualified; do not resurrect it because a local control passes.
