# Reverse an owned hot constructor spine

The checked RLE worker lrevp.go takes apart a List.Con cell, constructs a new List.Con with the same head and the current accumulator, then loops on the previous tail. The actual qualified ELF's CID18 metadata marks Con hot. Ordinary reconstruction seals the accumulator when it is a raw constructor. A raw in-place rewrite would silently violate that invariant. The frozen experiment begins with an exact empty accumulator and a unique, dynamic raw cell. It moves its old tail to the cursor and seals the already-packed empty list by leaving its word unchanged. At later steps an incoming count-one RFC normally wraps the next input node. Transfer that uniquely owned wrapper to the previous accumulator by replacing its referenced physical location and preserving count one. The input node's data cell becomes the new raw result node. The new tail slot holds the transferred wrapper, whose CID is the same concrete two-field list constructor as both nodes. Never touch heads. No allocation, free, call to keep/sink, or count update on these transitions.

Bound the first experiment to the named valid-input RLE worker, exact current native assembly and immutable ABI11102 descriptor. A nonempty entry accumulator, shared count, static data location, different tag, or incompatible storage returns to the untouched old loop before writing that step; the accumulated prefix is a fully valid owned list at that point. Count raw starts, RFC transfers and fallbacks in a separate executable. Require agreement with mature C, at least five of six favorable pairs and a median ratio no greater than 0.98 in both GNU-as layouts before a checked implementation. Include held aliases, shared tails, static and dynamic fallback, and a tail that remains live after dropping the result. This experiment addresses the list's hot-publication requirement independently of the cold tree swap rule.
