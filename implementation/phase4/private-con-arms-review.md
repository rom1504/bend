## Evaluation and scope

The tokenizer proves the exact literal arm shape and matching closing delimiters. Each replacement retains the outer one-argument function and calls the same `project("Con", value)` before entering the body. It deliberately adds no tag check: wrong-tag values with two fields retain `matcher1` projection behavior. For an ordinary two-element field array, private exact `apply` already passed that array directly to the arm. Binding it as local `a` therefore preserves the selected body's ordered arguments, rather than removing an observable public array copy.

The body stays inside a fresh function activation in the same enclosing lexical environment. Nested functions keep their own argument scopes. The transform rejects tokenized `this`, `arguments`, `eval` and `super`, conservatively including occurrences in nested functions. Reserved experiment identifiers are refused across the entire input. Recursive rendering handles nested selected arms; the exceptional-field-count fallback retains the original nested body verbatim.

Zero, one and more than two fields take the original arm application path: zero returns the unsaturated arm, one creates its partial application and larger arrays retain ordinary overapplication and forcing. For two fields, the original body returns its bounce/build/value directly to the same `force` loop. It does not force a build field or a returned function prematurely. Thus the removed trampoline transition does not consume JavaScript stack per tail visit. Projection exceptions precede body effects; the existing tests cover this, selected versus unselected effects and build-field order.

## Limits and future guard requirement

This is not a general JavaScript transformation. The present syntax checks do not establish that `a` is read-only or that body declarations cannot shadow the introduced `project`/`fn` accesses. For example, an otherwise matching hand-written body assigning `a=[]` would change a mutable parameter into a `const` assignment; `var a` could become a syntax error. A local `project` declaration could put the introduced projection in its temporal dead zone. These are concrete unsupported-source patterns, not observed failures of the frozen compiler image. A lightweight tokenizer inventory of all 192 actual bodies found no parameter writes, declarations of `a`, `project` or `fn`, or refused scope-sensitive tokens. If revisiting this experiment on different emitted syntax, add fail-closed checks and regression tests for these patterns before claiming reusable transform support.

Malformed ordinary field arrays are covered, but proxies, accessor arrays, mutation of compiler graphs or observable function identity remain outside the private text-only transport contract. The additional `a.length` test can be observable for a hostile proxy; the shape fallback is not a public arbitrary-JavaScript compatibility guarantee. Original public compiler/runtime code remains untouched.

The marker, matcher text and Con metadata guards are consistency checks, not authentication or a complete runtime fingerprint. Reproduction depends on the separately recorded exact input image/runtime identities. Equal selected outputs cannot establish complete conformance, nor repair the independent lexical-capture failure in the underlying private-call transform.
