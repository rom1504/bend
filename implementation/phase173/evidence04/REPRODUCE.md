# Phase173 evidence04 checkpoint

This capsule records completed experiments only. It extends evidence, evidence02 and evidence03; it does not replace their pinned producer/compiler/runtime evidence. No production compiler or installed selection was changed by this collection.

## Results and their limits

- **Layout substitution:** complete typed value agreed with pinned upstream JS and independently checked constant-program native readback. The complete-value execution pair is below the harness timing floor (3.63/3.34 ms), so it establishes agreement, not a resolved speedup. The independently checked digest workload runs in 92.683 ms baseline / 73.427 ms candidate, ratio **0.792235** across four paired rounds. Its candidate source also passed upstream checking. This is an extracted compiler computation, not a full compiler speed result.
- **Consuming compiler overlay:** the checked full experimental compiler emitted byte-identical QBE for the real 39,333-byte verifier source. This is one hosted request. The receipt explicitly says the separate native output oracle was not executed in this request. There is no new self-hosting or installed-compiler qualification claim.
- **Borrowed wide-store06:** 80.269 / 80.266 ms, ratio **0.999967**, with complete native output agreement. Instrumented event counts remove 4,508 logical allocations and 2,254 constructor takes, but add 2,046 keeps/sinks/drops; dispatch count is unchanged. Fewer allocations did not produce a resolved runtime benefit in this pair.
- **Explicit eight-field result:** revision 2 passed source checking, 26/26 finite cases, all 3 expected refusal cases, 16/16 complete roundtrips, and complete comparison of 101 actual compiler bodies. The independent full-value comparator covered 1,417,426 checked-request values, 229,340 input values and 321,590 output values. However the emitted-shape gate **failed**: the compactor still contains 11 Store7 construction and 15 take7 sites plus two boxed edge-helper calls. No runtime win is claimed and no machine build was launched for that failed shape gate.

The 26 listed guarded runs completed with zero process failures. Separately, one completed structural acceptance gate failed. Expected invalid-input refusals are correctness successes, not process failures. All scopes, pin identities and individual samples are retained in the original receipts.

## Reproduction

1. Start from the same repository source revision and canonical assembly hash recorded by each source manifest. Restore exact frozen modules from `modules/` to the original locations in `copy-provenance.json`, or adjust paths while preserving bytes. Earlier producer sources and recipes remain in the previous evidence capsules.
2. `recipes.json` retains the exact guarded target invocations. Source-preparation recipes are explicitly reconstructed from manifests and tool CLIs. Use **fresh output directories**; never overwrite historical evidence. Every source must reproduce the source SHA-256 in `source-pins.json` before target acquisition. The small layout sources are included verbatim in `workloads/`; large assembled compiler/native-literal sources are deliberately omitted.
3. Use the authenticated source/Base/carrier/stamp/API/toolchain/runtime pins in the receipts. Checked APIs must be rebuilt rather than substituted with an arbitrary executable. Source preparation is host transport; the checked Bend compiler performs the compilation.
4. Follow oracle order for layout: checked original upstream API → complete-value or U32 oracle → independently checked constant native readback where recorded → baseline/candidate machine builds → exact stdout pair. Do not infer complete semantics from digest agreement alone.
5. Recreate wide8 full observations using `store-wide8-verifier02` and then the literal native source using the recorded `vertical-native.py` recipe. The multi-megabyte full observations, 827 KB literal entry, QBE, assembly, binaries and compiled APIs are pinned, not copied here. The 101-body corpus is not silently reduced.
6. Preserve the single guarded execution lane, CPU affinity, memory/disk limits, runtime/compiler flags and paired-order benchmark policy in each `process.json`. Timing comparisons need comparable hardware and a fresh controlled rerun. Instrumented counts are not clean timing.

`inventory.json` hashes every retained file except itself; `copy-provenance.json` maps verbatim copies to originals. Manifest projections retain the original manifest hash and explicitly name omitted declaration/source-map inventories. `referenced-artifact-pins.json` is the deduplicated set of identities embedded in these historical receipts; it does not claim every large artifact remains on disk. The frozen v2 wide-return audit preserves exact inverse token equivalence and the affine payload correction.

Retention evidence includes only completed operations. Storage02 and storage03 both completed before this capsule was finalized; their exact proposal, capture, verification and apply receipts are included (8 and 22 roots respectively). Net filesystem free-space changes are observational, not archive size claims. The ongoing automatic decomposition pass is not part of this checkpoint. No targets were run to package this capsule.
