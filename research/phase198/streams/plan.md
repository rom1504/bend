# Linear stream and text homomorphism ceilings

Two further tests ask whether the remaining C gap permits work-elimination gains across unrelated programs. They change only source algorithms inside a measured diagnostic copy. The original direct-x86 machine product and independently built mature C executable remain the comparison. Ordinary points, input domain, output strings and benchmark harness stay intact. Alternate inputs use the C oracle.

1. Feed the lexer's generated characters directly into its unchanged token transition. The state is advanced in original character order. The producer uses total word arithmetic, contains no IO and never exposes its partially built string. The original template, seed mixing, classifier, lexer modes and checksum stay unchanged. This tests removing string construction, linear traversal and destruction as a unit. An automatic rule would have to recognize a producer with a private tail destination and a left fold with a private carry.
2. Rejoining a split that includes leading, trailing and empty fields replaces each delimiter with the joining string. This operation distributes over concatenation. Mapping the block once before repetition avoids constructing the intermediate full text, list of fields and rejoined output; final output bytes are still produced and measured. The initial ceiling pins the exact one-character separator as observed in the source. A general compiler rule would require a checked split/join law or equivalent structural evidence binding the actual definitions, and a total pure map. Consecutive delimiters, empty strings, multibyte Unicode and zero repetitions discriminate different split conventions.

No benchmark recognizers or user workload changes enter production. Use these ceilings to decide whether a compiler-level stream transformation deserves a qualification campaign.
