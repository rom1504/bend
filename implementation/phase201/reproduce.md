# Reproduce the cold comparison

Run from the repository root with the qualified Phase198 progress chain, prepared Base, runtime and historical receipts available. Use fresh run names and fresh artifact directories. The recorded commands and input hashes are in the evidence file. The ordinary job wrapper uses the repository's serial CPU3 lane, 5 GiB disk reserve, 16 GiB available-memory floor and 3 GiB process-tree RSS limit. Allow enough additional disk budget for other filesystem activity. The compact native image is about 5 MiB on disk.

1. Run `python3 -B research/phase201/cold/prepare.py --out selfhost/build/phase201/source-replay`. Upstream-check the resulting compiler with the source-check command from the check02 receipt. Its SHA-256 should be `a68ba12c823fff623c58f31154ddca5de8d80cce9a207f3f14b04e95c20836d0`.
2. Replay the runtime screen with `cold/job.py` and `cold/runtime_screen.py`. This builds the experimental single-mutator compiler runtime. The original runtime remains the product runtime for ordinary source requests.
3. Use the acquire02 command with the new source and runtime paths. The qualified QBE-produced x86 compiler emits an x86 object directly, then the linker produces the x86 candidate. The complete compressed executable lives in the fresh output directory. Acquisition is a separate cost.
4. Run the candidate on the 39,333-byte real verifier closure, check the frozen object hash and execute the linked verifier. It must print 768.
5. For the historical comparator, use the Phase198 `progress-native-reproduction01` receipt. A fresh baseline can be collected by running the cold replay with `--full baseline`. Run `--full image:PATH/TO/program.gz` for the candidate. Both commands rebuild the frozen 1,947,566-byte compiler source. The cold replay checks the full object and compares allocated sections of the linked ELF against the qualified reference. Compression, decompression, digest checks and independent source checking are outside the timed interval.
6. To measure strict self-reproduction of the *new* implementation, run the candidate with its new source and the same experimental product runtime as acquisition, using `--reference PATH/TO/acquisition/results.json`. That is a different workload from the historical comparator.
