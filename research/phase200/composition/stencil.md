# The complete-state row has little stencil work to eliminate

The ordinary complete-generic-row32 invocation runs 32 DP cells, then serializes all 512 words of four arrays, yielding 1,079 bytes including its trailing newline. Before the checked spill optimization it took 258.68 µs per native invocation, versus 80.18 µs for mature Bend C. The confirmed spill rule dropped six frame accesses per cell and improved the median paired time by 0.61%. [Measured programs and complete output](../spill/RESULTS.md).

A candidate transformation could forward the current-row value written at the previous cell into the next cell's left-neighbor read. For a row of n cells beginning with a real backing-array read at j₀, this removes at most n−1 subsequent reads. It still writes every result and publishes the same final array. The equality required is between physical addresses: the write must use the same base and element width as the next read, and the same masked word index after the wrapping U32 increment. The current array must be unchanged in the interval. An unknown writer, escaping mutable alias, differing mask or base, unexpected control-flow entrance, or observable fault outside the verified memory contract invalidates that equality. An empty row must skip the initial read. These are proof obligations for a future rule.

At n=32 this mechanism could eliminate 31 reads. Saving 2% of the observed 258.68 µs requires approximately 167 ns per eliminated read. In contrast, the entire ordinary local-pair run, including 65,536 cells and its setup and completion, averaged 348.74 µs, or 5.32 ns per cell. Cache state, entry costs and output behavior differ, so this comparison estimates opportunity and cannot prove a latency bound. It leaves insufficient evidence to allocate a compiler experiment to the remaining complete-state performance gap. The candidate was not implemented or timed.
