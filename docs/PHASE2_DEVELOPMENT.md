# Fast conformance development

Use a checked bootstrap API for small source edits, and keep full self-hosting
and broad corpus sweeps separate from the edit/test cycle. Both the bootstrap
and self-emitted APIs execute the compiler algorithms written in Bend; the
bootstrap's JavaScript was generated by the pinned upstream compiler.

The [phase 2 design](../design/phase2/fast_conformance_loop.md) explains the
priorities and trust boundaries. The [implementation report](../implementation/phase2/report.md)
records measured results, exact artifacts, unsuccessful attempts and remaining
conformance differences. The commands below run from `selfhost/` with Node 24
available as `node` and the pinned upstream tree at `.bootstrap/upstream`.

## Build once after a compiler edit

```sh
BEND_UPSTREAM="$PWD/.bootstrap/upstream" \
BEND_TYPED_API="$PWD/build/phase2/dev-api.mjs" \
  node tools/typed-driver.mjs --bootstrap
```

This fully checks the current Bend compiler source and writes a selected API,
`dev-api.mjs.bootstrap.json`, and immutable source snapshots. It does not replace
the default distributed compiler. New bootstrap reports verify a clean pinned
upstream tree and hash the consumed upstream compiler files, host/build tools,
manifest and source snapshots before and after checked emission. Historical
reports lacking this build provenance remain historical evidence.
Reuse this API until the compiler source
changes; editing a test or rerunning a failed probe needs no rebuild.

For the focused frontend rules changed in this phase:

```sh
BEND_TYPED_API="$PWD/build/phase2/dev-api.mjs" \
  node --stack-size=4096 tests/frontend/phase2-rules.mjs \
  build/phase2/frontend-attempt-01.json
```

Use a new report path for each attempt. This command compares 21 invalid/valid
control cases with live pinned TypeScript APIs. It checks acceptance and rejection
phase, not exact diagnostic formatting or the entire language. The recorded
phase 2 run took about nine seconds with a reused API and warm Base cache.
A later complete checked rebuild plus this matrix, starting without a candidate
Base cache, took 40.5 seconds; see the report for its exact artifacts and scope.

The separate 25-case grammar matrix uses the isolated paired harness:

```sh
node tests/frontend/phase2-grammar.mjs build/phase2/dev-api.mjs \
  build/phase2/grammar-attempt-01
```

It covers required types on marked parameters, list delimiters, and valid
quantity parameters, typed arrays and statement/IO semicolons.

## Select exact upstream probes

Create `build/phase2/dev-target.json`:

```json
{
  "upstream": "../../.bootstrap/upstream",
  "api": "dev-api.mjs",
  "runtime": "../../src/runtime.mjs",
  "bootstrapReport": "dev-api.mjs.bootstrap.json",
  "timeoutMs": 30000,
  "stackKb": 4096,
  "heapMb": 4096,
  "cases": [
    {"id": "base/list_sort.bend", "lanes": ["check", "js"]}
  ]
}
```

Then run:

```sh
node tools/conformance/target.mjs build/phase2/dev-target.json \
  build/phase2/target-attempt-01
```

Paths inside the configuration resolve relative to that configuration file.
An optional `cpu` integer pins execution on Linux; omit it for portable use.
The command verifies the checked API's provenance, freezes its host and harness,
and runs the same selected probes through live upstream and the Bend candidate.
It retains the two reports, paired discrepancies, requests, responses, logs and
generated programs. It never bootstraps or runs a full self-hosting chain itself.

`selectedComplete` concerns only the selected probes. Full-suite `complete`
remains false. Exact fixture agreement, semantic agreement and diagnostic
differences remain separate. A rejection during parsing is not evidence that a
checker or proof rule ran. Upstream JavaScript effects requiring unavailable Bun
are reported as unsupported; they are not executed through a substitute runtime.

Use `rerun` in a new configuration to name a previous `candidate.json` and select
its failures. With explicit `cases` as well, previously failing selected cases
run first. Each attempt has a fresh directory and records the previous report's
hash. Unknown, duplicate and empty probe selections are rejected.

For a retained exact replay, use the `replay` command recorded on that result row.
Replay requires unchanged source/support files and compiler/host artifacts; it
creates a new attempt rather than modifying the old result. It is not a portable
bundle that can be moved independently of its input paths.

## Runtime limits and larger milestones

The worker's explicit Node stack and old-space settings propagate to generated
JavaScript children. The driver forwards only those resource options, not loaders,
evaluation commands or debugger flags. Directly running a generated `.mjs` file
still uses the Node options supplied on that command. A 4 MiB JavaScript stack
needs an adequate OS stack; the self-hosting runner checks for at least 8 MiB.

Run the complete component build and tests separately:

```sh
BEND_COMPONENT_DIR="$PWD/build/phase2/components-attempt-01" \
  node tools/verify.mjs
```

This preserves the build, captured source and `report.json` in a fresh directory.
`BEND_COMPONENT_REPORT` can select a different report path. An earlier recorded
build plus 19 test groups took about 35 seconds. These timings are
local observations, not guaranteed budgets. Full checked self-emission remains a
larger milestone; use the recipe in [Bend-in-Bend](BEND-IN-BEND.md), freeze its
source/API/runtime/host, and let it run while targeted tests use another CPU.

For the two measured small workloads, validated Base caching makes the ordinary
JS API as fast as or faster than the native graph host: about 1.6–1.9 seconds
versus 1.9 seconds per fresh process. Uncached JS took about 6.6–6.7 seconds.
Use the cached checked API for small edits; native compilation has a substantial
build cost and is a separate option to measure on larger workloads.
Its [explicit graph manifest interface](../selfhost/tools/performance/rapid/native-graph.md)
extends the original main-plus-Base experiment to provided modules and reachable
JavaScript foreign assets. Module loading, checking and emission remain in Bend.
The host supplies files and process management. Consult that guide and the
implementation report for validated scope before choosing native for a batch.
