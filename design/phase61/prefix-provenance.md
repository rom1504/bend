# Private native prefix provenance

The state04 profiles identify repeated Base comparisons after checked-prefix
reuse: loader `f_fresh_prefix_tail` receives 61.20/62.20 ms of sampled inclusive
time for Numeric/MapSet, and checker `base_prefix_split` receives 31.48/30.39 ms.
These are disjoint ancestor partitions of one profile per source, not clean
latencies or guaranteed savings. Cache decoding/validation is a separate host
transport experiment. The new compiler work remains implemented in Bend.

The private carrier is produced and advanced by actual native loading. It is
never inferred from a public seed, a Boolean supplied by a caller, a rehashed
fabricated state, or an arbitrary API implementation. Existing public raw graph,
seed and checker functions retain full structural comparisons.

`f_prefix_complete_seed` delegates `f_complete_seed`. Only a successful exact
Base path/text match, empty prior book and completed-source list, empty errors
and a global namespace admit the initial carrier. It retains the actual injected
prefix and its top-level event count. A nonleading/namespaced/repeated injection
uses the ordinary path. Cached state still binds current API/Base/path/source
interval and the actual preparation producer under the established private
prepared-cache trust model; a digest is not an authentication proof against
fabricated local cache contents.

`f_prefix_complete_source` delegates the unchanged native completion routine.
`f_graph_finish_module` rewrites only the new module fragment and appends it with
`norm_defs_join(prior,new)`, which copies prior list cells while retaining their
definitions. A shallow drop of the certified prefix event count therefore
retains the actual returned suffix. No term equality is needed to establish a
property already preserved by this native dataflow. Any completion error or
short result discards the permission. The driver may only thread these opaque
values through its internal authenticated API flow; raw `discoverSources` and
caller-supplied API/seed paths do not receive permission.

Finalization still runs whole-graph parse validation, duplicate/fresh-name
checking and origin/diagnostic refinement. It uses the actual prepared freshener
counter, freshens the actual suffix and produces `FPrefixLoad{trace,prefix,suffix,
ready}`. Validation/refinement preserve the book; only the suffix is freshened.
The private checker consumes this returned suffix, retains all suffix name and
constructor collision guards, fresh-floor/budget guards, whole declaration
predeclaration, raw Base publication and checked-output replay, and complete
world/diagnostic behavior. A failed carrier uses full checking. Public
`base_prefix_check` continues to split and compare arbitrary supplied books.

The same prototype computes `base_prefix_final(prefix)` once per resume and
threads that actual list through admission and replay. This removes duplicate
local computation without changing persistent state or world construction.

Focused qualification must compare the complete old/new `FLoadTrace`, `DChecking`
world and completed output on actual Base plus Numeric/MapSet, with activation
counters proving the two deep prefix comparisons were avoided. Test nonleading
imports, namespace and alias paths, Base/API/path/text/span invalidation,
completion failures, declaration/constructor collisions, moved fresh floors and
empty suffix. Dropped/reordered/changed raw prefixes must continue to refuse
through the existing public equality path. Caller-created carrier data is not a
private capability and is never admitted by the public driver. Source/module
byte equality and held-out sources follow only a qualified candidate.

No target has executed this prototype at registration. Root owns builds,
resource guards and selection; independent source/driver review precedes use.
