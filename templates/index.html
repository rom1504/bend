CONFORMANCE

Keep different gates separate.

Frontend agreement, native programs, backend contracts and command-line controls test different behavior. Counts are not added across overlapping suites. Expected rejections are labeled, diagnostic differences remain visible, and reused observations retain their provenance. An emitted-C fixed point is a reproducibility result; local proof checks establish only their stated optimization contracts.

SIMPLICITY

Count the same boundary.

Canonical module lines, assembled compiler lines, command-line policy and C providers are separate counts. Their histories are labeled rather than spliced. Native deployment removes interpreter dependencies from ordinary requests, while bootstrap tools, generated C, the runtime and tests remain distinct parts of the system.

Generations, measurement freshness and release boundaries

The native core is Phase 102 candidate04. B1 and B2 compile the same source and produce the same 30,373,059 C bytes and clock-stripped diagnostic. Phase 104 re-authenticates the archived artifacts; it does not build a B3 executable. The historical full-source request observations are 126.584 seconds for B1 and 150.846 seconds for B2. They are individual observations, not a repeated generation-speed experiment. Building the executable with Clang is a separate clock.

The Phase 103 standalone command uses that native core with a public Bend entry point and a distinct build bridge. Its 41 integration controls and six complete C/verdict pairs pass. This release does not establish a new matched-source fixed point. Ordinary requests need no Python, Node, Bun or TypeScript subprocess. Bootstrap and development still use external tools, and emitting C still requires a C toolchain to produce an executable. The CLI is qualified on Linux x86-64 for its documented source and effect scope.

The broad frontend comparison is 3,173 of 3,174 exact observations: B2 rejects one invalid proof correctly but prints a short fallback when deep diagnostic rendering overflows its JavaScript stack. Historical JavaScript golden coverage retains 1,045 passes, 123 unprintable-main exemptions, one shared Process.run failure and one graphics deferral. Native fixtures, semantic programs, backend obligations and CLI controls have separate gates and dates; the public CLI release did not rerun every older campaign.

Phase 104 adds a fresh two-case, 16-request native screen and a research baseline. It supplies no new upstream comparison, full self-build, generated-program campaign or evidence of accelerating research yield. The main performance figures remain tied to their latest broad campaigns; current JavaScript runtime timing is explicitly carried forward using output identity.
