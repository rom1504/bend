# Reciprocal equality transplant

The portable slowdown does not transfer directly to our compiler: our selected `f_eq`/`p137q_name_eq`/`index_bucket` paths already use `p88_string_eq_go`, which returns a Bool without rebuilding String pairs; qualified emitted code already has ordinary borrowed-read and owned workers for equality and `index_hash`. The borrowed readers perform no heap allocation (the equality Bool constructor is immediate), although their public adapters still have alias/refcount admission, drops and an owned fallback. Our index also hashes a complete name once and tests stored U32 masks; it does not repeat Bendc Base's character-position `Map.bit` walk at each trie node. **The reciprocal test has completed checked acquisition and measurement: the unchanged safe Bend `p88_string_eq_go`, `p98_eq_finish` and held `p88_string_eq` wrapper are copied under private names into Bendc's checker-only String.eq call sites, with native Map operations and memo fixed.** We compared this non-reconstructing portable predicate against native String.eq and the already measured Base-comparison transplant, with the same complete checker outputs; a later diagnostic can separately count equality calls and characters examined on identical names/aliases, including equal strings, early/late mismatches and Unicode. This tests whether the large portable String penalty comes from the Base comparison/reconstruction algorithm or persists for the exact predicate our compiler actually executes, before proposing any new runtime intrinsic. It neither predicts a whole-compiler win from native Strings nor treats the combined and Map-only timing arms as additively decomposable.
