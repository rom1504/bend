# What would still be needed for10×

The final candidate18 warm subtotal is120.368s against346.960s fresh.
Charging all shared preparation and unassigned native/runner time to the edit
gives124.679s. These are single same-output observations, not general speed
guarantees or an interactive editor latency measurement.

A10× build budget is about34.7s. Current machine construction alone costs13.8s
and full-byte output reconstruction5.5s. That leaves about15.4s for compilation,
versus101.0s actually measured. The31.0s frontend already exceeds that remaining
budget. No isolated backend optimization can meet this target.

## Highest-value next boundary

Carry producer-owned, exact change evidence between the already composed stages.
An unchanged raw segment should not require separate deep rediscovery by the
verifier, optimizer, registry and renderer. Start with raw lowering→verifier
body admission while keeping full context checks and the independent final
verifier. Differentially compare the proposed unchanged-body decision with the
existing exact comparator before allowing it to skip work. Invalidating
declaration headers, constructors, effects, literal addresses, readiness or
runtime identity must remain observable. A revision number alone is not proof
that every consumed dependency is unchanged.

The [source-grounded audit](../../research/phase140/next-reuse-boundary.md)
identifies the actual remaining traversals and the smallest falsifier. Do not
build another separately keyed cache at each stage. First show that one retained
fact removes a measured expensive scan and lowers complete request time.

## Frontend and output are separate obligations

Even after checker-prefix reuse, the frontend still constructs globally
freshened declarations, merged books/indexes, reachable ordering and reporting
state. Reusing those products safely requires explicit stable semantic identities
and consumed dependencies. Header equality before global freshening is not
sufficient; the current post-freshening gates must not be dropped speculatively.

For machine construction, the earlier Phase135 object cache did not beat the
monolithic build. It becomes worth revisiting only when stable owner binding
lets a small edit avoid real machine work. Reducing QBE text again is not a
substitute for that evidence. Current full output still has106MB, even though
only about2MB of changed payload is freshly rendered for the product edit.

## Make the research capability usable before claiming a development service

The native adapter consumes an immutable predeclared job list. It is useful for
controlled candidate batches, but cannot yet accept an arbitrary subsequent
editor change. A small persistent request protocol must authenticate each new
source and output, retain fixed producer/Base/runtime identity, reject failures
without losing previous successful state, and expose per-request resource/cost
receipts. This should wrap the existing Bend session state rather than implement
compiler logic in a host process. It is an explicit remaining usability step.

## Consolidation and qualification

Experimental source18 adds5,839 physical lines, including adapters and controls,
to the58,569-line qualified parent. The versioned research archive is larger
again because rejected attempts are preserved. Before promotion, consolidate the
successful interfaces and separate test-only exports without deleting evidence.
Then perform source/proof preservation, native self-reproduction, independent
focused/ordinary gates and relevant generated-code checks. Full qualification
was deliberately deferred during this bounded performance investigation.

No new mathematical correctness theorem, general10× gain, cold-build speedup,
or recursive research acceleration follows from this experiment.
