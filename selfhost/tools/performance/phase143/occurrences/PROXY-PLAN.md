# Bounded actual-body replay and native discriminator

No call-capture framework, generated-API mutation or target execution is needed
to prepare this experiment. Append `subjects-v01.bend` in the same checked API
acquisition and export `p143o_subject` in addition to the six prototype/control
exports in README. The ordinary source parser/checker and complete compiler
request remain unchanged.

## Inputs and honest scope

Use root's frozen ordinary Lexer and Map input requests. From each original
`P86PlanReady.request`, call `p143o_subject(request,name,0)` for three existing
ordinary names already in `request.names`, chosen to cover small/medium/large
compacted bodies. Keep every attempted owner and any refusal in the receipt.
Do not treat built-in/native Base primitives as unrelated application evidence.

The helper runs the exact current `nc_compact_definition` against the actual
checked request's book, and records the ordinary arity. Pin source, Base,
compiler/API receipt, logical path, selected name, `fresh=0`, returned complete
KTerm and its JSON digest. The bodies are real compiler outputs; the query
schedule below is deliberately **constructed**, not a measurement of actual
`nd_comb_fresh` caller distribution. If the existing full compiler request is
already available, add one compiler implementation body without parsing it
again solely for this microbenchmark.

For a query shaped like `nbc_select`, keep its selected body at≤32 nodes, as the
real caller does, and put large real subtrees in the argument list. A64-query
test of an entire large function body is a stress ceiling, not representative
evidence for that caller. Retain both labels rather than selecting only the
largest favorable tree.

## One shared checked-API screen

For each unchanged captured body, test arities1,4,64 under a chosen clear fresh
range, empty args and empty environment. The old executable predicate establishes
whether a chosen range is actually clear; retain misses rather than silently
discarding them. Add one actual child subtree as an argument in a separate row.
Add explicit constructed first/last-range environment collisions, preserving
the untouched actual body, and a wraparound n=MAX row. The30 fixed controls
already cover syntax collisions and malformed Var children independently.

Run original/NU_Set/range predicates on the **same** exact values, alternating
order and charging all summary construction. Require Bool agreement for every
row before collecting any timing. Record nodes/Var count and unique IDs only as
offline data diagnostics; do not call them actual dynamic production counts.
Do not pool arity1 with64 or clear with early-failure rows into one headline.

For the whole-output screen, use three isolated sources: unchanged original,
only `nd_comb_fresh` calling `p143o_summary`, and only `nd_comb_fresh` calling
`p143o_range`. The candidate wrapper must retain the original inferred signature
and attached-law interface if present. Since `p143o_original` normally calls
the original name, frozen differential fixture results must be captured before
that override, or the extracted baseline must have a renamed exact original
body. Never compare a candidate with itself after the override.

Complete ordinary Lexer/Map QBE must match the preexisting independent frozen
oracle, along with unchanged refusal outputs. Full output equality does not
itself show which runtime caller dominates. Root owns source checking and
execution; this document is a recipe, not a completed result.

## Native proxy with a bounded extraction

Reuse the exact-declaration extraction method in
`phase131/usage/prepare-fixture-v2.py`, with the selected Phase142 source pinned
instead of Phase130. Seed the dependency closure with the original query,
prototype modules, `KTerm`, `NC_Binding`, `NU_Set`, and a small workload. Exclude
control and subject-extraction modules from the native program: preparation is
performed once before fixture freezing. Bound the closure to80 declarations;
stop and simplify if it unexpectedly imports the full compiler.

Store the captured complete KTerm variants as literal fixture values using their
actual constructors/fields (`KTerm`, `KLambda`, `KLiteral`). Do not project all
variants to `tag/id/kids`, strip origins or replace names to make the benchmark
easier. A serializer is a data transport tool, not a semantic transformation.
Preserve the source/API JSON as the independent source of that literal fixture.
Each native variant differs only in one query wrapper; all three use the same
producer, compiler options, runtime and argument schedule.

For each row, an ordinary run prints its query Bool code and a repeated checksum.
The expected code comes from the frozen original query, independent of the
candidate. A timed run retains the same body across repetitions, invokes the
selected whole predicate on every iteration, and reports an `IO.now` millisecond
interval. Calibrate the original to at least100ms, share its repeat count across
all variants, cap each run and use3–5 alternating rounds. Keep arity1,4,64
separate. Checksums prevent removing the query; a native machine inspection
should confirm the intended wrappers are called and the summary is rebuilt per
iteration. Charge compile/acquisition separately from kernel timing.

Only promote a whole-compiler native candidate after native query evidence and
complete-QBE gates. A large64-query kernel gain is not a whole-build gain. The
recent20.62% cold raw occurrence-context fraction cannot be assigned entirely
to this caller without additional evidence.
