# Phase152 prepared-value contract

Preserving an authenticated nullary value through selector expansion is a plausible general compiler improvement. It must preserve **both the full packed word and its nonowning binding fact**. The narrow first experiment should change compiler behavior on unchanged source, with no function-name recognition. Phase151 establishes a causal cost in two consumed workers; it does not establish the prevalence or whole-compiler benefit of that cost.

This source audit starts at commit `461664fb48fc3311ba06d5f8f46daadf67902a1d`. No compiler/benchmark targets were run by this audit and no production source was edited. The frozen overlay and corrected finite controls were subsequently reviewed below.

**Current boundary.** [`nbc_definition`](../../selfhost/src/back/native/closed-match.bend#L109) refuses native/foreign definitions, then obtains [`nc_source_body`](../../selfhost/src/back/native/book.bend#L442). That accessor deliberately unwraps the retained same-name `NativeErasedBody` inside a `NativeStaticBody`; otherwise it erases the source normally. This preserves typed literal information required by other analyses. Do not globally change this accessor to return prepared terms.

[`p131sc_definition_body`](../../selfhost/tests/compiler/native-controls.bend#L988), included in the canonical recipe despite its controls-module location, first applies the 33-unit budget and closed-source grammar, then compacts the bounded callee and calls `nbc_select`. Admission retains a matcher, saturation/callback restrictions, at-most-once literal callback use, fresh IDs and ordered outer lets for nonliteral actuals. String and unknown literal kinds fail before compaction. Callback bodies are not included in callee compaction. [`nbc_evaluate`](../../selfhost/src/back/native/closed-match.bend#L89) distinguishes delayed literal lambdas from already evaluated actuals; changing this boundary would change effects and ownership.

[`p112s_prepare`](../../selfhost/src/back/qbe/static-data.bend#L206) separately compacts/prepares live definitions once in a fresh cached request, blocks special/effect constructors, and records `NativeStaticBody{body,[prior]}`. Its `P112StaticImage` context carries the same ordered constructor IDs/arity used by emission, plus the node index. Raw incoming `NStatic`/`NWPattern` markers are refused during preparation. `NativeImage` from the older C path is a distinct representation and must not pass QBE admission.

[`p112s_value`](../../selfhost/src/back/qbe/static-data.bend#L301) already validates the context, marker shape and constructor/node lookup before emitting a word. [`p112s_verify`](../../selfhost/src/back/qbe/static-data.bend#L272) retains program and image verification. Neither substitutes for proving that a different prepared body is equivalent to the admitted selector: once a constant becomes an ordinary `N111Const`, the verifier does not reconstruct source correspondence.

**Required invariants.**

1. Preserve incumbent source admission and fallback exactly. A failed source grammar, budget, saturation, applicability or freshness check remains `Absent`. No new acceptance of source `NStatic`, references, arbitrary primitive evaluation, fields, String literals or free variables follows from accepting a prepared marker later.
2. Reuse only a same-name fact obtained from the current request's `ns_body` index, under `P112StaticImage`, with a bounded prepared body. Prefer a bounded structural correspondence check against the already admitted compact source: every difference must be a same-name nullary `Ctr` replaced by a packed nullary `NStatic`; all other nodes, binders, children, quantities and relevant metadata remain identical. This is stronger than historical V03's same-name lookup plus marker scan and keeps source/fact mismatches out of admission.
3. Each accepted marker has tag `NStatic`, `qt=1`, `ix=0`, and no children. `p112s_constructor_ok(current_ctors,name,0)` must establish exact name, zero live arity, cid below 65536 and ordinary immutable constructor status. Reject boxed markers, one-field packed zero, nonzero payload, unknown/mismatched constructors and special runtime constructors. Preserve foreign-program fallback. Effect blocking happens in preparation; the attached ID catalogue alone is not an authenticity certificate for an arbitrary supplied marker.
4. Keep the existing freshness/substitution/evaluation machinery. A prepared leaf contains no variable, field, effect or owned payload, so substitution does not create a new capture or duplication obligation. It does not license duplicating a callback, dropping a strict actual or evaluating an unselected arm.
5. Classify only an independently authenticated accepted value as `N_Imm64`, preserving its full 64 bits. `N_W32` would truncate the tag/constructor metadata. Current [`p113_value_kind`](../../selfhost/src/back/qbe/signatures.bend#L64) sends `NStatic` through [`p113n_original_value_kind`](../../selfhost/src/back/qbe/scalar-facts.bend#L171) to opaque `N_W64`; body reuse alone therefore leaves sinks. The classifier's refusal returns the incumbent kind rather than laundering an invalid marker into a nonowning fact.
6. Leave `p112s_value`, source validation and final verifiers unchanged. A forged marker control is compiler data, not a native execution fixture. Finite tests and source reasoning remain distinct from a new code-generation theorem.

The historical V03 proposal is available with `git show 8a37e91:selfhost/tools/performance/phase131/safe-codegen/selector-static-v03.bend`; it is retired provenance, not a maintained module or qualified implementation. Its controls remain in [controls-static-v03.bend](../../selfhost/tools/performance/phase131/safe-codegen/controls-static-v03.bend). In particular, globally extending `nbc_closed` also extends the original-source precheck; a post-admission prepared-body path avoids that unnecessary widening.

**Aliases and ownership.** Nonowning propagation through exact local aliases is already available: `p113_binding` classifies the RHS; `Var` delegates to [`nk_kind`](../../selfhost/src/back/native/layout.bend#L12), preserving the first matching binding's kind. Generic, direct and boxed-product let paths all use `p113_binding`, including [`p113dl_let`](../../selfhost/src/back/qbe/direct-lower.bend#L380) and [`p113px_boxed`](../../selfhost/src/back/qbe/flat-products.bend#L616). [`p111_partition`/`p111_keep`](../../selfhost/src/back/qbe/lower.bend#L369) omit sinks/keeps only for the existing nonowning classes. `N_Imm64` retains the ordinary full-word ABI. Thus authenticated marker → binding → alias → discard needs no new alias analysis.

Finite controls should show exact word/ID preservation; one and two alias hops; unused and multiply referenced aliases; first-binding shadowing; missing aliases; opaque and owned values retaining their old classification/keep/sink behavior. Do not infer an interprocedural return fact or a mixed-branch join from one nonowning arm. Broadening to every static box may ultimately be sound because static storage is immortal, but it adds image-offset/child provenance obligations and is unnecessary for the nullary experiment.

Use unchanged source bytes, runtime and machine policy for each compiler pair. Historical Phase131's 2.46× lookup/summary result introduced the scalar admission already present today; it is not this experiment's baseline. Its [larger transfer manifest](../../selfhost/tools/performance/phase131/usage/final-transfer-cases.json) contains retired projection/compiler-uses source paths; do not launch it wholesale without explicit recovery and hash checking. The two small transfer sources above are present and their hashes were independently recomputed.

For the lexer, compare both `reference` and `candidate` modes under both compilers so source and compiler effects remain separate. Retain exact token equality, not just timing hashes. Phase150's scalar probe acquired in roughly 8.6 seconds and lexed the frozen 3.07 MB input in roughly one second; these are historical budget guides. Its existing full-parser acquisition costs roughly 46 seconds per image and runtime roughly 28–31 seconds, so repeat the complete parser/15 graph boundary only after emitted call removal and a useful lexer transfer justify it. The prior 4.43× lexer/9.62% parser gains belong to the source change; Phase152 must measure any additional compiler gain.

**Broader nullary lowering.** A book-aware lowering rule could also turn newly introduced ordinary nullary `Ctr`/`NCtr` values into the existing authenticated packed representation, covering other expansions without a new IR. It would need the same exact constructor/arity/foreign rules and nonowning binding update across generic, direct and product paths. Merely adding a count-zero shortcut to [`p114p_constructor`](../../selfhost/src/back/qbe/region-emission.bend#L37) is incomplete: that helper lacks the request book and would leave opaque binding sinks. Preserve malformed-arity refusal and special-constructor semantics; do not generalize from cid 0 or the absence of fields alone. Treat this as a separate hypothesis after identifying residual emitted sites, not an extra change in the first overlay.

**Profitability and stopping evidence.** First require exact controls/outputs and disappearance of both calls in the consumed Phase151 and safe-kernel paths. Then compare complete generated-program regions and charge candidate compilation on the same small requests, including rejected/unrelated cases. Added fact lookups, correspondence walks and per-binding authentication execute inside the compiler and can outweigh downstream gains. A cheap tag gate before classification work and bounded scans only after existing selector admission avoid whole-book work per call. If only a synthetic dispatch improves, if sinks remain, or if request overhead dominates the transfer, stop before a whole-image build. General compiler and cold-build gains remain hypotheses until an acquired candidate compiler executes matched ordinary requests; static callsite counts are not hotness or a speedup estimate.

**Independent overlay/control review.** The [91-line overlay](../../selfhost/tests/phase152/prepared-constants.bend) is 5,205 bytes, SHA256 `41a292734587772e9da3ed1d0ae59b2d7fc15cd7ac964b9251a81233c9399a36`. It replaces only `nbc_definition` and `p113_value_kind`. I found no semantic defect in the inspected change: it implements the post-admission structural correspondence above, keeps `nbc_closed` unchanged, and calls the same freshening and `nbc_filled` machinery. Freshening/substitution preserve an `NStatic` leaf's identity and payload. The previous value classifier is copied exactly modulo whitespace into `p152c_prior_kind`; all nonmarker inputs retain it. Nullary marker authentication is stricter than the existing `p112s_value` contract. Alias propagation consequently requires no additional production changes.

The corrected [control module](../../selfhost/tests/phase152/prepared-constants-controls.bend), 10,078 bytes, SHA256 `76158765fade8e4a35c69f0843b4aba5772d3d157d4e690a139a498561d2a995`, has 66 rows: the unchanged 19 selector rows plus 15 nullary, eight correspondence, 12 context and 12 ownership rows. Positive prepared bodies use the actual `p112s_term` factory; the surrounding contexts are synthetic compiler data. New rows cover cid bounds, unknown/special/foreign catalogues, malformed markers, source/body/metadata disagreement, absent/legacy contexts, retained-prior identity, budget/freshness/native/foreign refusal, full-word emission, alias shadowing/missing/owned preservation and removal of the nonowning keep/sink. This is a review of the actual assertions; execution status belongs to the coordinator's fresh receipt.

Two fixture defects were found and corrected during independent review, with the overlay unchanged. Setting the builtin flag on a definition named `probe` does not make it an intrinsic; the refusal control now uses `U32.add` and first asserts `nc_native_def`. The narrow correspondence checker rejects `KLiteral`, while a complete expanded caller deliberately retains literal actuals/callbacks; its order control now compacts both compared results as compiler data. Neither correction widens production admission.

I also independently read the retained [baseline dispatch SSA](../../selfhost/build/phase152/baseline-dispatch01/program.ssa) and [candidate dispatch SSA](../../selfhost/build/phase152/candidate-dispatch01/program.ssa). The exact `p113d` workers for `$direct.p151p_roles_select` and `$direct.p151p_binary_select` change from 22/22 and 20/20 constructor/sink callsites to zero/zero. Both consumed loops change from two/two to zero/zero. This establishes more general emitted removal than Phase151's two-body text patch, which deliberately left common-loop calls untouched. It remains structural evidence, separate from native runtime, transfer and compiler-cost results.
