## Fast loop and next experiments

Use the [Phase39 portable guide](../selfhost/tools/performance/phase39/README.md):
previous/current/TS bundles, explicit Phase37 catalog, selected20/60/300/600-second
ceilings. Portable fast5points passed in17.444seconds. Checked05 build plus36
focused probes took42.295seconds. Full performance and conformance are release
checks, not the edit loop. Fixed timing windows execute more calls when programs
speed up; the full suite does not automatically become shorter.

1. Keep an unchanged-byte negative control in every timing experiment.
2. Test one first-order list or lexer component, retaining materialized values
   and full semantic oracles. List is not evidence for callback specialization.
3. Extend remaining tree flow only after independent shapes validate it; retain
   generic fallback and demand/alias/stack contracts.
4. Probe allocation within the existing numeric entry guard. Numeric already
   has one outer scope; do not claim another amortization opportunity or omit
   required host checks.
5. Isolate a Map/String component before any broad runtime rewrite. Fusion needs
   a future direct-unfused comparator, not the current generic denominator.

Former holdouts are exposed. Freeze new distributions before future selection.
Root alone runs heavy jobs, serial CPU3, Node24.18, heap≤1GiB, treeRSS≤2GiB,
available memory≥2GiB, fresh output paths and deadlines. Agents author/review.
