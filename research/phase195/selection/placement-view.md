# Certified selection before placement

Hypothesis: direct x86 still colors source predicate/copy diamonds after the final selector has proved that their intermediate values need not exist. A conservative analysis view of the selected operation should admit useful values and reduce interference before allocation, while preserving the exact original emitter and all observable writes.

The Phase194 final editdist `$product.row` positive loop has 77 instructions and 20 explicit RBP memory accesses. Its retained QBE counterpart has 44 instructions and four such accesses; C's `NF.dp.row` inner loop has 26 instructions and no explicit stack accesses. [Exact binary inputs](machine-inputs.json) and bounded disassemblies are adjacent. These are straight positive-path counts, not sampled attribution or speed estimates. The C path includes specialization to a fixed 256-column loop and a different wrapper/representation; its static count is not an apples-to-apples instruction-selection counterfactual. All paths perform the same visible cell recurrence at the catalog point.

Current direct x86 materializes each certified minimum into reserved scratch registers, then publishes into original homes; selected result aliases still spill. The loop also spills its updated count/index. Nine allocatable general registers and a 32-name candidate limit remain unchanged. Projection may improve candidate admission/interference but cannot promise to remove true simultaneous-value pressure.

The isolated candidate files are `selfhost/tests/phase195/selection/select-placement.bend` and `select-placement-hook.bend`. Only `x191_placement` is replaced, using the existing placement-view convention already used for selected addressing. `x195_sp_enabled()` controls the new path. A predicate plan is projected only when both `x194_ps_pick` and the original whole-function `x194_ps_allowed` certificate succeed; these are the same gates as actual emission. Rejections return through the exact existing shared-address/ordinary placement path. Matchers remain bounded; no extra whole-function analysis walk is introduced.

The projected event order is:

1. Read both comparison operands in a synthetic Bin whose destination is reserved and unallocatable. This models the actual CMP; its flags have no register home.
2. Read both selected values before writing the first selected destination. A synthetic OR expresses this interference event; its computed arithmetic value is never executed or inspected.
3. Write every further original selected destination through the same copy chain. This preserves original writes and enough liveness to conservatively cover publication. Inversion does not change the set/order of register reads needed for the snapshot.

Projection never reaches the emitter. Frame slots are built from original statements; original facts, control structure, selected publication and final machine selection remain authoritative. Setup/parameters and ordinary branches retain the previous placement behavior. The scratch-register exclusion stays intact, so input snapshots cannot alias scratch homes. Reading both choices is essential: modeling only the taken arm would incorrectly permit one choice to be overwritten before actual snapshot. Removing a destination write would likewise break alias/interference safety. Comparison width and selected width are independent.

The reserved synthetic name follows the established `__x181` internal-name exclusion and is neither allocated nor emitted. A comparison input may share a destination home only after CMP has consumed it; both selected inputs remain live until the first modeled write. All selected destination writes remain represented, including dead writes and chains. Refusal/fallback allocation still receives this conservative view, not a partially transformed executable body.

Qualification supplied to the root lane: `controls.bend`, independent `controls.c`, `driver.mjs`. Eight ordinary-selector machine functions cover all four compare/select U32/U64 width combinations, inversion, destinations overwriting both inputs, preservation of old input snapshots, and twelve arithmetic values live across the selection. Eleven-by-eleven full-word edge inputs produce 968 observations per route. Nine data checks verify removed predicate reads and external-copy refusal. Reuse the Phase194 predicate-controls-v3 and stress-v2 controls for all signed/unsigned operators, repeated definitions, source overwrite refusal, protected setup/params, empty/scalar Ifs and fuel boundaries. These are finite checks, not a proof; they must pass before any performance interpretation.

API exports: ordinary seven compiler roots plus `p195sp_controls`, `p195sp_emit`. Driver requires `x188_many`, `x188_render`, `x188_assemble` and standard explicit API/assets/source-manifest arguments. Authoring ran only `node --check` and offline source/disassembly inspection. Root owns checked API acquisition, all target execution and timings. No maintained file was edited.

Falsification: if actual row spills/candidate placement are unchanged, this view is not the limiting factor; retain that negative and inspect physical CMP/CMOV operand/publication selection next. If spills drop but runtime does not, do not infer speed from static counts. A separate current limitation is the nine-register pool and always-reserved scratch contracts; widening that pool requires a new clobber/liveness contract, not a numeric color-count change.
