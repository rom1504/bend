# First broad measurement and runtime experiments

The Phase197 source acquired a native compiler that emitted all 45 ordinary direct-x86 programs correctly. On fresh measurements on CPU3, its geometric runtime ratio to mature self-hosted Bend C was **1.87145×**, versus **1.89758×** for the preceding Phase195 compiler in the same comparison. One zero-work case is correctness-only. Mean positive log-slowdown went from 0.77077 to 0.75447. Both versions had 36 of 44 programs above 1.1× and 26 above 2×. The candidate reduced fixed-catalog time from 23.82 to 23.53 s versus 10.51 s for C. The 30 timed held-out cases improved 0.48% geometrically. Edit distance and local-pair improved about 14%. In the paired repeat local-fold-128 became 6.0% slower with all six pairs in the same direction. A 13.7% apparent list-pipeline regression in the first measurement occurred with byte-identical object code and linked sections; the repeat measured 0.6%. Lexer-6's initial 7.2% regression also failed to repeat. These controls are why a consistent code mechanism and repeated timings matter. ## What changes when the generated code is held fixed?

Recompiling the shared runtime at O3 produced mixed effects. Keeping the incumbent compiler and -O2 flags while separating raw owned constructors from packed/shared slow paths reduced runtime on four distinct inputs. Compared to the original, tree sort took 0.917×, BST-64 0.875×, Map churn-128 0.925× and expression-128 0.915×. Lexer, RLE and scalar fold were close to unchanged. All seven original executable identities reproduced before the comparison. Each variant passed the mature C output checks for the ordinary and an additional input before timing. The complete screen took 61.8 seconds. [Per-round values and object identities](../../research/phase198/runtime/screen01-summary.json)

The pilot binds the constructor arity/sealing information once per process and splits out a small free-list hit and raw take. A separate experiment tests whether a split using live descriptor reads has the same benefit, and whether the gain transfers across the full suite. The first seven points do not establish a new global score. [Experiment](../../research/phase198/runtime/plan.md)

## Five compiler transformations in the same native image

The combined x86 source passed independent checking and its N1 built all 45 complete programs correctly in 106.32 seconds. The four-role head-to-head kept the same frozen 45 Bend inputs and the same mature Bend C programs. The incumbent measured **1.87495× C**, the new compiler with the original runtime **1.57487×**, and the identical new program objects with the live-descriptor constructor runtime **1.54663×**. Four rotated rounds produced 720 measured observations and 616 calibration pilots. Fifteen programs had within-role dispersion above 10%. On the original fixed batch, the three corresponding x86 times were 22.90, 20.11 and 19.72 seconds versus 10.31 seconds for C. No fixed-orbit acceleration is present in this checkpoint. [Full runtime results and raw evidence](../../research/phase198/runtime-broad/portfolio-summary.md)

The compiler rules nearly halved the geometric runtime of the studied semantic families (0.5163× prior x86). The other families together took 0.9879×. The positive log-slowdown to C decreased from 0.7503 to 0.6466 with the live runtime, and the count above twice C time fell from 25 to 21. This separation helps decide whether to expand a useful optimizer or look for a different cause of the remaining deficit. [Partition and family results](portfolio03-breadth.json)
