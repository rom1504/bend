# Residual cycle snapshots on parallel Again assignments

Actual table-v3 ray `product.nearest` has a 12-word Again vector. One edge is handled by the original acyclic scheduler; the other edge's R13↔R14 cycle makes that scheduler refuse the entire plan. Its generated block at0x40a8f8–0x40aa57 executes72 instructions to snapshot and reload all twelve words, including unchanged loop invariants. The raw Again vector and physical homes identify two residual register-cycle words, two other changing stack words, and eight unchanged homes. Exact witness: `ray-residual-cycle-witness.json`, with binary pins in `table-machine-metrics.json`. The branch's dynamic frequency is not established by these static counts.

## Smallest bounded change

`parallel-cycle-v1.bend` and its hook replace only `x186_p_ready`. Original `x186_parallel` keeps its64-word size limit and exact zip validation: unique destination homes, valid ordinary full-word registers/stack slots, source validation, reserved state rule. Original physical-home self elimination and ready-move selection are reused. Each acyclic move still uses `x190_move` in the same order.

If no ready move remains, the candidate snapshots only the residual moves into the existing private `__x181_tail` bank, then publishes only those destinations. The instructions reproduce the original fallback's full64-bit load/store sequence, using R10/R11 for each snapshot and RAX for each immediate publication. No scratch register carries a value across a helper or another scheduled move. No extra register, frame slot, type, source IR transformation, or whole-function pass is introduced. The final Again jump remains the original caller's responsibility.

The bank must be an existing aligned buffer with enough capacity for all residual words, contained in the frame. Residual source/destination stack words must not overlap it. Refusal still returns None and the original full-vector fallback remains authoritative. Disabled toggle invokes the exact old schedule.

Correctness invariant: a scheduled destination is not read by any remaining move. Therefore the scheduled prefix cannot destroy a residual source; residual sources still denote their original simultaneous-assignment values. Snapshotting all residual sources before any residual write preserves those values even for cycles/fanout. Original full-word self moves can be omitted because this API has no U32 write semantics; any preceding U32 instruction remains emitted and must still zero the upper half. XMM homes are outside this ordinary word-home API; floating code must publish canonical ordinary words before Again as before.

The ray witness predicts a much smaller backedge block (roughly16 instructions rather than72 for these homes: four stack-copy instructions plus two six-instruction snapshot/publications). This is an offline code-shape prediction, not a runtime forecast; allocation changes can alter the home graph. Exact emitted candidate disassembly and balanced timing are required.

## Independent review and v2

Independent p192_registers review found no valid-frame semantic blocker. It noted that v1's explicit bank guard did not exclude a fabricated tail bank overlapping the saved-register area, even though canonical frame construction guarantees that exclusion. Prefer versioned **parallel-cycle-v2.bend**, hook-v2, controls-v2 and driver-v2 (C observer remainsv1). V2 additionally requires `da(bank)-dx(bank)>=40` after the non-underflow check and adds `saved-area-bank-refused` for a fabricated32/16 bank. The unchanged residual nonoverlap guard is not a complete malformed-frame validator; nonoverlap with unrelated frame objects still relies on canonical checked frame construction. The v2 reference/delimiter/matching audit is pinned separately in `parallel-cycle-preflight-v2.json`. Root-owned sourcecheck and machine gates remain pending.
