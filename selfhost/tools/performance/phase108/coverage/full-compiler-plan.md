# Full compiler qualification plan

[`full-compiler-plan.json`](full-compiler-plan.json) is prepared data only; no
compiler or generated target was executed to prepare it. Its source, runtime,
assets, methods and historical evidence paths were checked against current file
hashes. Q0's binary and successful acquisition receipts are deliberately bound
only after root finishes its build.

The six prepared-Base sources are exactly the six Phase105 representative
products already selected from broad45: lexer, active ray geometry, closures,
Unicode text, Map churn and numeric recurrence. Their existing Phase88 wrapper
paths and complete-output receipts are reused without source edits. The plan
adds one invalid-type source, one live-Base numeric request, one five-request
lexer process, and the complete portable compiler source in two fresh Q0
processes. It needs at most 20 compiler processes and 22 C outputs; an already
complete, exactly authenticated `full-emit01` can supply the trusted full-self
product and avoid one process. No generated-program build/run is required for
this compiler-output gate.

The source/runtime binding is `portable-source02/manifest.json`: compiler source
`8b1a72a4…` and runtime `d56fe7a0…`. Both producer roles receive that same runtime
and its five retained parts, the same Base/effects and the same source path.
Only the candidate executable changes. A changed runtime or source requires a
new plan version, not substitution under this frozen plan.

Use `native_args` from the selected native launcher, replacing the binary for Q0
and the runtime positional argument for both roles. The JSON includes the exact
argv template and cache suffix. `calls=5` belongs to that compiler entry; the
current `phase108/run.py emit` CLI does not expose a `--calls` flag. Live Base
means omitting both cache arguments, rather than merely relabelling a prepared
request. All invocations remain root-owned, serial, guarded on CPU3.

The trusted old compiler lacks the four transport metadata definitions. Apply
the fixed bridge once, require Q0's four definitions to have exactly the same
bytes, then compare complete C with only those four complete definition lines
removed. Nothing else may normalize: runtime, names, paths, whitespace, literals,
ordering and every generated function body remain part of the comparison.
Unnormalized old-plus-bridge versus Q0 equality is also recorded and expected.
Full-self repetition compares the two Q0 files without normalization as well.

Keep raw stdout/stderr and both child/guard statuses, including expected failures.
Separate the existing anchored timing telemetry before comparing every remaining
diagnostic byte; clocks are not an output oracle. For five requests, require
ordinals 1–5 and check all five outputs plus the one final verdict: the actual
`p86_request_finished` prints the verdict only when the last request completes.
For invalid input, require
nonzero rejection and no complete or partial C product. Every failure remains
recorded under its role and stage, rather than being counted as a missing sample.

Full-self output equality establishes deterministic compilation of the whole
frozen source by Q0. It does not establish a rebuilt Q1 image or a Q1/Q2 fixed
point. Existing broad45 runtime expectations in the JSON are optional later
controls and do not enlarge this plan's compiler-output claim.
