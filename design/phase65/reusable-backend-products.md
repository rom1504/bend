Authorized October 8, 2026 from `49431ba`. The compiler remains implemented in
Bend. This phase targets compilation time while retaining the tested emitted
programs' behavior and performance. No upstream migration or PR comment.

from the same-campaign baseline's 1.41737× (9.025% less time); imports plus

## H1: one resolved backend product

The existing JDPlan already lowers each retained definition once. The new
question is the work before and around that lowering: annotation normalizes
types but retains original type expressions, call analysis walks bodies, lowering
reconstructs decisions, and layout validation walks them again. Retain specific
constructor, telescope, layout and call facts at their original demand point in
one immutable owning context. Begin with a consumer whose whole traversal or
expensive derivation can actually disappear.

Do not repeat the rejected annotation-child guards or typed-spine experiment.
Fewer queries alone previously made request time worse. Annotation's checked
book and the selected annotated overlay are distinct: facts require the same
context or an explicit equivalence condition. Preserve erased demand, dependent
substitution, source origins, fuel/refusal boundaries and diagnostic ordering.

Planning range: 8–20% whole compilation if the new attribution supports it.
First discriminator 45–90 minutes; a qualified scoped implementation 3–6 hours.

The first discriminator retained the WNF head already computed by annotation.
Its 16 focused cases passed, but the B1 screen changed compilation by only
−0.23%, below noise. Reject that candidate without a B2 build or costly public/
private annotation redesign. Retaining a cheap head is not equivalent to
removing a typed traversal; any successor must identify a larger concrete unit.

## H2: reusable closed Base backend information

Prepared Base already saves frontend/checker work. It does not yet persist the
backend products rebuilt by each request. Measure eligible Base definitions
separately from user definitions during annotation, call analysis, layout and
lowering. Prototype retained annotated bodies, call rows or signature/layout
facts for a closed immutable dependency set. Recompute global SCC bookkeeping
initially; cached final text requires additional order/label/bounce proofs.

Eligibility must bind actual canonical dependencies, native policy, binder IDs,
compiler/source/Base identities and the selected alias overlay. Source-dependent
specializations, prefix collisions and unsupported contexts use the old path.
Incoming source edges do not permit assuming global component labels stay fixed.
Cached work must still charge existing budgets and preserve first refusals.
Preparation and artifact validation costs remain explicit. Compiler algorithms
stay in Bend; JS may transport facts but cannot invent their semantic validity.

Planning range: 5–15% whole compilation, possibly 10–25% on Base-heavy inputs.
First discriminator 45–90 minutes; annotation/call facts 2–4 hours, extending to
closed component output 4–8 hours if justified. These gains overlap H1.

The selected experiment is narrower than that initial range: a separate optional
artifact of checked Base annotations with at least 64 body terms. It contains
12 products (437,464 bytes plus 520 key bytes); seven qualify on Map in the
initial census, none on Numeric/Lexer. The four Bend APIs own preparation,
wanted selection, current prefix admission and retained-annotation consumption.
The host transports validated products only on the actual successful owned-world
route, binding API/Base/source/ABI and both parent graph identities. It reads
keys before the heavy body, preserves current stops and ordinary fallbacks, and
does not create the sidecar during normal inspection. World3 remains unchanged.

State08 strict36/export99 is ready. Required next gates are actual cached-product
activation, full annotation/module equality, no-hit unread-body behavior,
malformed/stale/admission fallbacks, and a fresh-process net latency comparison
that pins the optional sidecar. The warmed artifact discriminator does not
predict fresh request savings. Retained call rows or final text remain later,
separately proved extensions; singleton SCCs alone do not authorize text reuse.

## H3: avoid rebuilding unchanged composite terms

Leaf reuse, delayed substitutions and the graph evaluator already exist. Count
composite reconstruction and semantic no-change cases before proposing more
sharing. Reuse a composite only where the original beta/substitution behavior,
freshness, origins and exact result are preserved. A term without the substituted
variable may still require beta work; absence alone is not a proof.

Planning range: 5–15%, conditional on a substantial measured avoidable share.
First discriminator 60–90 minutes; full scoped change 4–8 hours. Reject when
guards/indexes cost more than rebuilding or when identity-sensitive consumers
invalidate the ownership premise.

## H4: finish output metadata propagation

JDText exists, but some JDOrdered/raw output is still scanned character by
character to rediscover references and uses. Carry exact metadata through the
producer/consumer boundary where it is already known. Preserve quoted strings,
escaped names, marker boundaries, ordering and refusal budgets. Prefer fewer
scans and simpler code to introducing another output IR.

Planning range: 2–6%; 30–45 minute first discriminator and 1–3 hour scoped change.
This can supplement a larger semantic-work gain, not independently close parity.

## H6: stable static units for frame4 decoding

The host may validate and materialize compiler data; it must not implement Bend
compiler algorithms. The first patch merely moved unused field loads inside
cases and regressed first decode (62.33 → 65.29 ms), so it is rejected despite
later warm-call improvements.

The successor splits the original twelve tag bodies into static functions,
keeping schema, validation, object shapes and sharing unchanged. All 87 domain
controls and eight fresh-process workers pass; first complete decode changes
64.47 → 27.13 ms. This isolated clock excludes imports/file reading. A first
same-image genuine-B2 request screen preserves all eight outputs: Numeric
255.68 → 205.26 ms, while Map is noisy and essentially unchanged. Four-source
confirmation is pending. No production or broad compiler-speed claim follows
from the microbenchmark alone.

If whole-request gains survive, integrate the helper separately from H2's
semantic product cache so each effect remains attributable, then qualify the
selected combination. Preserve the rejected load-only patch and avoid adding
extra V8 profiling before the clean discriminator answers the useful question.

## Execution and rejection gates

1. Register/freeze methods and verify the installed baseline, then run the four
   source cost survey. Investigators prepare isolated patches and controls in
   parallel; only root integrates a reviewed production patch.
2. Start with exact enclosing-result or full-module differential controls,
   then a strict checked B1 and a short balanced comparison. Larger changes or
   uncertain B1 effects get an early genuine-B2 screen, not repeated microloops.
3. Keep separate changes separate until a material benefit survives clean
   request measurement. A/A showed several-percent apparent differences in
   Phase64; do not multiply tiny improvements from separate campaigns.
4. Qualify the selected combination once: genuine B2, own-source type acceptance
   with expected unsafe-proof refusal, exact B2/B3, checked/B2 semantics,
   native/runtime controls, full23/45 artifact equality and balanced207 timing.
   Changed generated modules/runtime require fresh program-speed measurement.
5. Preserve the prior release, install only an admitted candidate, verify
   ordinary/relocated CLI and helper integrity, document size/complexity, archive
   exact raw evidence, commit and push. Do not promote a regression to finish.

Each hypothesis gets its own file. Quantitative forecasts are conditional and
may fail; record rejection rather than expanding an unpromising implementation.
The first useful milestone is a measured cost budget and one substantial removed
traversal, not a large new framework. Stop a lane's implementation when its
maximum plausible whole-request benefit does not justify the added complexity.

## Resource and time policy

Root alone executes compiler/Node targets, serially on CPU3: 1 GiB heap, 4 MiB
stack, 2 GiB process-tree RSS and 4 GiB available-memory floor, under one guard.
Agents use CPU0 for disjoint source, tooling, data and review. Consumed tools and
receipts are immutable; corrections use explicit successors and fresh outputs.
Broad timing takes roughly four minutes after preparation. Reuse completed
gates bound to identical inputs, and do not repeat full qualification per edit.

Record start/finish and closed guard occupancy without calling uncovered wall
time idle. Give progress updates about the findings and next discriminator.
Source and evidence checkpoints are committed/pushed during the campaign.

## Research and existing negative evidence

not a claimed speed multiplier. The local compiler research collection and

comparisons. Phase63/64 rejections constrain new experiments: broad WNF memo,
