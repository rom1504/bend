# P61-004 — Keep architectural iteration short without shrinking acceptance

Registered 2026-10-07 before Phase61 outcomes. Owner: root/qualification owner;
research documentation records decisions; independent method review required.
Status: prior measured subset available; no Phase61 target result; decision reuse
its method with truthful new image bindings.

**Hypothesis:** Cheap checked/focused rejection followed by the measured contrasting
request subset finds invalid or unhelpful architectural changes before expensive
self-image/full-corpus qualification. This is development-loop efficiency, not an
algorithmic compiler speedup or a universal performance guarantee.

**Invariant:** The candidate remains compiler source in Bend, emitted images retain
the real checked parent/emission lineage, and no target or failed sample disappears.
Numeric recurrence+MapSet is the first-only rejection group; add active raytrace
with two rotated rounds for confirmation. Lexer/Evening remain held-out, and all 23
sources remain the eventual population gate. New mechanisms can add a concrete
falsifier without silently redefining the fixed acceptance denominator.

**Prior measurements:** [Phase60 fast loop](../../implementation/phase60/fast-loop.md)
records 17.528899 s / four workers and 49.509634 s / 12 workers for full CLI commands,
excluding reusable preparation/image generation. Those are measured host costs,
not budgets promised for a changed compiler. Phase5's checked B1 remains an
available genuine development route; select faster B1/B2 experimentally with
truthful stage/provenance, not by assuming old latency rankings still hold.
[Emitted-B2 installation follow-up](../../implementation/phase58/b2-installation-followup.md)
is deferred: a private qualified image does not authorize default installation
or a fabricated checked sidecar.

**Cheapest disproof:** Track source edit→checked image→focused semantic gate→screen
elapsed/process intervals and failures separately from target latency. A slow
candidate, incomplete gate or unstable output refuses advancement. Preparation,
profiling, first/later requests and compilation versus program execution stay
separate. Root serializes targets under one process-tree guard and unchanged
resource limits; no parallel target timing with analysis-heavy jobs.

At a surviving architectural candidate, run broad 23/45 correctness plus the
applicable semantic, emitted B2/self-check/fixed-point, native and release gates.
Only root admits promotion after measured benefit and review. New raw belongs to
Phase61; preserve closed 58–60, installed release and103 unrelated files. This
record authorizes no extra target beyond the root's existing campaign schedule.
