# P185-005: Admit verified local-continuation frame buffers

Status: bounded source prototype; measurement and machine gates pending.

The ordinary `p114t_frame` expansion already copies captures and updates the
runtime stack pointer. Baseline Phase184 QBE output contains no residual
frame helper calls in map128, two in tree-bitonic, and one in raytrace. Every
remaining call uses `p114h_case_0_local_scratch`, a buffer created after the
original verifier by the local-continuation renderer. Raytrace's observed
frame-helper sample share is approximately 7%, so deleting that entire share
would bound a speedup at about 1.075x. The copied words and stack updates
remain; no such measured speedup is claimed. Capability-4 register clearing
was already eliminated and is unrelated to this candidate.

`continuation-frames.bend` provides a scoped adapter at the two frame-list
consumers in `p114h_stmt`. It receives the currently admitted case's buffer,
requires that exact buffer in the original call, and recognizes only the
eight concrete names generated by `p114h_buffers`. Literal counts 0 through
8, a real symbolic FID below the runtime-ID reserve, exact state identity,
and U64 result are required. All other shapes keep the original renderer.
The global `p114t_buffer` policy is unchanged: a matching-looking name alone
does not admit a frame outside this scoped entry.

Independent existing obligations are retained. `p111v_counted_call` proves
the symbolic continuation has positive incoming width, captures plus incoming
equals its arity, and the source buffer has capacity. `p114h_plan` and its
case closure require clean source/case namespaces; `p114h_clean_segment`
excludes user `p114h_` and `p114r_` locals. Closure is bounded to eight cases,
and `p114h_buffers` allocates each case's 2048-byte scratch before entry.
Renaming retains the verified frame's original FID, literal count and
ordered stores. The residual raytrace call is visibly followed by the local
descent depth increment, matching one of the two scoped hook sites.

The adapter reuses `p114t_frame` verbatim under the same selected CPU ABI
11102 qualification boundary as existing state accessors: load `state.sp`
at offset 16, copy each capture in source-load/destination-store order, store
the continuation FID, advance `state.sp`, and produce result zero. There are
no runtime source changes, descriptor-policy changes, or new allocator or
reference-count operations. Current direct x86 does not instantiate P114H
plans; its ordinary frames already use the existing expansion. The shared
structured template has independent machine controls for both targets.

`frame-controls.bend` includes 28 structural and original-verifier rows.
`frame-oracle.c` checks 140 observations per target over seven wrappers,
including every state byte, every stack and separate-capture word, zero and
eight captures, the last valid case, refused contexts, and three overlapping
capture layouts. Its single slow helper is an isolated fallback observer,
not a runtime replacement in generated programs. The benchmark mechanism
check must show the residual frame calls disappear without changing complete
outputs before the rotated raytrace measurement can justify retention.
