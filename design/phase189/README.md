# Phase189: qualify and install direct-object x86 defaults

The user authorized direct ELF objects as the default for x86 executable builds
and `--run`, retaining explicit assembly and the previous installed release.
Parent is Phase188, commit2c5b759. Compiler source is unchanged in this phase.

## Qualification and honest generation identities

Reuse the independently checked Phase188 source and actual QBE-built native N1
and object-built N2. Run N2 to compile the identical source into N3, requiring
complete object-byte equality with the object that produced N2. Preserve the
real stages: do not relabel N1 as N0 or invent an unexecuted generation.
Qualify the selected N2 through the current64 finite catalog and10 runtime cases
using direct objects. Retain Phase188's45-case machine identity and semantic
controls. These finite gates and self-reproduction are not a compiler proof.

Extend release admission with an explicit object-lineage variant that verifies
the same source, image bindings, Base, runtime, actual producer chain, and exact
reproduction. Keep installed JS/C/QBE/native-CLI components and their historical
source identities intact; the x86 component owns its independently authenticated
source profile. Never rebind old artifacts to newly assembled source.

## Default interfaces

Public x86 executables and --run select object emission; .s output stays assembly.
The maintained native builder defaults x86 executable construction to objects,
with explicit --emit assembly for comparison and assembly IR retaining its
meaning. Raw request emission remains assembly unless explicitly requested.
Other targets, ownership, runtime policy, stdout/argv/status and no-overwrite
rules remain unchanged. Benchmark/profiler adapters must either select an
explicit format or consume the actual recorded output; do not silently parse
objects as text.
