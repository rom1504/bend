# P155-018 — Fuse identifier syntax and exact reserved-word classification into one scalar scan

Status: **win-screen**. [Overall report](../../implementation/phase155/README.md).

Family: [frontend](frontend/README.md).

Native new/old ratio: **0.362207×**; 63.78% less time.
Common count: 4096; receipt `selfhost/build/phase155/screen01/report.json`.
Three alternating paired rounds in the same native image; whole child time retained.

**whatWorkDisappears:** Repeated first/tail projections and dot lookahead in f_name_chars, plus up to16 sequential String equality calls in f_reserved. Candidate validates identifier segments and accumulates exact first-six ASCII bytes in two U32 lanes during one scan; capped length and exact byte keys preserve keyword case and avoid hash collision assumptions.

**scope:** Actual maintained Phase150 scalar lexer plus complete maintained name-validation consumer, applied to every token of fresh valid Bend source per repetition. This is not the complete grammar parser, loader, checker or a whole-compiler request.

**limitations:** No native timing or check has run for this source yet. Finite lexical/name controls do not qualify the full parse consumer. Some callers already test f_reserved before f_valid_name, so replacing only this predicate does not remove all duplicate classification. ASCII syntax is intentional and matches the existing predicate; Unicode remains rejected as a name. A full parser comparison and normal qualification would still be required before integration.

**promotionGate:** Reject on any control/old-new mismatch. Even a large local gain needs measured transfer through the complete parser, because Phase150 already reduced lexical work and remaining parse costs are distributed. Never multiply this proxy ratio by the whole parse stage.

This screen is not production qualification or a whole-compiler speed claim. See the
frozen specification and independent audit before choosing a transfer experiment.
