Independent values use original Math.fround at each primitive operation and
Object.is for NaN/signed-zero distinction. Input grid includes ±0, ±smallest
subnormal, ±maxfinite, ordinary canonical F32, noncanonical1/3 and ±Inf/NaN.
Normal recurrence, subnormal accumulation, overflow, signed-zero output and
runtime division-by-zero results are distinct checks. Controller serialization
records value class and bits without JSON silently replacing infinities/NaNs.

Boundary scenarios import a fresh module per role/case. A temporary prototype
getFloat32 hook retains that module's actual shared view through public_literal,
then restores the hook before the selected computation. Retained view checks
its last literal write; zero-trip keeps its previous word unchanged. Own/prototype
getFloat32, own setUint32 and accessor replacement compare full events, values,
errors and sentinel identity. Reentry, Math.fround throw/reentry, Math/Number
getters and post-import global DataView replacement remain separate observations.
Transferring the retained buffer checks matching detached-view TypeError, with no
later reuse of that irreversible module state.

The candidate's complete G assignment ASTs must contain the finite literal marker;
each marked setUint32 must have exact offset0/little-endian arguments and finite
exponent. Counter-only instrumentation increments before each marked write at the
same literal expression. One-step roots must execute selected writes; zero-step
roots must not. Own-view hook changes must leave the selected root's finite
counter at zero while matching original-module boundary behavior.

These counters establish actual executed literal lowering, not root-marker
presence. The counter clone is not a public host-introspection or performance
subject. Module/receipt/catalog/source/upstream/Node identities are pinned and
rehash-checked. Every passed CLI module must equal its receipt output path/hash.

Important refusal limit: the source frontend rejects exponent255 compact F32
literals. Source runtime Inf/NaN is tested, and transformed literal exponents
are statically checked, but this controller does not claim an executed compiler
plan test for a synthesized exponent255 KLiteral. The implementation owner/root
can expose the checked API's j_private_float_plan/code/finite through a separate
diagnostic derivative for that lower-level refusal proof, without changing the
production ABI. Source controls alone do not establish every NaN payload or
all possible compiler-input bit patterns.
