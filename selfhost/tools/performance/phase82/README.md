# Phase82 methods and evidence

[Design](../../../../design/phase82/fixed-work-and-native-products.md) ·
[report](../../../../implementation/phase82/README.md).

Selected compiler04 changes only native compiler/driver preparation. All
measurement outputs are under `selfhost/build/phase82`; frozen projects are
independent of the current checkout. Every screen uses one guarded CPU3 process
tree, Node24/1GiB heap/4MiB stack,2GiB aggregate RSS and4GiB available floor.

`prepare-screen.py`/`prepare-heldout.py` and `run.py` derive the original checked
B1 discriminator. `prepare-paired.py`/`run-v2.py` compare genuine B1/B2 with
Phase78 and the pinned TypeScript compiler. `prepare-erasure*.py` isolate the
rejected compiler05 consumer against compiler04. `measurements.py` checks exact
C/reports and retains every clean sample before computing medians/ratios.

`template-controls.mjs` appends observation exports to actual B1/B2 images and
checks125 cases each. `transport-controls.mjs` mutates only a disposable copied
project to exercise missing/corrupt/custom/injected fallbacks.
`request-controls.mjs` compares complete owned and ordinary preparation products.

`prepare-bootstrap.py` derives checked B1→genuine B2 and eight driver comparisons.
`prepare-custom*`, `prepare-c-identity.py`, `prepare-release-qualification.py`
and `qualify.py` preserve existing native and selfhosting gates. The C identity
method explicitly admits the new template and audited driver transport change,
while requiring identical runtime/effect bytes and every complete generated C
file. Old mutable driver references are verified against their identical frozen
Phase78 bytes. The failed original preparation method remains as `*-v1.py`.

`worker-v3.mjs`/`run-v3.py` correct the diagnostic stage expectation for the new
combined preparation API. v1/v2 clean measurements are valid; those workers were
not used for successful new-API profiling. Diagnostic profile clocks are never
combined with clean samples.

For a new experiment, use new output directories; do not edit completed plans,
workers or receipts. Start with the short B1 screen and exact-output controls.
Reserve the full serial qualification campaign for a selected candidate. Reuse
native execution evidence only when complete C and its runtime inputs match.
