# Phase156: cheapest trustworthy transfer boundary

Read-only method audit, 2026-11-02. No compiler, generated program or benchmark
was executed. The only computation was maintained source assembly and conservative
declaration-closure accounting in Python. Production source was not changed.
The exact assembled source matches qualified Phase152: 3,085,157 bytes, SHA256
`027e15041035522ed7e40ef971eff75f24a09ef6a00e3f8fe335839f94bcb8a8`.

**Use one small native executable with runtime-selected original/candidate
complete regions before acquiring another full compiler. Publication and
use-summary transfer need different input boundaries. Neither the Phase155
publication replay nor the Phase154 legacy direct producer is sufficient to
claim these two changes improve the maintained compiler request.**

## A decisive publication admission check

The selected [`p86_plan_loaded`](../../selfhost/src/host/native-plan.bend) uses
`p143cg_enough(suffix,256)` to select logged `p143cb_program`. Smaller suffixes
take `check_program_diagnostic_world`. The test counts childless definitions in
the **actual suffix**, not loaded Base declarations and not total source lines.

Phase155's 603 compiler / 504 Map publication events include the loaded Base.
Those counts do not establish that either corresponding prepared request enters
the logged publication branch. Record the actual suffix predicate and relevant
call count before judging candidate speed. Map may be a valuable non-hit/overhead
control. Forcing `logging=True` on an otherwise ineligible small request is a
regional ceiling, not production request transfer.

Use a dependency-closed current compiler workload large enough to exercise that
real branch, selected for its declarations before performance is known, plus the
unchanged Map workload. A closure of actual checker functions provides a plausible
compiler input; confirm its admitted suffix count through the actual Bend loader
and predicate. Do not create synthetic repeated declarations solely to claim a
normal request win. Keep the smaller verifier workload for continuity, explicitly
recording when it does not enter the target path.

The following offline closure sizes use the exact maintained Phase152 source,

A real request CLI can therefore be materially smaller than the complete
3.09MB compiler source. It still brings approximately seven times the source of
an individual checker/lowering region before its IO/cache additions. Source size
is not a timing predictor: use a capped preparation first, then charge the
actual checked acquisition and native build. No new build duration is established
by this audit.

Keep unaffected dependencies shared in that image. Clone only the affected
caller chain needed to route to a named candidate, with declaration-level exact
inverse-renaming checks and unchanged protected-verifier bodies. Blindly cloning
the whole request closure doubles acquisition work and can accidentally change
global names, signatures or output ordering. Host extraction is source transport;
it must not become a host implementation of compiler decisions.

## Preferred small native method

Reuse the architecture of the
[Phase154 harness](../../experiments/phase154/tools/native-harness.bend) and
[native preparation](../../experiments/phase154/tools/native.py):

1. Bind exact original source, candidate source, fixtures, captured headers,
   Base/carrier, runtime and toolchain. Preserve exact original declarations;
   additive renamed candidate declarations must not silently shadow them.
2. Acquire a small checked API once for independent finite controls and exact
   object comparison. Check the complete final native harness source as well;
   a previously checked candidate does not check a newly added IO wrapper.
3. Build one executable through the maintained `native.py`, explicitly selecting
   Phase152 N2 at `selfhost/build/phase152/native-n2/program` and its actual
   `report.json` image binding. The installed `--image-key qbe-n2` is a separate
   consolidated selection; its name alone does not select Phase152.
4. Read runtime mode/count and external fixture files. Execute original and
   candidate in fresh processes from the same executable, serial CPU3, one
   worker, GPU off. Both modes pay identical input decoding and whole-process
   cleanup. Every repetition must rebuild the affected result/analysis; immutable
   input and genuinely shared metadata may be prepared once if this lifetime is
   explicit. Report count-zero startup without subtracting it.
5. Require complete output equality and independent expected success/refusal
   before timing. Preserve negative controls. Calibrate a complete child above
   the existing minimum signal, then use balanced paired order. Keep semantic
   observations and clean clock samples distinct.

Phase155 built its 194KB shared native screen in 33.41 guarded seconds;
Phase154's larger native harness build cost 63.97 seconds. These historical
observations justify attempting one bounded small build; they are not promised
Phase156 costs or evidence that duplicating the full request pipeline is cheap.

## Publication: carry the real checking world

The next useful checker comparison must execute `check_definition_world` and
the original event/last-definition schedule. At publication,
`p143cp_publish` takes **`rw(result)`**, not the previous submitted world. Merely
replaying loaded KDefs omits the very mutations that could invalidate a clean
canonical-state bit or constructor-membership metadata.

Retain or explicitly observe the full `KWorld` contract: book/index, memo, fresh
state and checked declarations. Preserve event history, first failure and all
diagnostic data. `KChecking` also carries term/type, usage, error and consumed
state; success Bool alone is insufficient. A candidate may internally represent
its private clean/dirty state differently, but its published common boundary must
match the independent baseline exactly. Do not canonically normalize both outputs
in the observer in a way that hides the effect being tested.

The cheapest regional harness can compare complete actual checking from frozen
loaded inputs, without backend emission. Call that **checking-region transfer**.
For prepared-request transfer, use the authentic prepared Base state and the
actual `FPrefixLoad`/suffix admission. Source checking Base again inside each
regional repetition is legitimate only when both modes do so and the report
states this is a different workflow from a prepared request.

A diagnostic-only invariant check may compare the book with canonicalization at
proposed clean points and record which actual checker transitions preserve it.
Do not time those full comparisons as the optimized implementation or infer a
universal invariant from passing examples. Template instantiation, normalization,
fresh-ID changes, declaration replacement, law/fill scheduling, duplicate ADTs,
childful non-ADTs and early failures all need explicit treatment. Unsupported
histories must keep the original path.

After exact checking transfer and a useful native region saving, the smallest
real request gate is a source-selected request wrapper rooted at `p86_plan` and
the original streaming `p134e` emitter. It must preserve normal threshold routing,
prepared Base admission and original final verification. Compare complete emitted
QBE and verdict/error status with the original Phase152 executable on each fixed
source. Only that result establishes small-request compilation improvement.

## Uses: exercise the selected flat-binding consumer

The active [`p113pl_bind_flat`](../../selfhost/src/back/qbe/flat-products.bend)
computes `nc_uses(body)` for `p111_keep` and then calls `nc_live_env(env,body)`,
which traverses uses again for a nonempty environment. The boxed sibling already
shares one `uses` value. Do not count the boxed path as a new opportunity.

Capture real calls/owners from the selected prepared lowering path, including
book, value, body, environment, binder ID, target, fresh counter and shape. The
target carries real signature/layout/view metadata; arbitrary invented target
records can change admission and lower different code. Preserve empty
environments, small bodies and all early/refused outcomes in the census. Choose
compiler and unrelated Map owners before candidate acceptance or timing.

The original Phase154 capture is useful input infrastructure but its timed
`p113d_candidate` path covers only nine admitted helpers and is **not** this
selected `p113pl` route. Do not reuse its performance result as transfer. Either
capture the exact flat-binding call contexts or enter the real complete prepared
owner producer containing those calls.

At the narrow boundary compare every field of the resulting `P113DCode`, not
just code length or final fresh ID. For a complete owner, retain original global
function/constructor headers and authentic ordered ready-prefix signatures,
then run the original verifier and emitter. Ready signatures must exclude the
current and later owners as before; full unordered header sets caused invalid
controls in Phase154. Unchanged complete owner/program QBE permits skipping
duplicate generated-program execution for that exact product, but it is not a
new runtime speed measurement or broad-program qualification.

## Input transport and past harness failures

Prefer external exact captured graph files and a checked Bend decoder over huge
nested AST literals. Phase154 rejected a 4.5MB literal book and retained all book
fields plus sharing correspondence in graph transport. Do not transport only
names/types while silently dropping ownership, unsafe/native flags, spans,
removed fields, index structure or order needed by the consumer.

Phase155 parser transfer first exceeded the hosted stack on long literals;
balanced 256-character chunks fixed acquisition but not the later full-source
`dg_width` recursion. Its matching old/new parse errors also initially passed
equality until independent success assertions rejected them. Therefore:

- Source-check success is not successful execution of a native/hosted fixture.
- Keep actual Base constructor/name context; empty scope is not a shortcut.
- Avoid re-running full Base parsing/serialization in hosted observations when
  exact captured input and a smaller complete observer suffice.
- Do not silently substitute `p86_width` for `dg_width` in only one role to make
  the harness run. A justified shared transport repair needs its own receipt.
- A graph equality bridge must bind source/API and decoder bytes and check all
  fields. Pointer identity is not language equality, but sharing/lifetime changes
  can alter native behavior and therefore need retained correspondence evidence.

## Cost and stopping boundaries

The whole Phase155 investigation used 159.16 guarded seconds, distinct from
agent/review time. Preserve that efficiency by collecting both families in one
bounded extraction/check and building one shared image where dependencies remain
manageable. Do not buy a full self-build merely because a new API compiled.

Run the cheapest stage first: source/admission census, complete finite outputs,
one small native acquisition, actual consumer output, paired region timing. A
failed invariant or non-hit actual workload rejects a claimed transfer cheaply.
Whole-request construction is justified only by a material surviving region win.
One cached-runtime prepared request ratio cannot become a cold source-to-executable
or upstream ratio without its own matched denominator.

All root-owned jobs use one maintained disk/process guard, fresh run roots and an
explicit complete-run disk budget; no nested guards or parallel timing. One
worker/mutator remains the runtime contract. Close/seal failed and successful
attempts without pruning. Historical recipes are inspected for method; their old
installed selectors, source identities and path guards must not be replayed as
current Phase156 identities.
