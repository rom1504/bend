## Results

Relative to the preceding Phase39 compiler, the two list pipeline points run
**9.97× and 13.11× faster**, and the three tree points run **1.83–2.18× faster**.
These are actual compiler-generated programs, with unchanged materialized tagged
intermediates. List execution still takes **4.51–6.52× TypeScript time**, and
these tree points take **17.15–21.54×**. There is no average-program or parity claim.

## What changed and why it works

The compiler reuses the existing structural frame engine and complete typed
purity/dependency proof. It adds canonical Nat producers returning data, direct
transfers to proper descendants, and one-child constructor/known-combiner
continuations. The exact built-in `List<&2,U32>` representation is admitted.
Arguments before a recursive child execute during descent; later arguments
execute during reconstruction. Mixed unary/binary frames retain child order,
tagged values and original aliases. Public host/dependency guards and proof
cleanup remain mandatory. Primitive combiners and unsupported shapes keep their
existing fallback; there is no fusion or new runtime representation.

The large list gain comes from avoiding generic dispatch throughout a useful
recursive component. It did not require deleting intermediate lists or changing
observable values. The tree gain similarly comes from extending the component's
flow and continuations. The [backend rules](backend-rules.md),
[list evidence](lists.md) and [tree/order evidence](tree.md) explain admission.

Checked05 exposed an important selection conflict: its broader Nat rule bypassed
an existing faster scalar island. Original raytrace became **2.426× slower**,
despite passing every output check. Checked06 restricts the new Nat-first rule to
data results. Both ray modules now match Phase39 byte-for-byte. The fresh three
ray comparisons have overlapping ranges and baseline/candidate ratios
**1.0097 / 0.9942 / 1.0247**; these fluctuations are controls, not new speedups.
The [selection review](raytrace-selection-review.md) preserves the cause and fix.

This is a small source-cost tradeoff: **+141 physical Bend lines (+0.753%) and
17 definitions**, reaching **18,863 lines / 2,104 definitions**. The **70 modules,
71 types, 640 laws and runtime bytes are unchanged**. See
[source accounting](source-counts.md). It is not a line-count reduction.

## Compilation cost and profiles

All 36 [normal checked requests](compiler-cost.md) reproduce their expected bytes.
Tree request time rises **24.45%**, list **19.09%** (about 0.485/0.317 seconds);
local has a noisy **18.44%** increase, while numeric is approximately unchanged.
Requests take **4.66–8.37× TypeScript time** on these four sources. The release
accepts this cost for the much larger selected execution gains; it does not
claim faster compiler throughput or faster compile-and-run-once latency.

All 18 [CPU/allocation captures](profile-findings.md) pass on exact final modules.
Sampled allocation per call falls **81.8% list512 / 46.9% tree8**. Direct list
workers replace hot generic dispatch; residual tree calls and tagged storage
remain expensive. Static total call sites grow because fallback code remains,
so syntax counts alone would miss the hot-path improvement. Profiles are separate
from clean timing, and allocation figures are sampling estimates.

## Workflow and next work

Two Sol 6.1 medium agents investigate mechanisms and semantic boundaries, a Sol
6.1 low agent handles evidence/tool reuse, and root reviews changes and executes
heavy jobs serially. Saved-output prototypes precede compiler integration;
actual-output controls precede broad timing. Root keeps a 1 GiB Node heap,
2 GiB process-tree RSS ceiling/free-memory floor, CPU3 and explicit deadlines.
The [portable loop](../../selfhost/tools/performance/phase40/README.md) provides
20/60/300/600-second presets with independent case selection and separate
CPU/allocation/JavaScript diagnostics. Broad release gates are not the edit loop. The published five-point/45-sample
portable smoke passes in **20.36 seconds**; the runner records a **0.36-second
overrun** of the 20-second preset.

Exact-byte reuse avoids a second full 18-minute comparison after the corrective
change: only the three changed points are retimed, in **79.463 seconds**.
This reuses execution evidence only; fresh semantic, compiler-cost and release
checks still bind checked06. The [workflow findings](workflow-findings.md) and
[selection review](execution-selection-review.md) explain the controls.

A lexer complete-component prototype improves three fixed points by roughly
**2×**, but remains manual JavaScript. It is deferred because production needs
broader String/Char/Sigma proof support. The [lexer study](lexer.md) preserves its
mechanism, independent controls and timing without claiming a shipped gain.
The next useful investigations are that proof boundary and the still-generic
Map/String/BST components. Direct unfused lists now provide a measured baseline
for a later fusion experiment.

The campaign started October 2 and resumed October 3 after an interruption.
Elapsed accounting separates declared session windows, recorded jobs and
unclassified time; it cannot identify a causal model/effort speed multiplier.
No PR comment is posted. All 103 unrelated starting files remain protected.
The [closed evidence capsule](evidence/README.md) preserves raw failures, checked
emissions, timings, profiles and release receipts; the [accounting](accounting/report.md)
keeps recorded job time distinct from session windows and the interruption.
