# Controlled historical45 generated-program screen

This is a bounded screen of programs emitted by a **checked hosted API**.
It does not establish native N1/N2 self-reproduction or replace the ordinary
native full45 qualification. Do not execute the broad plan until the selected
source passes the coordinator's small source, finite-control and request gates.

The exact historical Phase93 repetition wrappers remain frozen in
`phase112/benchmark45/manifest01.json`. Baselines are the selected Phase128
N2-produced programs from `phase128/native-runtime01/report.json`, whose last
measured44-point runtime ratio is1.65258× upstream. Phase130 demonstrated
unchanged program generation; it did not produce a new historical timing block.
Pinned upstream binaries, the original independent output/count oracle,
`upstream-50ms-profile01.json`, input arguments and aligned machine-build policy
are retained. No wrapper source is rewritten.

## Stages

1. `prepare` authenticates the checked compiler API/source and writes jobs.
   The existing `phase128/emit-entry.mjs` emits all45 exact wrappers through the
   actual request-bound entry, independently verifying parent IR for each one.
2. The derivative `screen.py --check-only` builds with unchanged
   `phase123/build-aligned.py` and the selected Phase128 runtime. It runs each
   wrapper once, no warmup, using its frozen runtime arguments and the original
   `phase112/benchmark45/run.py::observation` oracle. This is a correctness
   smoke, **not a historical runtime sample**. Wrapper output has four lines;
   the one-line oracle for ordinary full45 programs cannot be substituted.
3. `classify` compares exact whole QBE against Phase128, authenticates the same
   runtime, and reuses Phase127's read-only ELF inspector. An unchanged product
   must also have identical allocated sections, addresses and contents, except
   the nonsemantic linker build-ID note. NOBITS extents are compared without
   treating them as file bytes. Each result and binary identity is recorded.
4. If fewer than23 products changed, only changed products enter the runtime
   screen. If23 or more changed, run the entire original45 corpus:405
   observations, three roles and three rounds. These use the original frozen
   repetition profile multiplied by4, original warmups, rotating role order,
   in-program millisecond clock and complete output oracle. Previously checked
   builds are reused rather than rebuilt.

Every target job has its own CPU3 process-tree guard, memory cap and16GiB
available-memory floor. Run jobs serially. Do not wrap the entire plan in an
additional target guard. The `classify` step only reads artifacts and invokes
`readelf`; it never executes generated programs.

For changed-only results, report per-program comparisons and explicit coverage.
Do not combine current subset timings with historical unchanged timings into a
new broad geometric score. Exact QBE/runtime/allocated-code preservation
supports unchanged generated code, not a fresh wall-clock measurement. A new
historical aggregate needs the full comparable block, including the frozen
zero-work control,44 timed points, positive-log deficit, families and regression
counts. The existing `phase126/summarize.py` can summarize a full screen.

## Prepare and execute

```sh
python3 -B selfhost/tools/performance/phase131/programs/plan.py prepare \
  --api CHECKED_API_REPORT --source-manifest CHECKED_SOURCE_MANIFEST \
  --out selfhost/build/phase131/FRESH_SCREEN --tag UNIQUE_TAG
```

The source/API hashes are frozen into `plan.json`. Root executes its three
jobs in order, stopping on failure. The existing Phase113 serial runner can
do this while pinned to CPU3; individual target commands already contain their
guards. After classification, inspect `classification.json` and execute
`runtime-jobs.json` only if correctness passed. A separate full native compiler
qualification remains necessary before selecting or installing the compiler.

## Cost and changes to the old tool

Historical Phase128 native emission of these45 wrappers took121.9s. Its aligned
builds took13.0s and the405 target observations158.5s. These are planning data,
not promised current durations; hosted independent emission can cost more.
The smoke avoids spending the full timing budget before correctness and exact
code-change coverage are known.

`screen-derivation.json` records every textual change from the Phase128 runner
and verifies its exact inverse. The timing oracle, repetition/warmup selection,
role rotation, argument order and clocks are untouched in timing mode. Changes
are result/build locations, the explicit Phase128 baseline, authenticated
reuse of already built products, and the separate correctness-only mode.
`plan.py` checks that inverse before preparing or classifying a campaign.

## Bind measured outputs to the native successor

After the successor image build is complete, `native-equality.py` can prepare
45 native source-to-QBE requests with exact byte comparisons to the measured
hosted products:

```sh
python3 -B selfhost/tools/performance/phase131/programs/native-equality.py prepare \
  --image-build N2_BUILD_REPORT --image-request Q2_ACQUISITION_REPORT \
  --admission selfhost/build/phase131/combined-literals-admission01.json \
  --hosted-emission selfhost/build/phase118/p131-combined-literals01-wrappers/report.json \
  --screen selfhost/build/phase131/combined-programs01/runtime/report.json \
  --carrier-receipt selfhost/build/phase130/base-carrier01/receipt.json \
  --out selfhost/build/phase131/FRESH_NATIVE_EQUALITY --tag UNIQUE_TAG
```

It authenticates the image build against the native request that generated its
QBE, the checked candidate source/admission, the compact carrier lineage and the
exact binaries in the measured405 block. Every request uses unchanged
`phase130/native-request.py --expected-qbe`; output must match completely,
including LF bytes. Root executes the planned serial CPU3 guards. The final
metadata job binds all45 completed receipts. No generated program is rebuilt
or executed by this plan.

If all45 outputs match, the same QBE bytes and runtime reproduce the already
measured products; repeating405 timing observations adds no new code-quality
evidence. This gate itself makes no native qualification claim. Whole-source
self-reproduction, focused controls and ordinary native qualification remain
separate, including the required extra code-generation generation.
