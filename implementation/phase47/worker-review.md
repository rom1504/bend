# Phase47 private-worker optimization review

Recorded 2026-10-04. Reviewer: callbacks owner. Status: **proposal read; implementation pending; no target execution or correctness qualification**. This review is separate from [compiler-cost work](compiler-cost-proposal.md).

The writer's proposed `jw_optimize_functions(List<JWFunction>)` preserves function count, index and order. It performs bounded expansion of straight-line callees, forward copy/constructor-field substitution, then removal of unused inert copies or fresh tuple/tagged shells. Full original JPure/source/instance/host guards remain outside this pass. The proposal is a plausible narrow enabling transformation; its implementation and independent controls still need review.

## Representation facts checked

- [worker-model.bend](../../selfhost/src/back/js/ir/worker-model.bend) has values separate from explicit call instructions. `JWGlobal`, `JWNative`, primitive, projection and constructor values are not uniformly inert.
- [worker-lower.bend](../../selfhost/src/back/js/ir/worker-lower.bend) gives every nontrivial expression a stable slot and lowers actual arguments left-to-right. Prefix matches demand fields before continuing. Parameters occupy slots below arity; later slots are temporaries.
- Branches reuse numerical slots: `jw_match_fields` starts the fallback at the incoming `next`, and `jw_match_done` takes the maximum branch bound. A slot number therefore is not a globally unique definition identity across mutually exclusive arms.
- `JWCase` generated by lowering terminates its surrounding instruction list. The existing [simplifier](../../selfhost/src/back/js/ir/worker-simplify.bend) flattens only that exact form; malformed cases with trailing work are not permission to make trailing work executable.
- [worker-emit.bend](../../selfhost/src/back/js/ir/worker-emit.bend) chooses SCC-specific call/continuation transport from function indices. Inlining must preserve indices and targets, and refreshed component analysis must inspect the final transformed calls.
- [worker-nat.bend](../../selfhost/src/back/js/ir/worker-nat.bend) turns Succ/add into checked Number-Nat operations only after whole-graph admission. These operations can fail; neither their unused results nor source purity authorize dropping evaluation.
- [primitive.bend](../../selfhost/src/back/js/primitive.bend) includes F32 Math calls and conversions. It is unsafe to classify every `JWPrimitive` as discardable or duplicable merely because U32 addition is total.

## Required transformation contract

| Area | Required invariant | Discriminator |
| --- | --- | --- |
| Inline target | Exact existing index, valid function, Assign-only prefix ending in Return; no calls/cases/global/native dependencies newly hidden | Invalid target, recursive target, case/native/global helper stays unchanged |
| Parameter binding | Materialize every actual once and in left-to-right order before inlined instructions; never substitute actual expressions directly into formal uses | Unused failing first/last actual, repeated formal use, noncommutative actuals |
| Alpha-renaming | Fresh range above full caller bound, including both branch bodies; return value and every nested operand renamed | Same slot numbers in caller/callee and sibling branches; two expansions of same target |
| Copy propagation | Substitute only already evaluated immutable slot/Nat facts; invalidate on an assignment to the same numerical destination if reassignment is possible | Old alias read after destination reassignment; branch-local definition must not reach sibling |
| Aggregate fields | Exact matching tuple/tagged layout, in-range index, dominated fresh constructor; fields are already evaluated values | Mixed layouts, shared constructor, repeated projections, nested aliases |
| Demand and errors | No movement/duplication/deletion of global/native/Char/String/Nat/NumberOp/opaque literal evaluations | Unused checked Nat overflow; String/Char failure; hook observation order |
| Dead values | Drop only exact inert copies or fresh tuple/tagged shells after a complete remaining-use scan | Use in nested value, call argument, case control, either arm, returned/shared aggregate |
| Proof provenance | Admission and primitive/dependency fences retain complete original typed graph before optimization | Removed primitive call still requires original fence; refused graph remains ordinary |
| Bounds | Code-growth, fresh-slot, fact-table and traversal limits decline or leave original instructions unchanged | Deep/large helper, wide arity, many inline sites, slot arithmetic boundary |

The writer proposes at most 12 callee instructions, 32 added instructions per caller and 64 forward facts. Added-instruction accounting must include parameter assignments as well as expanded body assignments. The budgets require real short-circuit `kc` fences before dependent/recursive traversal: strict Bend `&&` does not stop a scan on an invalid earlier guard. A miss or refusal must not publish partial renamed code.

## Explicit limitations

No whole-graph purity claim grants all discard/move/duplicate permissions. A fresh shell can be removable while its field computations remain required. Opaque `JWLiteral` is emitted code and must remain opaque for those permissions. Nonescape and immutability need distinct facts; shared references cannot be changed into repeated construction when identity or later native transport can expose them.

The current successful typed graph admits private immutable aggregates but also retained native/global scalar operations. This review does not license Array backing reuse, host memoization, public aggregate ABI changes, altered Error-hook reentry, or entry-guard reduction. No proposed speedup is inferred from source counts.

Implementation inspection and independent source/control review will append a new dated status below; pending work must not be read as a static PASS.

## Implementation read — static qualification of helper only

Reviewed `worker-optimize.bend` at SHA-256 `8ff5f8d63bc53b937e879510a0d4b4062fc431be06c58eaabe967c6b2f7e7cbd` (365 lines). **Static PASS for a source experiment on admitted JW graphs**, not a checked build, executable qualification, measured gain or promotion. Integration call sites/manifest were not yet changed at this checkpoint; any successor bytes require a new review identity.

The helper satisfies the principal obligations:

- `jw_opt_expand` consults original templates throughout one sweep. Candidates are at most twelve Assign/Return instructions, with no calls or branches, so expansion cannot recursively grow an inlined template or remove a recursive edge. Existing function count/order/index and valid flags remain unchanged.
- `jw_opt_parameters` binds all actual values left-to-right before the cloned body. Clone offsets every admitted nested slot and writes the returned value to the original call destination. The fresh starting range comes from the full caller register bound; the next range accounts for the entire callee register width. An explicit U32 capacity check protects offset arithmetic.
- The per-caller 32-unit budget is shared across both case arms and following code. Cost includes arity plus callee body length, counting the replacement return assignment. It is introduced-instruction accounting, not a claim that net code grows by exactly that number.
- `jw_opt_forward` starts both branch arms from identical incoming facts and clears facts after the case. `jw_opt_forget` removes both the overwritten key and every retained fact whose stored slot/constructor fields reference it. Facts contain only stable Slot/Nat leaves or fresh shells; opaque literals and computation expressions are not alias facts.
- `jw_opt_shell` requires canonical `Tuple` with exactly two fields for tuple facts/discard. Tagged layout is a literal fresh named-field object in the existing emitter. Projection substitution requires the same layout and an existing field; an out-of-range lookup keeps the original projection. It replaces the already evaluated field value, never its computation.
- The backward use walk descends projection inputs, constructor fields, primitive/native/NumberOp arguments, explicit call arguments, return values and both case arms. Each branch's pre-use set is unioned before its predecessor. Exceeding 64 tracked slots changes the state to incomplete/all-live; it cannot authorize deletion.
- Dead cleanup only removes unused Slot/Nat copies or exact fresh shells with stable fields. Literal/global/native/primitive/Char/String/checked-Nat/NumberOp evaluations stay at their original assignment point even when their destination is unused. Inlining admits only a narrow U32 arithmetic whitelist and retained opaque literals; native/global/faulting arithmetic values are refused as templates.

The optimization is not an admission proof. It depends on existing successful JW lowering for valid slot definitions, ordered arguments, typed immutable aggregate shapes and bounded graphs/bodies/depth. The 12/32/64 local limits do not replace those upstream traversal bounds. Existing source and primitive/dependency proof scans must continue to consume the original rows/JPure graph; final SCC, register and Nat analyses must consume the transformed JW functions.

Remaining root gates: integration diff, a checked candidate, independent renamed argument/branch/aggregate controls, unused overflow and opaque-demand controls, original dependency mutations and the five canaries.
