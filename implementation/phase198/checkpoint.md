# First broad measurement and runtime experiments

The Phase197 source acquired a native compiler that emitted all 45 ordinary direct-x86 programs correctly. On fresh measurements on CPU3, its geometric runtime ratio to mature self-hosted Bend C was **1.87145×**, versus **1.89758×** for the preceding Phase195 compiler in the same comparison. One zero-work case is correctness-only. Mean positive log-slowdown went from 0.77077 to 0.75447. Both versions had 36 of 44 programs above 1.1× and 26 above 2×. The candidate reduced fixed-catalog time from 23.82 to 23.53 s versus 10.51 s for C. The 30 timed held-out cases improved 0.48% geometrically. [Full results](../../research/phase198/qualification/broad-runtime-summary01.md)

Edit distance and local-pair improved about 14%. In the paired repeat local-fold-128 became 6.0% slower with all six pairs in the same direction. A 13.7% apparent list-pipeline regression in the first measurement occurred with byte-identical object code and linked sections; the repeat measured 0.6%. Lexer-6's initial 7.2% regression also failed to repeat. These controls are why a consistent code mechanism and repeated timings matter. [Regression repeat](../../research/phase198/qualification/regression-summary01.json)

## What changes when the generated code is held fixed?

Recompiling the shared runtime at O3 produced mixed effects. Keeping the incumbent compiler and -O2 flags while separating raw owned constructors from packed/shared slow paths reduced runtime on four distinct inputs. Compared to the original, tree sort took 0.917×, BST-64 0.875×, Map churn-128 0.925× and expression-128 0.915×. Lexer, RLE and scalar fold were close to unchanged. All seven original executable identities reproduced before the comparison. Each variant passed the mature C output checks for the ordinary and an additional input before timing. The complete screen took 61.8 seconds. [Per-round values and object identities](../../research/phase198/runtime/screen01-summary.json)

The pilot binds the constructor arity/sealing information once per process and splits out a small free-list hit and raw take. A separate experiment tests whether a split using live descriptor reads has the same benefit, and whether the gain transfers across the full suite. The first seven points do not establish a new global score. [Experiment](../../research/phase198/runtime/plan.md)
