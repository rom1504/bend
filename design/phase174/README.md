# Publish the Phase171 compiler

The user authorized completing publication of the measured Phase171 version.
This is a bounded integration and qualification, not a new optimization campaign.

## Frozen comparison

Keep Phase170 source (3,150,535 bytes, SHA256
`434edd1d56128f9480800573abf8a0ae21d910a547837af089f25cd1d0e89b71`)
and its installed N2 as the performance reference. Phase171 measured
188.620→180.677 seconds on this identical input. A new self-build source is a
separate workload and must not replace that comparison.

## Sequence

1. Integrate exactly the sixteen replacements and twenty-eight new declarations
   from the four measured overlays into maintained modules. Preserve protected
   verifiers and independent source checking; compare with the frozen candidate.
2. Re-run the 77 finite controls through a checked hosted API. Build genuine
   N1/N2 and observe Q3; require complete QBE fixed-point and inspect machine
   products. Retain the qualified Phase170 installation throughout qualification.
3. Qualify actual N2 with all 64 native cases; compare ordinary and timed
   45-program QBE products with the qualified references. Check native positive
   P140/2 sessions and the explicitly supported hosted API.
4. Because publication history changes common checking, acquire real JS B2/B3
   and a canonical-derived native public C image. Run their independent public
   behavior and broad correctness gates. Keep source checking, finite tests and
   self-reproduction distinct from mathematical proofs.
5. Run a clean fixed-input native performance comparison and record the new
   source self-build separately. Exact products preserve generated-program
   performance evidence; they are not new runtime measurements.
6. Audit all three bindings using the unchanged release auditor, install with
   selector-last transaction and rollback, verify installed artifacts and
   launchers, update documentation, commit and push completed evidence.

## Resource discipline

One CPU3 execution lane, maintained guards, fresh outputs, 5 GiB reserve and
explicit budgets. Archive only exact verified retired artifacts when necessary.
Source auditors work concurrently; expensive target runs remain serial. Failed
attempts remain evidence. Do not promote Phase172/173 speculative changes.

## Linked image identity clarification

The strict first reproduction check found identical QBE/assembly/object and
actual Q3, but raw ELF load bytes differ. The bounded [audit](../../experiments/phase174/elf-audit.md)
accounts for exactly 21 mapped metadata bytes: one section-table offset byte and
the 20-byte GNU build-id. All loading parameters, executable code and runtime
data are identical. The separate v2 receipt preserves raw equality as false
and admits only that explicitly parsed pair. The original failed receipt remains.
The release auditor and semantic gates are unchanged; no arbitrary metadata
mask or binary rewriting is used.
