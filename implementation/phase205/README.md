# Phase205 · Direct x86 program runtime on fixed work

The experimental native compiler cut fixed-batch execution time **3.74%** in a matched comparison. Direct x86 took **1.547× mature Bend C**, down from **1.607×**. The corresponding geometric means were **0.941×** and **0.996×**. Lower is faster.

## Question and baseline

Can two transformations on checked Bend terms reduce the original fixed-work batch, while keeping the same programs, input sizes and mature Bend C executables? Phase200's 44 timed cases took 17.810 s on direct x86 and 10.941 s on C. Its geometric mean was 1.004× C. The fixed batch was 1.628× because the remaining slow programs accounted for more seconds. Bringing the three lexer inputs alone to C speed would save 1.235 s. Both Unicode inputs together offered another 0.231 s to C parity. [Frozen weights and ceilings](../../research/phase205/weights/results01.md)

The latest cold-build experiment and the best generated-program experiment had diverged. A clean three-way merge combined Phase204's cold-build changes with Phase200's generated-code changes using Phase198 as the common source. The same Phase204 native compiler built both this merged baseline and the treatment. Each user program in the comparison was then freshly built by each experimental compiler and linked against the same Phase199 runtime. ## Two transformations

**Distribute a string transformation across repetition.** The transformation reconstructs seven helper roles from their checked equations, verifies binder relationships and the native equality operation, and recognizes a repeated block that is split and rejoined with a separator. Since this operation maps each input character to a string, it can transform the block once and repeat the result. Both the count expression and the block expression are still evaluated once, in order. The zero case returns immediately after evaluating those arguments. Equational matching rejects near-misses that drop empty fields or expose the intermediate parts. Rechecking covers the generated body and the existing layout verifier still runs. The checked sequence lemma from Phase200 covers the algebraic identity. The connection between those equations and the emitted executable remains an implementation and testing obligation. [Matcher](../../research/phase205/hoist/distribute.bend) · [Strict zero branch](../../research/phase205/zero/guard.bend) · [Independent cases](../../research/phase205/controls)

**Unfold a bounded structural recursion on a known String.** A worker may consume a literal supplied at any argument position while threading unknown dynamic arguments. The compiler selects the known constructors, keeps unknown computations in evaluation order and rechecks the residual. The selected stage accepts at most one such specialization per request. The string limit is 64 codepoints. There is no required template value or worker name. [Bend implementation and limits](../../research/phase205/native-unfold/README.md) · [Exact selected source delta](../../research/phase205/snapshots/guarded.json)

On the lexer, resolving the 39-character spine replaces recursion with straight-line calls. In the real emitted object there are now 39 relocated calls to `gen.at` and 28 to `salt`. The direct worker is 5,177 bytes. Total machine text fell from 75,433 to 74,158 bytes and the number of functions fell from 249 to 221. The compiler still does character-dependent helper work. The separate source experiment that also specializes those helpers measured a 31–33% runtime reduction on the three lexer inputs, compared with 21–22% for its spine-only variant. Those source measurements use a different baseline. [Real object census](lexer-machine.json) · [Source ablation and held-out packet](../../research/phase205/unfold/README.md)

## Experiments that changed the decision

- The first automatic unfold left the lexer object identical. A trace of checker continuation construction was misleading. Recording the actual checker return found an affine binder error on the lexer and missing types on nested residual lets on a separately authored packet worker. Requesting reusable binders for shareable data and typing the residual lets admitted both workers. A two-owner case checked the single-specialization restriction. [Refusal](evidence/p205decisions01.json.gz) · [Repair trials](evidence/p205repair01.json.gz) · [Final decisions](evidence/p205decision06.json.gz)
- Early automatic text distribution cut positive held-out packet time by about half. It made an empty repeat of a precomputed 65,000-character block about 4,800–4,900 times slower. All returned words were correct. Moving the transformation inside the positive branch addressed a performance obligation that a semantic equality test missed. [Adverse and positive results](evidence/packet-transfer02.json.gz)
- A separate Boolean-tag tree representation passed finite structural checks and emitted its intended code. The BST timings were 1.082× baseline on the larger input and 1.003× on the smaller one. The larger case had substantial dispersion. This variant was excluded from the final image. [Machine checks and timings](../../research/phase205/tree/native-result03.json)
- Phase200's aggressive hand-staged lexer at these weights makes 1.445× C conceivable when combined with the earlier text ceiling. The automatic transformation tested here only unfolds the known input spine. Token production and consumption still happen at runtime. [Counterfactual calculation](../../research/phase205/weights/staged.json)

## Transfer, compiler cost and scope

Two independently authored workloads isolate different transformations. On positive dynamic repeat counts, the packet text transformation took **0.465×** baseline on fixed work. The guarded long-block zero cases took **0.876–0.880×** baseline. The return value includes length and two hashes of every output word. The separate packet counter that folds a static Unicode header took **0.274–0.276×** baseline over three seeds at 512 records. Seven points passed independent counter oracles. The source was identical between compilers. [Guarded packet text](evidence/guarded-packet06.json.gz) · [Native packet counter](evidence/p205unfoldnative01.json.gz)

Emission across 45 fresh requests rose 0.951 s (1.20%), and linking rose from 1.534 to 1.726 s. The requests were built in a fixed role order; these totals are a cost signal with limited precision. On a separate balanced four-run compiler-verifier request, both emitted the same object and printed 768. The baseline averaged 7.564 s and the candidate averaged 7.478 s. A Phase204 compiler acquired the merged baseline in 297.237 s and the candidate in 301.996 s on different sources. The candidate source grew by 30,233 bytes. These acquisition figures answer a different question from timed program runtime. [Compiler request control](evidence/p205verifier06.json.gz)

Two additional prototypes were kept outside the selected image. A checked one-pass replacement makes both generated helpers reachable on a direct split/join owner. The observed-list and altered-delimiter controls leave those helpers unreachable. The second prototype specializes small pure helper branches on constant scalar inputs. It passed the actual body recheck on both the lexer and packet and preserved the one-owner cap. [One-pass decisions](evidence/p205onepass07.json.gz) · [Scalar decisions](evidence/p205decision08.json.gz)

The selected N1 compiled its own source to a fresh N2 in **305.03 s**, including a 0.29 s link. The N1 and N2 compiler objects have different hashes and sizes (33,641,872 and 34,280,136 bytes). They have different producers. The result establishes a successful native compiler build; a fixed point requires a further generation and an independent release decision. N2 independently emitted byte-identical objects and executables to N1 for the lexer and both Unicode programs, with 27 fresh checked timing observations. Eight additional finite controls passed mature upstream JS and both baseline and treatment N1, including observed intermediates and effect ordering. The installed compiler was preserved. ## What to try next

It takes another 0.479 s of fixed work to reach 1.5× on this run. The largest remaining family gaps to C are ray tracing (0.947 s), BST (0.739 s), evening (0.643 s) and lexer (0.623 s). These are measured differences, not forecasts. The lexer is the best short experiment because the partial evaluator already admits it and independently written packet code benefits from the same mechanism. The larger opportunity is to remove intermediate character lists and classify the residual token stream directly. Test two unrelated token consumers with altered separators, escaped characters, dynamic seeds and observed intermediate results before acquiring another image. Ray tracing provides the next independent family and already has a staged instruction-level experiment. [Repriced opportunities](opportunities.json) · [Ray screen](../../research/phase200/ray/README.md)

Taelin shared his design rationale at the SF Lean Meetup on November 19. One concrete research question for this compiler is whether a rule can carry a bound on the work it adds or removes. The adverse repeat input gives an exact quantity to model: how many source elements must the mapping operation inspect? Lean 4.32 checked a new theorem about an instrumented mapper for every finite input and repeat count. The original visits `n × block.length` elements. The guarded formulation returns the same value and visits zero elements when `n = 0`, or exactly `block.length` otherwise. The theorem models mapper applications. Creating the dynamic arguments, allocating the output and executing machine instructions have separate costs. [Theorem](../../research/phase205/zero/Visits.lean) · [Check receipt](evidence/p205visitlaw01.json.gz) [Taelin’s post](https://x.com/VictorTaelin/status/2123406746018299989) · [Talk](https://www.youtube.com/watch?v=PqufdZ5skWQ)

## Reproduction

1. Reconstruct the merged source with `python3 -B research/phase205/parents.py NEW_PARENT_DIR`. The script checks all three historical source hashes.
2. Reconstruct the selected compiler with `python3 -B research/phase205/snapshot.py restore guarded NEW_PARENT_DIR/compiler.bend NEW_COMPILER.bend`. The compressed delta and resulting compiler are hash-checked. Working drafts in the research directories also contain more aggressive alternatives.
3. Build the two experimental images with the Phase204 producer and the runtime specified in the image receipts. These include the original guarded commands. The Phase198 installed image remains a rollback path. [Parent image](evidence/p205parent01.json.gz) · [Treatment image](evidence/p205image06.json.gz)
4. Follow the [measurement instructions](../../research/phase205/measure/README.md) with those image receipts. The frozen plan includes all 45 sources and C references, all input arguments and the new native compilers. Timings from identical products remain in the aggregate. The compiler requests, machine links and program execution intervals are reported separately.
