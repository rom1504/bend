# Phase197 copy/immediate selection

The candidate replaces an adjacent typed `movq source,destination; addq/subq immediate,destination` with `leaq displacement(source),destination`. It uses the existing LEAQ object encoder and renderer. The source and destination must be distinct ordinary 64-bit GPRs, excluding RSP/RBP. Both words of the immediate must satisfy the existing signed32 encoder predicate; SUB additionally refuses INT32_MIN because its negation is not a signed32 displacement. Arithmetic wraps modulo 2^64. U32 writes, memory sources, mismatched destinations and other operations retain their original sequence.

LEA preserves flags, unlike ADD/SUB. The candidate therefore looks forward at most sixteen typed items and accepts only when CMP/ADD/SUB overwrites all arithmetic flags first. Moves, LEA, shifts and bitwise operations may be crossed because they do not read flags. Partial flag writers never finish the proof: a zero-count shift cannot incorrectly certify dead flags. Conditional consumers, carry arithmetic, unknown instructions, calls, labels, directives, PEmpty and end-of-sequence stop the proof. There is no instruction motion and no state across a control-flow boundary. The explicit fragment work list handles either association of X188Join without flattening an entire function.

The intended machine witness is the Phase196 BST64 block in `p113d_FID_$product.bst.down`: its initial `movq %rdi,%r10; subq $1,%r10` becomes `leaq -1(%rdi),%r10`. The following frame store, source move, SHR, AND, immediate materialization and CMP stay in place. Neither the benchmark name nor its symbol occurs in the selector.

`recipe.json` specifies the isolated API overlay. `select.bend` adds the selector; `hook.bend` replaces only `x191_frame_forward`, composing after the original frame-forward pass. `controls.bend` exports `p197d_controls` and `p197d_emit`. `driver.mjs` reuses the existing authenticated two-route machine-control workflow; it checks 28 exact selection/refusal rows, then builds direct-object and rendered-assembly routes against `observer.c`. Each route checks 2,120 arithmetic/flag observations across boundary and deterministic generated inputs. The signed comparison observer includes the signed-overflow boundary. The two machine routes share typed selection and are not independent compiler implementations; C supplies the independent expected values.
