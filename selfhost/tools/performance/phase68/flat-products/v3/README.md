numeric/array/lexer C contains zero private product workers. The source audit
therefore rejected the intended array mechanism. The actual products10 signature
diagnostic then showed every `A & B` type remains `App(App(Ref Pair,A),B)` and v2

selection, not a vector performance result.

V3 uses a general syntax machine with a head, argument spine, visited definition
names and 64 transitions. It strips annotations, collects applications, looks up
ADT declarations or transparent definition bodies and substitutes lambda arguments
without invoking the global normalizer, conversion, matchers, primitives or effects.

no alias-name exception. Before alias beta or constructor-parameter substitution,
the product of body and argument syntax sizes must be at most 4096; each size count
stops at 4097. This bounds new expansion before constructing it.

dependencies and exact structural parameter equality. It ignores the outer ADT
parser quantity/id metadata, as the core's ADT conversion rule does. The earlier
nullary Ref canonicalization creates outer quantity0 while constructor results
carry quantity1, so whole-term `norm_exact` was too strict. This does not normalize
the arguments or infer any field representation.

All product call, ownership, demand, branch and graph-admission rules remain as
v2. The relative patch is bound to the existing helper hash in `manifest.json`;
it composes with the parent's occurrence-reuse bridge/flat changes. Preserve v2
