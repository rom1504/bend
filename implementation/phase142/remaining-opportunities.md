# What the first Phase142 campaign changes

This is a decision record, not a new performance forecast. The committed
[plan](../../design/phase142/README.md) still targets complete edited executables,
not isolated compiler functions. The native indexed-traversal result belongs in
the phase report; source and profile observations below do not substitute for it.

## Retain the ambition, change the order of evidence

The first raw-owner witness removes183/265 and641/666 comparisons on two small
programs. The absence of a clear whole-request gain is useful negative evidence:
the number of rejected/reused sites does not reveal their dynamic cost. A second
prototype avoids rechecking an unchanged same-request raw/static bundle, but
shared-API timing is mixed. Neither merits a native acquisition merely because
its reuse count looks good.

The source-prefix freshening prototype has a real scaling mechanism, yet its
guard still walks the complete retained prefix. It also starts after completion
and global loader validation. Do not describe it as an incremental frontend.
Keep it available as a bounded experiment; prefer eliminating earlier
materialization with an exact producer/context contract if that can be proved
and measured cheaply.

The new full-edit profile gives a better discriminator. Its warm frontend
contains substantial growing-list membership cost; the backend still contains
source-term comparisons, name/variable lookup and reclamation. These occur at
different boundaries and need distinct falsifiable experiments.

## Traps demonstrated in this campaign

- Different hosted API contents change JIT/GC behavior even on an unchanged
  compiler path. The unchanged-path control showed an apparent5.56% difference.
  Keep a same-API reference where possible, and demand a clean native comparison
  before promoting small gains.
- A pre-override differential control is independent; after entry rewiring,
  its old public call may enter the candidate too. Freeze the original oracle.
- Hash equality is not semantic identity. Use collision buckets/full names for
  sets, and actual source/dependency/runtime contracts for retained products.
- Parser reuse is not completed-prefix identity: relative foreign paths can
  change under a different logical source directory.
- A final projected-worker verifier does not independently validate all generic
  raw bodies. Preserve the actual proof/check boundaries when removing scans.
- A diagnostic active owner is not a physical caller stack or allocation origin.
  Use it to choose an ablation, not to assign all of a shared helper's cost to
  the first convenient caller.
- Small asymptotic tests can show spectacular ratios while real programs are
  neutral or slower. Preserve both and qualify the selected scale explicitly.

One coherent native candidate, independent frozen products and one serial
measurement lane are preferable here to parallel speculative compiler builds.
The next successful transformation should make a large real edit cheaper while
keeping the generated product identical, before another qualification campaign.
