# Bounded borrowed aggregate projection prototype

`prepare.py` replays the exact Phase98 recipe through source04, then adds 45 physical lines (2,391 bytes). The resulting `borrowed-projections-source01/compiler.bend` is SHA-256 `4ca5bbf2ba77e05ef074a495c468a7bd8be08232d6aa5ae73f842b5b648af0a8`. The root agent checked this source through the existing upstream API path; this directory contains no compiler or native execution wrapper.

The change admits plain, nonnative user ADTs with at most four checked constructors, widths zero or 2–8, and at least one boxed constructor. Existing list/String schemas take precedence. Applied fields retain their physical slot but carry an opaque type marker, so erased type names cannot authorize matching, scalar use or borrowed calls. A concrete child with exact checked type can borrow beneath a live entry root of another type. Direct entry arguments retain nominal equality. Certified helper calls with virtual root arguments may specialize repeatedly within the existing depth-eight and 4,096-fuel bounds; uncertified cycles and runtime virtual arguments remain refused.

The runtime, permissions, source04 shared-or-all-trivial guard, ordinary owning fallback and worker/adapter emitter are unchanged. This is a source prototype; whole-compiler performance and broad safety qualification have not been established.

`tag-probe.bend` uses the exact KTerm constructor layouts and tag/equality helper bodies. Each of one million iterations compares generic, lambda and literal tags. All roots remain owned; afterward the program prints every field, nested child and removed-name alias, plus independent input aliases. `prepare-probe-v2.py` prepares the existing emitter's minimal plan under `borrowed-projections-probe02`, reusing source04's checked API and the fresh projection API. `runtime-cases.json` supplies matching, mismatching and empty-input arguments and exact output. The older probe01 plan expected scalar flags zero; actual C has matching baseline/candidate scalar flags one. Probe02 corrects only that metadata and preserves the failed first run.

The already emitted probe01 C contains `$observer.p98_tag_eq_read` and `$observer.p98_tag_eq`. The reader uses borrowed parent and key peeks, directly calls the certified equality walker for a dynamic tag, and specializes `Lam`/`Lit` into character tests. Its body has no keep, sink, take, free or allocation operations. The public wrapper calls borrowed read and finish workers. Both owning adapters keep their entry handles live through the observation and sink them afterward. Baseline tag-reader C has three constructor takes, three frees and 22 field sinks across its branches; those operations remain in the candidate's ordinary fallback. This is mechanism evidence from emitted C, not a measured speedup.

The first useful performance test is alternating source04/candidate runs of the matched native case after exact output comparison. No full compiler images or new qualification framework are required to decide whether to continue.
