# Finite scalar selectors: one missing computation category

The strongest bounded hypothesis is **restoring immutable finite-selector tables**, rather than another F32 transport shortcut. In the actual active-256 ray source, `sx`, `sy`, `sz`, `sr`, and `skr` each select one of nine constant F32 values from a canonical Nat ladder. `nearest` repeatedly selects the first four columns for the same sphere index; `trace` selects them again. The final default covers every index at or above eight. The benchmark already contains a five-field `sphere` constructor with equivalent rows, but substituting that manually would only be a source ceiling experiment, not a general compiler pass.

There is direct upstream evidence for the category. In `selfhost/build/phase93/broad01/variation-ray-active-256-2240/upstream.1.c`, the corresponding `spin5`–`spin8` functions use `TAB_AT(TAB_1..4, i, 8)`, and `spin16` uses `TAB_0`. `TAB_AT` clamps the full input to the last cell. The upstream compiler's `emit_tab` evaluates closed expressions with a host JavaScript function; that implementation is unsuitable as a new self-hosted compiler algorithm. Its result demonstrates the missing optimization, not a reusable trusted evaluator.

The selected Phase125 QBE has 16 branches per standalone selector and 70 branches in each of the inspected `nearest`/`nearest.t` functions, including cold failures. Offline assembly counts are 52–72 instructions and eight conditional branches per standalone selector. `product.nearest` has 421 instructions, 33 conditional branches, and ten calls. These are whole-function static counts, not dynamic frequencies. The selector assembly already folds the constant float calculations: the headroom is repeated decision/control work, not runtime evaluation of every literal division.

The mature Bend JavaScript frontend provides useful semantic premises in `selfhost/src/back/js/region.bend` (`j_region_nat_select`, `j_region_nat_match`, `j_region_nat_first`), but its plan is a `JNatCase` decision, not table data. `j_primitive_type` and `j_primitive_call` authenticate canonical scalar owners and primitive telescopes. The currently selected `p111q_stmt = p114t_stmt` is a transport/primitive emission chain; the `t` prefix does not signify finite selector tables.

The isolated prototype in `selfhost/tools/performance/phase126/specialization/` reuses those premises and supplies a small bounded Bend evaluator. Its output is ordinary full-word P113D decision IR, checked by the unchanged program verifier. An independent final whole-function recognizer derives a clamped immutable data load from that exact IR. Thus no global program-model extension or externally supplied table proof is needed. Unsupported bodies retain the selected lowering. A narrow inliner exclusion preserves the table opportunity until rendering; this version still pays one direct call per selector.

This is a plausible repeated-work reduction with a clear falsifier: inspect whether all five real selectors produce the nine expected raw-bit cells, confirm complete existing outputs, and compare the same frozen ray workload before/after. It could be insufficient if table calls dominate or the remaining loop work overwhelms selector branches. No new speedup estimate is supported yet. Multi-column sharing, radius precomputation, and loop-invariant geometry hoisting are possible follow-ups, but would require distinct proofs of evaluation order and float-rounding equivalence. Reassociating the intersection algebra is not part of this proposal.

Evidence inputs and prototype files are pinned in the specialization manifest. All observations here are source/offline reads; target qualification belongs to the parent agent's serial lane.
