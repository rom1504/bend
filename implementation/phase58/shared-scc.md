# Shared mutual-tail dispatchers

The checked `shared01` candidate replaces repeated mutual-tail switch bodies
with one private dispatcher per component. Its checked build and strict
36-case source gate pass. Both focused dispatcher controllers and genuine
new-source B2 emission now pass. A saved-image experiment establishes a large
static size reduction and a smaller API-load observation, but no later-request
speed gain. Broader qualification and release promotion remain separate gates.

The [isolated patch](../../selfhost/tools/performance/phase58/choices/shared-scc01/shared-scc.patch)
changes only direct `core.bend`. It adds 22 physical lines, 18 code lines and
three helpers (967 bytes) relative to reach01. The
[source accounting](source-complexity-shared.md) records 26,555 physical lines,
21,819 code lines, 3,054 definitions and 108 manifest modules for the complete
candidate. Both runtimes, driver and all 17 native modules retain exact bytes.
The preserved reach01 accounting remains historical; no line-reduction claim
is made for this optimization.

## Mechanism and dependency closure

Previously `jd_definition_loop` emitted an identical complete component switch
inside every named component entry. Literal-choice lowering exposes additional
source tail edges, making this replication expensive. After the independent
per-definition dependency deduplication resolved the queue refusal, the full
reach01 image was 8,671,962 bytes, including 8,250,025 bytes of definitions.

`jd_component_definition` chooses the existing first member as leader.
`jd_component_shared` emits one private `leader$scc` function taking an initial
PC and the maximum-width positional arguments. Every original named entry
remains, with its original maximum-width formal list and a fixed-PC call to
that worker. The private suffix cannot be generated by the source-name encoder.
Singleton loops and native/Foreign definition paths remain unchanged.

The worker retains the existing case order, case-local source bindings, ordered
argument captures and parallel stores. Tail transitions remain loop transitions.
Each dispatcher invocation owns its parameters and PC, including nested non-tail
calls and callback reentry; no shared global argument or return storage is added.
The extra entry call may affect inlining or runtime constants, so smaller output
alone is insufficient evidence of faster programs.

Each wrapper emits a `JD_REF` to its real source leader. The leader explicitly
marks every component member before the unchanged loop body. Thus an emitted
reachability root reaching only the leader still retains the complete component;
recomputing call facts after filtering cannot silently change its member order
or PC assignments. The synthetic worker is not a source dependency name. The
4,096-definition, 65,536 queued-dependency and 2,097,152-character scan limits
are unchanged by sharing.

## Exact saved-image experiment

The data-only census found 133 exact loop-body groups across 437 named entries.
It required complete dense entry PCs, equal formal lists, identical loop bytes,
collision-free worker names, an unchanged runtime prefix, successful reparsing
and exact inversion to the full parent module. It never imported the target.

| Largest duplicated group | Entries | One loop body, bytes | Net bytes saved in v2 |
| --- | ---: | ---: | ---: |
| `f_context_publish` | 34 | 70,138 | 2,309,617 |
| `f_context_grow` | 19 | 29,354 | 525,892 |
| `norm_cmp_loop` | 13 | 28,675 | 342,231 |
| `g_eval` | 12 | 26,816 | 293,562 |

The v2 derivative includes the complete-member dependency comments used by the
source patch: **8,671,962 → 3,812,483 bytes**, a reduction of 4,859,479 bytes
(56.04%). The earlier v1 census without those additional comments is preserved
separately. These are file-byte measurements, not dynamic allocation counts.

The one-round lexer pilot used the original reach01 B2 and this syntax-only
derivative, both implementing the same frozen Bend source. Private Base disk
caches were primed outside the sample. Each role then ran in a fresh process.
Both produced the same 28,388-byte lexer module and passed its catalog oracle.

| Observation, milliseconds | Original B2 | Shared-body diagnostic |
| --- | ---: | ---: |
| Ordinary API load | 174.890 | 95.616 |
| Host import + API load + first request | 1,534.840 | 1,477.522 |
| First request alone | 1,355.766 | 1,377.641 |
| Sole later request | 749.915 | 750.518 |

There is one observation per role, not a steady-state estimate or statistical
speedup. The later request is effectively flat in this pilot. The reduction in
API-load time is consistent with less compiler code to load, but this experiment
does not isolate parsing, JIT work or memory effects. It also does not measure
the new Bend emitter's compiler cost: that source was not changed inside the
saved-image derivative.

The genuine `checked-shared01` source then emitted its own complete B2 in the
separate `final-shared01/bootstrap/full` run: **3,815,480 bytes**, with
3,393,116 definition bytes and 409,081 export bytes. This is a newly compiled
source image, distinct from the 3,812,483-byte saved-image derivative. Its
source SHA is `a4ad6717934a8596c6bf707ecabf11346f57ca5b4e4e08cdcbdaac7921546d9a`;
the emitted image SHA is
`b7c5752d66ae4eaa8619e06b5a12655b370fba9d745d223660fbbb73da68fec8`.
The selected closure has 3,093 definitions / 3,207 entries.

The instrumented full-emission worker records 75.638 seconds overall, including
13.939 seconds for emitted reachability and 7.694 seconds for definitions.
The earlier reach01 run recorded 104.416, 32.411 and 17.837 seconds respectively.
These are single diagnostic runs over different compiler sources, with stage
forcing/progress overhead; they are not a controlled steady-throughput speedup.
The emitted size and completed bounded pipeline are direct observations.

## Focused qualification and preserved failure

The original literal-choice source and catalog remain unchanged. The shared
controller preserves 36 value/error oracles and nine host observations, with
100,000-step self/mutual tails on the default Node stack. The mutual `orbit.a`
and `orbit.b` source entries already have unequal live arities (two and three).
AST checks now follow their wrappers into one shared worker and require exact
old loop bytes, unchanged maximum-width entries, fixed PCs and complete refs.

The first `controls-v3` run passed all 36 catalog observations and all nine host
observations per role, then failed an AST assertion: Acorn arrays created in a
VM context retained a different prototype from the locally constructed expected
array. The failure remains at `shared-choice-controls01/report.json`; it is not
counted as a passing controller. `controls-v4` copies compared AST arrays with
host `Array.from`, checks their Identifier nodes explicitly, and preserves all
semantic and structural expectations. No compiler source changed for this fix.
The fresh `shared-choice-controls02` v4 run passes all 36 oracles, nine host
observations per role, eight AST checks and the shared-component assertions.
Its controller duration is 9.184 seconds (9.748 seconds under the supervisor).

The separate supplemental source covers active-dispatcher callback reentry,
sentinel identity, replay after throw, partial entry, fresh lexical captures
across 100,000 iterations, and terminal unknown-closure tails. The same source
is compiled as a library and a program whose sole root calls the relay leader.
Its `shared-scc-controls02` run passes nine library oracles, 12 host observations
per role, one program oracle across three roles, and three exact component-shape
checks in 8.410 controller seconds. The initial supplemental run had already
passed all library/host observations, then its first child-process launch failed
with sandbox `spawnSync EPERM`. That environment execution failure remains at
`shared-scc-controls01`; no source or controller change was made for the fresh
successful run. Acquisition acceptance remains distinct from execution and AST
qualification, and neither failed controller is pooled into the passing counts.

Commands are in the [focused recipe](../../selfhost/tools/performance/phase58/choices/shared-scc01/controls.md).
Broader semantics, compiler self-check/reproduction and program timing must
refer to their own completed receipts before they can be credited here.
