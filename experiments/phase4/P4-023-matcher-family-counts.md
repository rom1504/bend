# P4-023: exact private-image matcher family counts

Status: planned, before execution. Root authorizes one diagnostic after the scheduler reservation is released (expected around 19:15 UTC). No production or canonical private-image mutation.

The [typed-worker proposal](../../design/phase4/next_compiler_lowering.md) identifies `subst_node`, `subst_terms`, `ka_defs_except`, `tele_check` and `ka_args` as functions whose emitted applications cross a matcher boundary. The final residual profile attributes 28.16% of exclusive private-image samples to generic `apply`, but does not establish that this particular family accounts for a useful fraction. This experiment counts actual family entries and staged runtime applications before any worker rewrite.

Use exact private image `4318bbcdb2040ad794387b1466b0bafbe12233e67983224c5a564d13fa5753a3`, frozen final source `34c6ef63…`, the same 60,909-byte core fixture, host, canonical Base and runtime as P4-022. Whole-image and individual emitted-body hashes guard every insertion. Insert counters into the three applicable positional worker entries, tag the five original function/matcher entries and their syntactically nested generated matcher/arm records in a WeakMap, and count generic `apply` exact/under/overapplication plus actual partial-record creation. The underapplication result inherits its diagnostic family tag; ordinary execution logic is unchanged. Counts from Base preparation and discovery remain separate from the checked compilation request and its top-level phases.

No wrapping or reordering of argument expressions, matcher selection, project calls, function bodies, force/build continuations or errors is permitted. Diagnostic WeakMaps/counters are outside the public compiler ABI. The instrumented image is disposable and does not carry a fabricated production manifest. This gate only establishes exact behavior on the selected finite compiler workload; it is not a general public-function equivalence proof.

Run one fresh process on CPU3, Node 24.18.0, stack 4 MiB, heap 3 GiB, hard process-group deadline 90 seconds. Require checked successful library output SHA `016a5cedeb7e285adeabdad19388d99d3d9070668c15776ccc10fab8ea7b7186` and every original consumed input unchanged. Preserve any timeout/failure and stop rather than expanding to a full source profile. A minimal in-image arithmetic fixture will check that partial tags propagate and matcher applications are counted, without executing a compiler before the CPU release.

Report actual tagged versus total generic applications, matcher entries, arm underapplications/partial records, and positional worker entries by phase. These counts are not bytes allocated, samples, time saved, unique source calls or a speedup ceiling. Nil-to-Con fallback adds a second matcher application and must remain visible rather than counted as another source entry. Related optimized `*_cached`/`*_static` functions are initially outside the five-name family; zero or small entries can therefore falsify this narrow candidate without claiming that all telescope work is absent. No semantic lowering follows automatically from a high count.

Stop before a semantic prototype if the exact guarded sites do not match, output/provenance fails, or attribution would require changing the scheduler or compiler algorithms. Root owns selection of any follow-up; this task supplies counts only.
