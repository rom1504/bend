# Can the second generic-body verification disappear?

Yes, but the final omitted-owner obligations must remain. The optional
`selfhost/tests/phase164/hybrid-retained.bend` implements this separate candidate
from the broadened admission snapshot. Do not include it in a base acquisition
by a wildcard; it overrides the private successful-open continuation
`p164h_functions`. This note does not qualify or promote that candidate.

## Current source evidence

The first mixed verification authenticates the actual generic segments,
adapter bodies, static image and original catalogues. The following route then
changes direct functions and constructor hot flags, not generic instructions:

| Route | Original field treatment |
| --- | --- |
| `checked-boundary.bend:p114s_commit` | Reuses `original` and `ids`; accepts only a replacement direct-function list. |
| `retained-context.bend:p146c_finish` | Closes that exact boundary before the retained-context direct verification. |
| `prepared-context.bend:p128raw_prepare` | Either returns the admitted input or enters the borrowed/cold route. |
| `prepared-context.bend:p128raw_br_scanned` | The only original mutation is the existing request-derived cold-constructor pass. |
| `ownership.bend:p118c_apply_verified` | Reconstructs the static program with the same segments, descriptors and nodes; changes only constructor records. |
| `ownership.bend:p118ns_ctors` | Preserves constructor order, names and arities; derives the `hot` Boolean. |
| `prepared-context.bend:p128raw_br_compose`, `p128raw_close` | Reuses static and certificate fields; merges/replaces only direct functions. |
| `representation-boundaries.bend:p131p_close`, `p131p_complete` | Carries the same static program; applies patches only to direct functions. |
| `ownership.bend:p118b_compose` | Reuses original program and nodes; replaces direct functions. |
| `product-composition.bend:p126bp_complete` | Packages that actual static program with the final direct functions and unchanged certificate. |

`p128br_apply` itself has a direct-function-list input/output type. The generic
segment and static-node values are immutable Bend data. No code in this route
rewrites their bodies. The constructor transformation does not alter the
identity/arity schema used by generic and static verification.

## Stronger interface than trusting a Boolean

A bounded candidate can retain the checked static program at the successful
mixed-open continuation. After the late optimizer returns, extract only its
final direct functions and constructor hot flags. Reconstruct the actual
emitted original from the retained segments, static nodes and descriptors.
Check final constructor names, arities and order against the retained catalogue
before adopting its hot flags. Retain the original request-derived array
certificate; do not accept a replacement certificate from a loose caller.

This makes the emitted generic instructions equal by construction to the ones
already verified. It does not need pointer identity, hashes, a full structural
comparison or a second full generic verifier pass. Constructor hot authority
continues to come only from the existing checked, same-request cold pass—not
from arbitrary flags supplied by an external API.

The final gate still checks every omitted owner against the final signatures,
and independently checks every final direct body including projected borrowed
helpers and array/transport namespaces. A removed worker, signature change or
malformed final direct body therefore remains a refusal. The cheap constructor
schema check catches a future pass changing identity/order under the retained
generic/static references.

Keep this retained continuation private to the successful mixed-open path.
A publicly supplied `valid=True` or a context fabricated by host code is not
evidence. In this experiment the checked request API remains the only authority;
internal finite malformed controls should exercise missing workers, swapped
constructor order and altered arities. A source-level preservation control
should compare complete current-pipeline output with the retained result.

The base broad-discovery candidate still repeats the full original check.
The optional retained continuation reconstructs the output from the original
generic/static fields and certificate, discarding those fields of the returned
late plan. It still scans retained headers (not bodies), checks constructor
schema, all owner obligations and every final direct body. The late plan's
certificate is never authority. Cold hot-bit authority remains the existing
internal request-derived pipeline, not this helper's independently callable
data signature. These helpers are not acquisition API exports.

Any saving must be measured separately, including the lifetime cost of retaining
original data, disposing of the late carrier and the final direct checks.
Compare exact emitted QBE to the base candidate before native timing. Finite
controls should also show that a substituted late generic body/static image or
array certificate cannot change what the retained original authorizes, while
changed constructor identity/order/arity and a missing final worker are refused.
