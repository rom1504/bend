# Phase136 cold baseline and bounded query diagnostics

`plan-v01.py` freezes the qualified Phase134 N2 ordinary compiler, its exact
source/qualification/runtime, fixed historical Phase131 compiler input, complete
independent107MB QBE oracle, and the existing Phase134 monolithic pipe builder.
It only prepares metadata; the coordinator runs the recorded guarded command.

Cold means fresh ordinary source compilation with no retained edit/source/
optimizer/object session state. Immutable compact prepared Base, the prebuilt
runtime and producer executable are explicit allowed inputs. OS caches are not
flushed. Their acquisition is not part of this measured source-to-executable
request. Complete outer guard wall is primary; emit and QBE overlap and must not
be added. Assembly/link are nested later stages. No new backend framework exists.

`prepare-query-v02.py` appends `query-counts-v02.bend` without overriding any
qualified declaration. The manifest names the exports for the ordinary checked
API gate. No diagnostic source is valid until that gate succeeds. The module
contains14 finite controls and logical counters for `f_find`, `lookup`,
`nc_ctor_owned` and its `nc_ctor_identity` consumer. Original results are checked
inside Bend. A delegated `BookCache` lookup is explicit unknown tree work, not
zero cost.

After source checking, `query-census-v02.mjs API_REPORT REFERENCE_JSON FRESH_OUT`
uses the three existing small source requests. It asks checked Bend for actual
source/erased KDef books,16/64/256-row prefix observations and the first16 actual
direct constructor names. All row selection, query semantics and instrumentation
remain Bend code. The host supplies files and serializes observations.

The query schedule is an intentional scaling stress, not the actual compiler's
observed call distribution. Diagnostic counters and independent value checks add
work; their elapsed time is diagnostic cost rather than an optimization speed
result. Connect any promising scan removal to native samples and an actual
caller before implementing it. No native image, full self-hosting or program
benchmark is needed to reject a bad query hypothesis.
