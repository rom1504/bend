# Independent static evidence-selection review

Reviewed `selfhost/tools/performance/phase40/select-execution.py` without running
targets or changing the selector. The intended operation reuses42 already
measured checked05 points whose complete emitted program bytes are identical
to checked06, and replaces three ray points with fresh checked06 measurements.
It is not a pooled comparison or a claim that all45 were freshly timed on06.

Positive boundaries: the selector requires complete successful old/fresh
summaries, exact45/three inventories, a shared explicit catalog, unchanged
baseline/TypeScript compiler identities, exact Node/harness/protocol/limits,
and per-point source/input and three-role emitted-byte identities. The complete
fresh preparation binds checked06 source/attempt/compiler/output receipts and
the serialization adapter. Ratios are copied with their original same-run
paired role observations; measurementApi and selectedApi remain distinct.
Rejected old ray rows remain preserved. Static inspection of the existing
final-candidate02 manifest independently confirms all three ray IDs have changed
candidate hashes, including both active-ray points that share one source module.

One concrete integrity gap needs attention before treating the selector as an
independent acceptance audit: it rehashes raw reports and summary inputs but
does not recompute the selected summary rows from the raw measured cases. An
altered or incorrectly constructed summary row can retain correct input hashes
and correct module identities yet carry wrong stats, ratios or paired samples.
The existence of the maintained summarizer hash in inputs records provenance;
it does not establish that the parsed row is that summarizer's actual result.
No incorrect row was found during this static review.

Small hardening: bind each selected row.report to its exact independent run-group
report and find exactly one raw case with the same ID, source/point and module
identities. Use the already-maintained run.summarize(samples,roles,rounds), require
its complete result to equal the raw case.summary, then require row.stats and
row.ratios to equal that recomputation. Reconstruct/compare paired values and
wins/losses from the same raw samples, plus reported ranges/drift. This closes
both accidental row/report misassociation and forged summary numeric fields
without executing targets or changing the comparison protocol. Preserve the
current selector if consumed; use a versioned successor for any correction.

The Nat-result source correction is a separate reviewed narrowing. Only the new
Nat-first component admission loses primitive scalar results. Existing ADT/List
structural folds retain scalar outputs; full purity, provenance, graph/backedge
and runtime-boundary proofs stay mandatory. Restoring previous ray bytes is
strong selection evidence, while current semantic owners and broader integration
still establish their own scopes. Byte identity licenses emitted-program timing
reuse; it does not transfer compiler-cost measurements, source-level proof
coverage or release installation status between images.

## Hardening reviewed before first selector consumption

The evidence owner implemented the narrow raw-row recomputation and report
association checks before root consumed the selector. Static review confirms
unique raw point/report membership, maintained summarize equality, complete
three-role sample/module/config/Node observations, exact paired round+role
reconstruction and wins/ties/losses, ranges/drift and numeric changes. Additional
checks bind moduleChanged, byte deltas and partition to the verified modules and
catalog. No remaining material acceptance issue was found in this reviewed delta.

The original campaign deliberately uses600second presets for historical and
variation groups, and300second presets for development/holdout. Their protocols
are now retained per selected row. Only each fresh ray replacement must match
its corresponding old point's protocol; harness, Node and resource limits remain
equal across all groups. This preserves existing per-point comparisons without
pooling or claiming one uniform warmup across45 points. Numerical rehashing is
read-only evidence validation, not another target execution or a new timing run.
Root still must execute the selector against the fresh replacement summary and
make performance/release decisions separately.
