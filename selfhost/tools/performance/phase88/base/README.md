# Private prepared Base prototype

This directory contains **experimental source**. Root checked the standalone
decoder control and both raw JS and native C returned `True{}` for all16 cases
(`cache-control03`). Root's `cache-products01` also proves complete decoded,
source-cache and freshly prepared products equal on the checked JS derivative.
The final native startup gate now measures58–59ms; see the
[phase report](../../../../../implementation/phase88/README.md). This does not grant public checker
permission. Root runs all compiler/native targets serially under the existing guard.

`inspect-cache.mjs` inspects an existing artifact using only the transport codec.
`carrier.mjs` converts an externally pinned, existing checked B2 artifact into
decimal records and length-prefixed strings. Neither imports a compiler image.
`decoder.bend` reconstructs exact named Data in Bend, using owned Arrays for
backward references. Native runtime layouts and constructor IDs never appear.

## First gate

`fixtures03/controls.bend` is the first passing version, generated by:

```sh
node selfhost/tools/performance/phase88/base/fixtures.mjs NEW_DIRECTORY
```

It is a complete small Bend source, carrying the exact six production Data
declarations it needs, the decoder and16 controls. `fixtures.json` pins input
bytes. Check/emit it with pinned upstream using the Phase87 small-control method;
run raw JS and native C. The expected native Bool spelling is `True{}`. No full
compiler acquisition is needed. Preserve every failed check/run; generate a new
fixture directory after a source correction rather than overwriting frozen input.

The first attempt (`fixtures01`) failed the parser's binder-order rule. The
second (`fixtures02`) failed list-pattern syntax. Both remain preserved with
root's failed acquisition reports. The current decoder fixes those syntax
issues using helper functions and explicit Con patterns; no acceptance rule
was removed to make the control pass.

The positive checks the complete small products including all term/definition
fields and all world/index lists. It covers shared graph references, Unicode
`λ🙂`, and U32_MAX. Negative cases cover invalid tag/width/reference kind,
forward reference, invalid Bool/readiness/span/root, count/number overflow,
leading zeros, wrong stamp, truncation/trailing bytes and a Unicode length
mismatch. This fixture is synthetic shape data, not proof of a checked Base.

## Carrier generation

```text
node carrier.mjs CACHE EXPECTED_CACHE_SHA API_IMAGE BASE_FILE NEW_DIRECTORY
```

Use the exact cache and pin recorded in
[`implementation/phase88/base.md`](../../../../../implementation/phase88/base.md).
The producer API is
`selfhost/build/phase82/compiler04-b2/full/compiler.mjs`; Base is the canonical
`selfhost/.bootstrap/upstream-phase66/bend2/base.bend`. The serializer verifies
their bytes against the existing cache header. It also checks both segment
hashes, versions/producer labels, constructor shape through the existing codec,
root readiness, and the world-prefix/state aliases. It writes `base.p88` and
`receipt.json` into a fresh directory. Generation is serialization, not native
checking or native self-reproduction.

The receipt gives exact carrier hash/size, input pins, a stamp bound to the
producer/Base/path/interval/schema, and the consumer-admission limitation.
Before launching a native target, the harness must authenticate that complete
carrier and bind the exact native consumer image. A self-declared stamp/hash
inside an attacker-controlled file does not make it trusted. Root must compare
against actual native preparation before admitting this cross-host artifact.

## Native entry integration after the small gate

`entry-cache.bend` is a frozen composition of the decoder and a copy of the new
Phase88 live entry. `entry-cache.bend.json` pins both sources and the generator.
`make-entry.mjs NEW_FILENAME` can compose a later candidate without overwriting
this one. Six arguments after the executable keep the live preparation mode;
adding `CACHE STAMP` selects the private prepared mode. Cache file reading and
decoding are inside `base_prepare_ms`; failures refuse instead of falling back.

The full carrier was generated offline into `carrier01/`:1,100,924bytes,
SHA256 `07af8cddb84820d861fc9f5d9475907754a64a9319de7d597c925149d8b186a7`.
Its receipt records47,662 nodes,884 strings and all producer/source pins. Keep
the payload with raw evidence if moving large generated artifacts out of this
method directory; regenerate the receipt before using a different path.

Acquire the cache entry in JS-only mode first, then apply the existing equality
derivative. Run the full-product gate under the serial target guard:

```text
node selfhost/tools/performance/phase88/base/compare-products.mjs \
  BUILD/report.json COMPAT/derivation.json CARRIER/receipt.json NEW_PRODUCTS
```

The harness verifies the checked build and exact permitted JS derivative,
replaces only its IO footer with pure exports, and forces all exported calls
through `run_loop`. It compares complete decoded products against the source
cache, fresh preparation against that cache, and the complete cached/live seeds.
It also exercises full-payload stamp, truncation and trailing-byte refusals.
These diagnostics are not native timings. Only proceed to a full native build
after their complete report passes.

That report now passes:88,575/120,669/125,089 object pairs and
221,911/313,958/318,383 scalar checks across the three complete comparisons.
Wrong-stamp, truncated and trailing full payloads refuse. The
[report and read-only review](../../../../../implementation/phase88/base.md)
describe the external trust boundary and resource limits; notably, the decoder
does not prove semantic readiness from arbitrary user-provided graph bytes.

Append `decoder.bend` after the compiler modules; keep Phase86 `P86Seed` and
located Base source construction. Read the carrier through the existing bounded
file reader and call:

```bend
p88_decode_admitted(carrier_text, expected_stamp, 1, 75066)
```

On `P88DecodeReady{P88Products{book,fresh,ready,world}}`, construct
`P86Seed{located_base_source,book,fresh,ready,world}`. Treat
`P88DecodeError{error}` as a refusal or deliberate live-preparation fallback;
never partially consume a failed decoder result. Do not suppress ordinary
request checking/reporting. Test wrong Base/path/producer identities in the
admission wrapper, not merely in the shape decoder.

For correctness, first expose products in a checked JS control and compare
the complete book/fresh/frontend/world Data to the source cache and to fresh
`p86_prepare`. Then require exact complete generated C/verdicts in live versus
prepared native modes. Source-span diagnostics and Map remain part of admission.

Measure carrier I/O, decode including temporary-table destruction, first
request, whole process and peak RSS. The text transport is intentionally simple
and not yet optimized: file reading creates native SCon nodes; each materialized
field uses a small temporary typed wrapper; Arrays retain nodes until the roots
are extracted. It may lose to live preparation. That result would reject this
transport, not prove that immutable prepared native Data is ineffective.

The decoder caps65,536 records,4,096 strings,1Mi Unicode scalars per string and
uses only enough power-of-two Array capacity for the declared counts. It checks
bounds before `Array.get`, because that primitive masks indexes. The caller's
16MiB file cap is part of the private interface. No closure-valued payload or
generic runtime term can be decoded.
