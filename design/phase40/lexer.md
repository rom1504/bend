# Phase40 lexer component (prospective saved output)

Hypothesis: replacing the classification/step/lex continuation dispatch inside
one manually audited owned scalar benchmark scope improves lexer execution,
while preserving each materialized Cls, Mode and native Sigma tuple. The line
producer and balanced batch remain generic; no fusion or source admission claim.

The current compiler proof excludes String/Char/Sigma. The experiment therefore
uses a clearly separate diagnostic `privateBench` export: snapshot exact source
functions and metadata, existing host obligations, String prototype descriptors
and native string methods; refuse mutated dependencies/hosts and reentry. Enter
one synchronous private flag without opening the compiler regionProof. Only
owned outputs of pristine gen and tuple construction reach direct continuations.
Ordinary public exports remain generic outside this manual export.

Ablations: unchanged/noise; guard-only; classification-only; step-only; full lex
plus step. Step preserves full tagged Mode and Tuple array, and classification
constructs a tagged Cls. Lex follows existing SNil/SCon/Chr/Tuple demand ordering
via runtime fields/project, then completes each step before its next character.
Flush is separate and runs only after the input ends. Keep complete input strings.

Controls before timing: independent lexical token fold and complete transition
trace, all12 Mode×Cls combinations, boundary U32s, Unicode including astral and
lone surrogates, blank/identifier/number/mixed lines, direct component admission
counters, mutation/getter/reentry/throw fallback observations, deep line stack.
Do not accept scalar benchmark checksum alone as component correctness evidence.

Root runs all jobs serially. Budget30–45minutes for prototype/control handoff;
20second small-input rejection then60second historical screen, unchanged-byte
noise in both. Abandon weak gains before widening compiler purity. Broad native
container proof is a separate proposal requiring explicit scalar/owned provenance.
