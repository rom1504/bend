Static review accepts the proposed request-local cache for the canonical,
immutable checked JS emission path, subject to the fresh checked03 controls and
actual generated-module identity gates. No execution or performance result is
claimed. No production files changed during this review.

The BookCache extension preserves its original first source-index child and
the original definition-list tail. All source lookup routes through
index_lookup/index_first, so the second child cannot become a declaration,
constructor or shadowing `$js.plans` binding. The maximum binder ID remains the
cache's unchanged arity. The new payload is a private tagged KDef with two
independent existing Patricia indexes, whose lookup checks the complete name
inside same-hash buckets. Component/direct keys cannot collide with one another.

book_put constructs a fresh BookCache with exactly the updated source-index
child and no second payload, so definition insertion/replacement invalidates
all prior facts. j_plan_context also strips any existing payload before
preparing each request. It computes facts against that stripped source context,
then creates a new payload; there is no process-global table, mutable API cache
or inherited previous-request selection. Concurrent requests cannot share newly
created payloads through this code. Canonical source objects and their index
may be shared because source KDefs are immutable during synchronous emission.

j_plan_fact stores the exact complete ordered JPure defs, remaining fuel and
valid flag. Retrieval reconstructs those three fields without sorting,
re-proving, reducing a refused graph or replacing a negative fact with an
admission. The logical component and direct planners are unchanged, including
typed graph validation, closed/backedge checks, fuel/depth/size bounds,
wrapper selection and failure behavior. The candidate only replaces calls
whose roots already come from canonical lookup. Nested wrapper graph callees
are canonical source lookups; arbitrary same-name logical root definitions do
not acquire a name-only root cache lookup. Recursive roots bypass acyclic
wrapper selection, while acyclic roots can cache only independently recursive
canonical callees.

The discovery scan's8192 fuel limits only the direct-plan candidates retained.
Each missing component/direct fact invokes the original logical planner on the
current canonical source lookup. Component precomputation uses the same
Def/non-template/non-Absent/non-Foreign condition as ordinary j_def, and
j_l_def already plans its canonical lookup rather than the selected lowering
object. Duplicate selected names therefore share exactly that canonical plan.
Primitive and unsaturated discovery refusals remove reuse only; all original
emitter admission/guard checks still run. Neither emitted runtime/IR nor
generated guard/proof cleanup code changes. Identical returned plans should
produce identical generated bytes; this remains an executable gate.

The cache changes compiler analysis demand timing by preparing plans before
ordinary emission. This review's equivalence scope is canonical checked books,
not arbitrary malformed/getter-backed compiler ASTs or forged BookCache
payloads. In particular a missing canonical lookup has empty dn, so replacing
that missing object's planner with a lookup-by-dn could select a separately
supplied empty-name definition in a malformed book. Checked declarations and
resolved calls exclude this situation. No universal low-level raw-API error
order claim follows. Source mutation through an external JS alias during a
compiler helper call likewise violates the request's immutable-source premise.

The facts controls inspect private metadata/source-index/rest identity, exact
positive direct and negative component round trips, arbitrary same-name
logical roots, source replacement invalidation, discovery exhaustion, fresh
request replacement, and a nonempty refused graph/fuel encoding. They append
diagnostic exports to the actual checked API and preserve its complete byte
prefix. They do not test positive recursive-component cached admission or
actual generated-module execution by themselves; inherited actual tree,
wrapper, component/direct/finite controls and module-identity checks remain
required.
