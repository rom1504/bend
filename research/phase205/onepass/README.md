# Optional checked native one-pass split/join

Status: staged source, no checker or target execution by this agent. `wire.py:apply(src)` preserves every existing declaration and installs two modules; it changes only the no-repeat-edits branch of `p205_ready`. Successful repeat-hoist edits take their unchanged original path. The wire rejects an unexpected branch shape or a second installation.

The pass scans the selected definitions' raw bodies, including pure String consumers nested inside IO bodies. It accepts only a complete direct application `join(separator,split(delimiter,input))`. Resolved definitions must pass all the existing exact split/join/join-rest/pick/push/append equations and the independent U32 equality primitive guard. Append must resolve to the canonical, equation-verified `String.append`. Separator and delimiter must be already evaluated variables or literals. This version does not eliminate a bound split list, so observing an aliased list cannot be silently removed. It does not cross an effect boundary or alter any producer; the input expression is passed once to the helper.

On the first real admission, the pass builds two ordinary KDefs equivalent to `phase200/text/replace.bend`: a Bool-driven emission helper and a structurally recursive String replacement. They are not runtime intrinsics. Binder IDs occupy fresh slots above the source context's bound, and both generated declaration names include that bound. Either name collision or insufficient U32 headroom refuses the phase. The cached context bound is explicitly advanced with `kw_bound_book` after insertion; retaining the old BookCache bound would be unsafe.

Both generated signatures and bodies are checked with `check_definition_world` in the augmented original context. Checked bodies are annotated normally. Every changed original definition is rechecked in that context. The final layout/closure gate sees both generated helpers and every changed selected definition. Both the context and the annotated argument handed to `nr_prepare_annotated` contain the new helpers; adding them to the annotation list alone would lose them when the native request merges source definitions. Any helper check, changed-body check or final layout failure returns the original context and annotated list. No admission adds no helper at all.

Generated helper quantities mirror the checked source: replacement's separator and delimiter are unrestricted; input is consumed once. Its character word is made unrestricted by a local let before use in both equality and emission. The Bool helper consumes separator/word/rest affinely in each mutually exclusive branch. The real checker, not this explanation, is the final arbiter of typed construction and termination.

Suggested validation before portfolio inclusion: standalone complete compiler source checking; direct `p205o_prepare` against a real checked Base context; original/candidate full-output controls on alias, boundary and packet fixtures; actual decoded helper calls; no-admission/negative objects unchanged; forced helper-name collision refusal; fresh-ID bound exhaustion refusal. ## Cheap request prefilter

Before scanning bodies or computing a fresh bound, the optional phase counts selected reachable definitions, stopping after 1,025 and refusing requests above 1,024. It then scans only their signatures, requiring at least one non-native, non-template exact `U32 -> String -> List<&2,String>` function and one exact `String -> List<&2,String> -> String` function. It stops immediately once both are found. Missing either signature returns the untouched native preparation path. These are conservative cost/coverage restrictions, not semantic certificates or benchmark-name tests; the complete equation graph is still checked for each actual candidate. Large compiler self-build requests therefore avoid the whole-body transformation walk.
