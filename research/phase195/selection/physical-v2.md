# Physical predicate/select v2

This independent candidate overrides only `x194_ps_emit`; start from Phase194 final source without v1's `x191_placement` hook. It retains the exact original matcher, whole-function admission certificate, allocation, frame homes, comparison width and result width. `x195_pm_enabled()` is the ablation toggle; false calls the exact original emitter body under a renamed helper.

CMP uses existing physical input homes when available and reserved R10/R11 only otherwise. Existing checked immediate selection handles representable constants. Comparison happens before any destination change. Selected result goes into the first destination's existing physical home, or reserved R11 when stack-resident. If that home already holds the true choice, the condition is inverted and the false choice becomes the CMOV source; otherwise initializing the false choice cannot destroy the true input. Every subsequent destination receives the same computed value. Register-to-identical-register publications can be omitted because that register already holds the result.

The CMOV source can be a register or an allocated frame word. Both original choice loads were unconditional, so a conditional-move memory source does not introduce an unvalidated memory read; no heap load or effect is moved. Constants/buffer addresses use reserved RAX. MOV/MOVL/LEA between CMP and CMOV preserve flags. U32 initialization explicitly truncates and clears high bits even when a conditional move is not taken; U64 uses full words. Independently mixed comparison/result widths remain supported. Zero/one alternatives use SETcc and MOVZX after CMP, publishing an exact full-word Boolean without two 64-bit immediate snapshots.

Offline encoder review confirms `selfhost/src/back/x86/object-encode.bend:x191cm_pair` already accepts both 32/64-bit register-or-memory CMOV sources through `x187_e_rm`, with a register destination and the existing ModRM path. No new encoder operation is introduced. Physical CMP input selection follows the same reserved-scratch convention already used by `x191_address_code`; immediate selection reuses `x190_branch_immediate_to` unchanged.

The concrete current row still emits six avoidable compare-input MOVs across three predicates, in-place min results copied through RAX/R11, and constant Boolean CMOVs. V2 targets these exact patterns, with a static expectation of roughly 10–12 fewer instructions under the same allocation; this is a falsifiable code-shape expectation, not a runtime forecast. Actual emitted code and independent output observations must decide it.

Controls: include Phase194 `predicate-controls-v3.bend`, unchanged Phase195 selection `controls.bend`, and `physical-controls-v2.bend`. The new driver defaults to two groups: forty signed/unsigned U32/U64 Boolean-output functions (4840 edge-pair observations per route), and eight mixed-width/inversion/high-pressure/old-value functions (968 per route). Also run existing Phase194 predicate driver for 7260 full-word choices and stress-v2 for repeated/protected/fuel/escape cases. Both direct and rendered routes share typed selection; independent C observers define values. API exports add `p195pm_controls`, `p195pm_emit`, `p195pm_pressure_controls`, `p195pm_pressure_emit`; usual compiler/encoder roots stay unchanged. Source checking, targets and runtime are root-owned; no such execution was performed in authoring.
