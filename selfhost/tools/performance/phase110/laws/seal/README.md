# Stored-field seal omission model

All four laws passed safe source checking, BendTT emission and the independent
Lean kernel in [check01](../../../../../../selfhost/build/phase98/phase110-seal-check01/report.json).
All three changed models passed standalone admission, then failed the intended
unchanged law in [mutants01](../../../../../../selfhost/build/phase98/phase110-seal-mutants01/report.json).
The accepted source is [seal-law-source01](../../../../../../selfhost/build/phase110/seal-law-source01/manifest.json).

This safe model characterizes the proposed omission of the retained field's
redundant `rfc_seal` in the private reconstruction fast path. It is separate
from the source-connected selector package. No C or Nx semantics is extracted
or independently verified by these laws.

`SealWord` distinguishes immediate/nonconstructor observations, raw constructor
words, and reference words. `seal_word_operation` leaves the first and third
classes unchanged. A raw constructor allocates one symbolic redirect with count
1 and returns its reference word. `SealState` records the next symbolic token and
the entire prior allocation ledger. The ledger makes unwanted extra wrapping
observable; a proof about just the payload could miss that effect.

The four laws specify:

1. A raw constructor gains exactly one count-1 redirect, with its complete word
   and allocation-state result specified independently by constructors.
2. The modeled constructor writer's seal establishes the stored representation:
   an immediate/nonconstructor or a reference, never a raw constructor.
3. Its resulting stored word is a seal fixed point in **any later allocation
   state**, accommodating the other field's sealing and intervening allocations.
4. Omitting only that retained word's reseal preserves both rebuilt fields,
   the remaining field and the complete allocator-state observation. The
   incoming other field is arbitrary and continues to be sealed.

The premise is generated by the modeled writer, rather than assuming an
equation that already states the desired fixed point. The final proof uses
congruence with the fixed-point lemma. It does not duplicate all representation
cases or introduce an opaque callback or a new axiom.

Three welltyped mutants skip initial raw sealing, wrap existing references
again, or omit the incoming other field's seal as well. They must first pass
law-free admission and then fail unchanged laws. The first anchor prevents a
wrong identity implementation from satisfying idempotence vacuously.

The independent package contains 40 definitions, none opaque, and 9,376 bytes
of BendTT, SHA-256
`a067bc4e5cfd6abe197721a80a78760bbb528bc28ebd00e2aea97dc86da8de5d`.
The kernel also rejected its independent false-equality control. The six mutant
admission/rejection subprocesses totaled 2.903 s of guarded wall time.

## Physical correspondence premise

The runtime source condition is `term_tag(t) != TAG_CTR || term_rfc(t)`: those
words are already fixed points of `rfc_seal`. Every admitted live dynamic
constructor payload writer must establish this condition. In the restricted
runtime closure, `nx_construct2`, direct specialized reconstruction and the
original private memory template seal both stored fields. The proposed template
omits only the retained field's redundant seal and preserves this invariant
inductively, provided its retained word came from a live admitted dynamic shell.

Static construction intentionally stores raw trivial children, which can include
static constructor words. A raw static constructor is still wrapped by
`rfc_seal`, so triviality alone is insufficient. The fast path must classify the
decoded parent shell as dynamic, including after following a count-1 redirect.
A redirect to static storage remains in fallback. A static child stored in a
dynamic parent was sealed by that dynamic writer, so its stored word is a
reference even though the target itself is static.

The ABI agent's source closure and native controls authenticate and test these
runtime obligations separately. The model does not prove pointer validity,
allocation freshness, bounded counter arithmetic, allocation success, the
dynamic-shell classifier, destruction invariants, concurrent mutation, machine
code, or the complete producer/consumer simulation. Existing live-object and
single-thread premises remain necessary. Sealing omission is not a retain
deletion: the shared-parent fallback still claims escaping child ownership.
