# Owning observer followed by a pure structural projection

This is an isolated successor to `depth-inline-source01`, not a change to the
frozen candidate or canonical modules. `prepare-v5.py` writes an exact reversible
source recipe. No compiler, image or target has run during initial preparation.

A readiness-only retry is insufficient: `nfo_admit` already revisits every worker
after early observer forwarding. Product signatures were filtered earlier, and
the existing product layout handles one fixed outer shell, not recursive result
flattening. The successful C experiment identifies a more specific composition:
the proved observer reconstructs immutable wrapper shells, then a consumer
immediately projects their scalar observation and discards their owned roots.

The new pass retains the existing route's actual `NOObserverEntry` certificate
through `nfo_finish`. It examines only already admitted ordinary workers with
one or two full-Term parameters and a one-Term result. The entire worker body
must be exactly a unary projection applied to an admitted observer call with
the same evaluated input variables in the same order. No application/function
name identifies the opportunity.

The projection's erased body is bounded to 256 nodes. A 32-step syntax machine
permits only lambda application and matches on the observer schema's known
constructor wrappers. Every consumed beta/match argument must be exactly a
subtree of the original immutable admitted schema wrapper, with a 32-node search
bound. Projector-created expressions cannot be discarded by substitution.
Matching an unknown root/scalar Var, a reference, primitive, foreign operation,
effect or other syntax refuses. Substitution has the existing 4096-node growth
limit. A structural scan rejects both Var occurrences and Lam binder IDs in the
reserved schema root/result range, including unused binders. The certificate
must reduce to the exact schema result variable.

The replacement reuses `no_adapter` with that selected scalar Var wrapper.
Its normal ownership environment drops the saved roots after the admitted
borrowed worker returns and after the existing post-call error check. Both
temporary shells disappear. The caller still takes owned Terms and returns one
owned Term; it adds no borrowed boundary. The original observer worker, adapter,
public names, unrelated callers and unsupported workers remain available. This
also preserves the existing observer macro/permission gates and constructor ABI.

Two earlier offline candidates are retained as rejected. Version 1 could drop
a projector-created effectful argument through beta substitution; version 2
fixed strictness but inherited an occurrence-only freshness check that missed
unused binders and allowed capture. Version 3 adds the explicit binder scan.
No target ran either rejected version. Version 4 makes only a grammar repair:
the computed adapter is passed to a named helper before matching its parameter.
The failed version-3 checked-API acquisition remains `projection-api01`.
The later `projection-api03` acquisition found that the identity-argument
predicate used `arg` twice without a reusable binding. Version 5 changes only
that pattern to `+arg`; the remaining helper formals and pattern binders were
audited for repeated use. `check-admission-v5.mjs` includes both
counterexample families and tests the freshness predicate separately.

No whole-compiler proof is claimed. The intended correspondence removes only
fresh immutable wrapper allocation/destruction and pure known projections.
Allocation failure timing changes because allocations disappear. Error-bearing
or effectful consumers are excluded; the selected scalar has already been
computed before any input root is disposed. Existing original candidate
readiness remains valid because replacement dependencies are already admitted.

First acquire the checked API, inspect actual emitted C activation, then use
the frozen complete projection controls and paired app comparison. Required
refusals include added effect/primitive, different root result, permuted or
duplicated call arguments, unknown-root matching, fresh-ID collision, excess
projection size/fuel and missing observer authority. Native-chain qualification
is separate and should follow only if the Bend implementation retains the gain.
