# What does rejecting a unique root cost?

The current Bend compiler already derives a pure scalar reader for selected source functions. Its adapter keeps all original owning roots through the reader call, then sinks each root exactly once. A separate runtime profitability guard selects the reader only when each root is trivial or shared with another owner, and rejects a pair of aliased reference-count locations. This prevents a full destruction walk immediately after traversal. The original audit explicitly identifies unique-root refusal as a profitability restriction. The generated owned worker is the alternative. [Admission and lifetime argument](../../../implementation/phase128/borrow-audit.md)

On immutable objects generated by the composed compiler, compare stock against three relinks. One delegates the same guard, one always chooses its already-generated reader, and one always chooses the owned implementation. Instrument a separate executable to count the original decisions by root arity. All other runtime calls and foreign visibility remain original. The test references the incumbent decision at **emitted call edges** only. Report a negative control when a program never reaches the adapter. None of these relinks changes the compiler or defines a new ABI rule. The measurement can indicate whether to invest in a compiler-side policy for particular verified reader shapes, including its destructor and lifetime costs.

Check outputs against mature Bend C at catalog and alternate points. Compare equal-position rounds and the delegating control to bound code-placement effects. Compare execution cost on mixed Map/string consumers, both short and long immutable inputs, and inspect reach. Do not infer that every one-word result or arbitrary reader can use this transformation. Retaining roots longer can change peak live memory and destruction cost.

## Results

The completed four-role relink found no case in this six-program screen where forcing all verified readers improved the median over stock. Forced-reader/stock time ratios were 1.0035 on Map/set, 1.0072 on Map32, 1.0000 on record aggregation, 1.1215 on Unicode, 1.0714 on generic edit row and 1.0520 on morning. The observed per-invocation guard deltas were refusals in all six. The forwarding control varied from 0.9791× to 1.0038×. The first attempt stopped early when its observer supplied a zero wall interval; the remeasurement passed complete-output checks and recorded the actual interval. Keep the current default.
