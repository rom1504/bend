# Phase66 final qualification methods

`make-method.py` materializes 16 methods from exact frozen parents. Its counted
derivation and the output manifest preserve historical source. It executes no
compiler or generated program. The materialized `qualification-method01` is
immutable; every subsequent attempt or correction needs a fresh directory.

`prepare-gates.py` writes root-run serial commands. It requires a strict passing
new-pin profile 7 attempt and fresh TypeScript acquisitions from the measurement
lane. The catalogs preserve every original fixture and oracle. Historical
TypeScript pass counts are never transferred to the new reference. The exact
historical signaling-NaN exception is conditional on observing that same failure
again; the candidate must still return the independent expected value.

From the repository root, after all reference acquisitions and the selected
attempt have closed:

```sh
taskset -c 0 python3 -B selfhost/tools/performance/phase66/bootstrap/qualification/prepare-gates.py checked --methods selfhost/build/phase66/qualification-method01 --attempt selfhost/build/phase66/checked-b1-04 --out selfhost/build/phase66/qualification04/checked --plan selfhost/build/phase66/qualification04/checked-plan.json
```

The checked plan has 13 serial commands: four acquisitions, a source role join,
four semantic controllers (96/34/18/2 observations), eight maintained suites,
45-point checked acquisition and smoke, and three native programs. Counts
overlap. Old/new C-byte equality is descriptive across the upstream ABI change;
both compilers must satisfy all three independent stdout oracles.

After genuine B2 emission, its complete tiny/driver gates and image pins exist,
prepare the `b2` stage with the same methods/attempt, plus `--image-pins` and
`--program-manifest` pointing to the selected checked 45-point acquisition.
Choose new `--out` and `--plan` paths. Its 11 serial commands cover fresh own-source
type checking, complete B2/B3 fixed-point equality, the four semantic acquisitions
and controllers, and exact B1/B2 bytes for all 23 runtime sources and 45 points.
Own-source type acceptance still includes the expected unsafe proof-trust
refusal; it is not a mathematical proof of the compiler.

Each target owns one resource guard (CPU3, Node24, 4 MiB stack, 1 GiB heap,
2 GiB process-tree RSS limit and 4 GiB available-memory floor). Launch plans with
the existing unpinned `phase55/run-retention-plan.py`; do not place that launcher
inside another target guard. Full upstream conformance, H2 permission controls,
compiler timing, generated-program timing, and release 42/24 checks remain
separate gates. These methods neither install a release nor admit reuse on the
basis of matching API bytes alone.

The final04 queue separates independent jobs to avoid waiting for semantic
references. `prepare-selfhosting.py` materializes the actual-B2 self-check and
fixed-point commands at `selfhosting04-plan.json`; both instantiate the reviewed
ordinary-driver setup with a fresh private cache. The measurement lane separately
qualifies the selected B1's complete 23-source/45-point program bundle and uses
the unchanged B2 byte-equality controller for that same bundle.

`prepare-semantic-gates.py` is an exact recorded projection of the full planner
for this queue. It emits the remaining checked 11 jobs (semantic matrix plus
maintained8/native3) or B2's eight semantic jobs. It does not repeat selfhosting
or program generation, and does not declare those external gates passed. Final
consolidation must still bind every closed receipt to the same selected source,
API, Base, runtime and host snapshot.
The selected release is now attempt07. Earlier 04/05/06 plans and failures remain
historical records. Its actual B2 image comes from `bootstrap-b2-07`; API identity
is not asserted between 05 and 07. `audit-selfhosting.py` joins the two fresh
selfhosting jobs and the existing 23-module/45-point B1/B2 program equality gate.
`audit-semantics-v2.py` binds the actual selected attempt, image pins, checked11
and B2 eight-job plans and their closed execution reports.

`join-final.py` consumes `qualification07/final-gates-plan-v2.json` only after all
11 required roles exist. It rehashes their inputs and requires strict36,
exports99, selfhosting, semantic matrices, upstream conformance, native admission,
owned/custom Base controls, complete compiler/program measurements, printable
controls, Min/wide source cases and private wide-field controls. Its output is
`implementation/phase66/evidence/compiler-qualification07.json`.

The conformance requirement is zero unexplained reference-pass candidate gaps
within the selected inventory, with shared failures, not-applicable cases and
runtime limits retained. The selected two/five-source reports intentionally have
whole-inventory `complete: false`; the join requires `selectedComplete: true`,
exact requested/result identities and all selected oracles passing. Compiler
latency and emitted-program runtime remain different measurements, and a complete
measurement need not show an improvement. This join does not install or grant
root release admission; preservation and installed 42/24/helper5 checks follow.
