# Phase182 completed-evidence promotion recipe

`selfhost/tests/phase182/prepare-release.py` consumes completed current-tool
receipts. It performs metadata and byte-identity validation, assembles the current
maintained source for comparison, copies small gate receipts, and calls the
unchanged `selfhost/tools/build/release.py` audit. It executes no compiler,
qualifier, kernel, runtime, or installation. A failed gate cannot be supplied as
a pass; no report status is rewritten. This note and example paths are a recipe,
not a claim that qualification or promotion has completed.

Start with `selfhost/tests/phase182/release-inputs.example.json`. Replace every
`REPLACE` path with an actual completed receipt or artifact. Paths may be
absolute or repository-relative. Freeze the previous installed selector before
installation. All of its installed files must still match while preparation runs;
its old source/providers are not used as current compilation authority.

The recipe's `canonical` must exactly equal current `sourceRecipe`/`sourceRoot`
assembly. Upstream must be `9a4223d577ba56a0cb53d1fd952d2b481c38930f` in the
maintained recipe, asset maps, checked B1, and finite qualification reports.
The required Base SHA256 is
`ff90fb27ed19d5c7a6165170f28ad81562bf345b9a9e6134e5c2e326beff9de4`.

`providers` maps six roles to asset keys in `assets`:

| Role | Example asset key | Bound use |
| --- | --- | --- |
| `base` | `base` | JS emission and packaged CLI Base |
| `jsLegacyRuntime` | `js-runtime` | Explicit current runtime provider |
| `jsDirectRuntime` | `js-direct-runtime` | Actual B2/B3 direct runtime |
| `cRuntime` | `c-runtime` | Packaged CLI linked/target runtime |
| `cRuntimeTemplate` | `c-runtime-template` | Fresh public runtime chunks |
| `qbeRuntime` | `qbe-runtime` | Actual N1/N2 linked runtime |

Add `js-direct-runtime` to the final asset map if absent, pointing at the exact
runtime pin in B2/B3 reports. Both native runtimes use `bend-rts-v1`.
`publicAssets` selects an asset manifest with the explicit `publicCliAssets`
mapping accepted by current `public-cli.py --assets`; it may be the same file as
`assets`. It must contain prepared decimal-Base and runtime-template receipts,
the same Base/runtime/template, and all nine current public effect assets. The
helper binds every public payload and records all declared C effect provider pins.

All fourteen `reports` keys are mandatory:

| Key | Actual report required |
| --- | --- |
| `qbeN1` | `bend-native-build`, N1, canonical source, selected QBE runtime |
| `qbeN2` | N2 actually generated by that N1; complete QBE matches N1 reference |
| `qbeQ3` | Actual N2 request emits canonical source, whole output equals N2 QBE |
| `qbeQualification` | Independent selected N2 `bend-finite-qualification`, QBE all64 |
| `jsB1` | Genuine `bend-checked-hosted-api`, checked canonical source/current upstream |
| `jsB2` | Genuine B1-generated B2, canonical source/current Base/direct runtime |
| `jsB3` | Actual B2 self-check/re-emission, type accepted and B3 bytes equal B2 |
| `jsQualification` | Independent selected B2 finite JS qualification |
| `jsCQualification` | Independent selected B2 finite C qualification |
| `jsPublic` | Current B2 public seven controls, unchanged cache |
| `cliProfile` | Current canonical-derived profile, only admitted main/effect-read seams |
| `cliPackage` | Actual C-built public CLI package `BUILD.json`; unchanged generated C |
| `cliControls` | Actual packaged image public CLI behavior/integrity/live-cache gate |
| `cliQualification` | Independent selected public CLI finite C qualification |

`qualificationCounts` explicitly declares the four finite-suite sizes. QBE is
64. The other counts describe the selected completed suites and are not required
to be 45. Example values 19 are placeholders: use the actual agreed focused set
and exact count. Count, unique selected IDs, passing row IDs, image, host, stage,
target, and upstream must agree. This does not expand the release gate scope.

Optional `extraGates` retain additional already-completed controls, such as
native9, direct ABI, or current-upstream comparisons. Each entry uses the existing
release schema, plus `components`:

```json
{
  "new-native-controls": {
    "report": "selfhost/build/phase182/actual-controls/report.json",
    "role": "qualification",
    "claims": {"passed": true},
    "bindings": {"image": {"bytes": 123, "sha256": "ACTUAL_REPORT_IMAGE_SHA256"}},
    "components": ["qbe"]
  }
}
```

Use actual field names and pin values from that report. The helper validates
every claim and binding; `release.audit` independently enforces all existing
mandatory gates. Supplemental evidence is not mandatory unless included in the
recipe. Qualification roles require a genuine true qualification status.

Run these commands from the repository root after the reports exist, choosing
fresh output paths. Root owns the resource lane and installation decision.

```sh
taskset -c 0 python3 -B selfhost/tests/phase182/prepare-release.py \
  --recipe selfhost/build/phase182/release-inputs.json \
  --out selfhost/build/phase182/release-proposal01

taskset -c 0 python3 -B selfhost/tools/build/release.py audit \
  --manifest selfhost/build/phase182/release-proposal01/promotion.json \
  --out selfhost/build/phase182/release-audit01.json

taskset -c 0 python3 -B selfhost/tools/build/release.py install \
  --manifest selfhost/build/phase182/release-proposal01/promotion.json \
  --out selfhost/build/phase182/release-install01

taskset -c 0 python3 -B selfhost/tools/build/release.py verify \
  --manifest selfhost/manifests/current.json
```

Preparation emits `promotion.json`, `audit.json`, `report.json`, small copied
evidence, the previous selector copy, and an operational native `BUILD.json`.
Preparation reports `installed: false`; installation is a separate operation.
The installer reaudits, stages with rollback, and publishes the selector last.
It installs exactly the three required components, Base, public assets, and
operational package metadata; no old hosted-QBE or session capability is silently
inherited. External provider pins remain explicit. Existing unrelated dist files
and compatibility manifests are not rewritten by the installer; root must decide
any separately qualified optional capabilities or compatibility refresh.
