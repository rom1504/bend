# Diagnostic transport and unrelated transfer source

The parent runs this under the existing guarded serial lane:

```sh
selfhost/.bootstrap/bun-1.4.3/bun \
  selfhost/tools/performance/phase126/specialization/inspect.mjs \
  selfhost/build/phase111/p126-table07-api/report.json \
  selfhost/build/phase126/table-source07/manifest.json \
  selfhost/build/phase126/table-inspect01
```

The transport authenticates the checked API/source pair, seven frozen selector modules, selected qualified Base/cache, and source/oracle inputs. It invokes the existing Bend `p88_cache_prepare` and `p86_plan` factories. It checks `p126s_projection_control`, exact `palette`/`words` cells, semantic `None` refusals for four unsupported ordinary definitions, and all five actual active-ray columns. The latter expected rows are identified as prior upstream corroboration, rather than an independent new oracle. It neither evaluates source semantics in the host nor constructs compiler IR.

`transfer/prepare.py` prepares a separate ordinary workload and mathematical oracle. It executes no compiler. `routing1024.bend` performs 1024 U32 LCG steps, choosing from an unrelated thirteen-cell U32 code table and eight-cell F32 weight table, then folding exact bit words with wraparound arithmetic. Inputs are `(17,99)` and the independent expected result is **1964461478**. Its timing wrapper is the existing Phase93 complete-result/count observer: two warmup and 2000 timed successes are required. `transfer/cases.json` describes this workload for normal emission/observation transport. It is a newly seen transfer fixture, outside original45, and is not a blind heldout.

`transfer/routing-ordinary.bend` prints the same full result once; `transfer/ordinary-cases.json` uses the existing `{status,stdout,stderr}` functional schema for a cheap qualification before timing. Both forms share the same source computation. The oracle uses fixed independent word/IEEE bit tables and a 1024-step integer recurrence; there is no benchmark-name specialization in production code.

Preparation was executed offline to write/pin source and oracle files. The checked diagnostic and generated targets were not executed by this subagent. The existing frozen v1 modules and inventory were not changed.
