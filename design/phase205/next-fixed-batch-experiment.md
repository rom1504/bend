# Next 30 minutes on direct x86

**Decision to make:** Would eliminating a single-use intermediate sequence pay for a reusable compiler rule? Phase205’s selected x86 compiler takes 15.667 s for the fixed batch against 10.125 s for mature Bend C. Saving another 0.479 s would cross 1.5× C. Full parity requires 5.542 s. The 0.5 s experiment threshold is a spending decision, not a predicted gain. [Matched baseline](../../implementation/phase205/broad06.json)

| Budget | Experiment |
|---|---|
| 5 min | Trace the two actual boundaries. In the lexer, `line` passes the **String** from `gen` to `lex`, which folds its characters into mode and checksum. In RLE, `expand` passes the list from `lrepeat` to `lconcat`. Check the selected image’s machine code for work already eliminated. |
| 15 min | Reuse the Phase200 lexer fixture and the Phase125 repeat-into-tail edit. Build original and experimental copies with the same Phase205 image and runtime. Isolate just the removal of the temporary sequence. The historical lexer also eliminated character classification and token-state work; retain those operations in a fusion-only arm. Check complete outputs on ordinary, empty and alternate inputs. Alternate timing order on the original three lexer points and the RLE point. |
| 10 min | Apply the original catalog repetition weights to within-session median time differences. Record seconds saved per family, dispersion and whether the same ownership and evaluation-order argument covers both. Invest in a compiler rule if both families benefit and together approach 0.5 s. If the lexer needs a separate token-classification shortcut to win, record that distinction and move to ray tracing. Run the full suite once a compiler implementation earns it. |

The earlier staged lexer already reached 0.198× mature C on one input; the earlier RLE source edit saved 18% on a QBE-era baseline. The unanswered question is how much **transfers to one rule on today’s x86 backend**. Keep the reference compiler, Base, runtime and C executables frozen for this experiment. ## Upstream decision, 2026-11-21

The maintained pin is `9a4223d` (2.0.40). Upstream main at `0e2f38f` is 42 commits ahead. Schedule a separate compatibility update after this experiment. The strongest correctness reason is how the native runtime accounts for arrays and buffers nested inside shared records. Use upstream’s nested-array fork regression to check our existing runtime before relying on that behavior. For performance, upstream now carries a cursor through Map lookups and updates existing keys in one trie walk. Our map-churn fixture actually calls `Map.set`. A matched old/new Base test on those inputs would measure the benefit directly. The TypeScript parser also remembers failed typed-let parses; our self-hosted parser would need its own implementation to get that improvement.
