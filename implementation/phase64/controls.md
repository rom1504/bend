## Review boundaries

Retained Base facts must belong to the exact immutable producer world. An
independent shape-valid payload or matching definition name does not establish
that ownership. Public raw APIs must retain their existing validation and
fallback behavior. Prefix/suffix name and constructor capture, fresh-ID floors,
full hash collisions and first-error selection remain differential obligations.

Backend facts must retain the exact context and telescope interpretation from
their original demand. Raw formal queries normalize each type and continue with
its uninstantiated codomain. Public host queries instead substitute `Absent`
through each binder. These are distinct analyses even when most examples give
the same arity. An IO-shadow context is another distinct normalization context.

Call analysis already computes arity and live arity for each eligible ordinary
definition. Retaining those results can preserve demand if native/foreign rows,
missing bodies, definition limits and invalid-body handling keep their original
branches. A new unconditional analysis prepass would require a separate proof.

## Host telescope review

The current wrapper first obtains arity/live count and scans the signature for
Nat conversion. It then computes the result telescope, result conversion,
input conversions, and finally argument write-back conversions. Retaining
normalized telescope heads at the existing result demand can avoid repeated
normalization without moving conversion work to an earlier demand point.

The exact stopping rules matter:

- `jd_host_result` performs terminal WNF even when the requested arity is zero.
- Argument and write-back walks stop at zero without that terminal WNF.
- A premature non-`All` head makes the argument walk emit its original formal
  telescope refusal fragment, while the write-back walk emits an empty string.
- The result walk does not stop at a non-`All` head; it continues its original
  `j_app_type(..., Absent)` calls until the requested count is exhausted.
- Foreign result checks use `j_io_shadow(book)` and cannot reuse a telescope
  normalized in the ordinary export context.

Plans should store raw normalized heads/result first, then perform conversions
in the existing result/input/write-back order. Erased arguments remain skipped.
Reusing a count alone does not establish that types, refusal fragments or
conversion ordering are preserved.

## Discarded child-type reconstruction review

The isolated nine-site patch replaces parent type computations only when the
unchanged direct child is an `Ann`. The existing consumer immediately discards
the incoming type in favor of that same child's annotation. No new type or
context equality assumption is needed. The patch retains parent `All` and
quantity checks, binder environments, constructor field counts, matcher
selection, layout-open checks and default-arm traversal.

Call-scan fuel is still charged at the same `Ann` and body nodes. Invalid scans
and the 64-field limit retain their refusal branches. Native numeric row paths
that strip annotations retain their original telescope computations. The Word
binder's zero-field path delegates to ordinary body lowering, whose `Ann` rule
also overrides the supplied type. Raw unannotated children keep the original
computation exactly. No source-level blocker was found.

There is a strictness boundary: substitution can perform beta reduction and is
not formally total on arbitrary ill-typed raw graphs. Removing a discarded
computation need not preserve divergence on those graphs. On the ordinary
annotated source path, lambda annotation already performs the same substitution
before producing its child annotation; match annotation likewise resolves and
specializes the constructor. No explicit diagnostic or refusal budget is
removed. Do not claim a general equivalence theorem for fabricated raw inputs.

Controls should compare the enclosing `JDText`, `JDCallScan`, layout worklist
and complete modules with all four helpers disabled. Comparing the helper's
returned type with the old discarded type is the wrong oracle: those types may
legally differ because the unchanged consumer overwrites that parameter.
